01 — Principles

Four ideas behind every page

When a decision is not covered below, fall back to these.

Map in, data out

Every visual tells one story: a place on a map becomes a clean row. Pins, contours and the graticule are the motifs; rows, columns and JSON are the payoff.

Calm base, expressive moments

Surfaces stay quiet — white or ink, hairline borders, one blue for action. Gradients, glows and serif accents are reserved for headlines, hero visuals and big numbers.

Honest by default

No invented metrics, logos or reviews. Prices and quotas come from the pricing source; sample data uses fictional businesses and 555-01xx phone numbers.

Motion explains

Animation demonstrates the product — search, scan, extract, export. Loops pause off-screen, and every effect has a reduced-motion end state.

02 — Color

One palette, two themes

Primitives come from the map itself — water blue, cyan shallows, park green, pin coral. Components only consume semantic tokens, and every semantic token carries its light and dark value in one light-dark().

Brand primitives

Used inside tokens.css and illustrations only. --blue-500 is shared with the extension and the admin app.

Semantic tokens

Left half renders in the light scheme, right half in the dark scheme — values are read live from the CSS.

Gradients & glows

Marketing layer only. Never on body copy, never on the dashboard or extension UI.

--grad-brand

--grad-brand-text

Reserved for pin moments. Use sparingly.

How theming works

System preference by default, a manual override on <html>, and theme islands for sections that must stay dark or light.

tokens.css 
:root {
  color-scheme: light dark;
  --surface: light-dark(#ffffff, #0e1424); /* one token, both themes */
}

/* manual override — theme-boot.js restores it before first paint */
:root[data-theme='dark'] { color-scheme: dark; }

/* island: every token flips inside, no second set of variables */
.scheme-dark { color-scheme: dark; }

06 — Components

Building blocks, live

Each demo below is the real component. Open “Markup” under a demo for the exact HTML it was rendered from.

Buttons

One primary per view. .btn-invert lives on dark islands; icon-only actions use .icon-btn with an aria-label.

Chips, badges & status

Chips are interactive or descriptive; badges are short mono labels. Status color always pairs with text.

Cards & icon tiles

Cards are flat surfaces with a hairline. Add data-spotlight for the pointer glow and .card--lift for links.

Forms

Labels sit above inputs; hints are muted; errors say what to do next. The search bar is the one expressive input.

Segmented tabs

Sliding thumb, arrow-key navigation, tabchange event.

Accordion

Native details, animated height, plus icon rotates.

Data table

For extracted rows and specs. Numbers use tabular figures; loading rows use skeletons.

Code window

Always dark, in both themes. Write plain text inside pre[data-highlight]; the runtime adds token colors.

Product mocks

Illustrations are built from components, not screenshots: browser frame, MapsGrab panel, pins and data chips, plus the shared parts below — toolbar download ring and popover, panel states, the typing caret and the stylized map primitives. Use a media slot until real footage exists.

Stats

Only real product facts. Numbers count up once when they enter the viewport.

Pricing card

Content comes verbatim from the pricing source. .is-featured adds the rotating gradient border — only on the plan the source marks as featured.

Feedback

Toasts confirm (green check) or inform (blue, MG.toast(title, desc, 'info')); the dialog asks; spinners and progress wait. The sign-in dialog is the real email + code flow.

09 — Rules

Do this, not that

The short list reviewers check first.

Do

From a map to a spreadsheet

One serif accent per heading — the human word.

Don’t

From a map to a spreadsheet

Two accents, or accents in body copy.

Do
Export

Primary blue is the only action color.

Don’t
Export

Pin coral, AI violet or gradients as button fills.

Do

Real facts from the pricing and copy sources; fictional businesses and 555-01xx numbers in samples.

Don’t

Invented user counts, customer logos, star ratings or named testimonials.

Do

Loops inside data-inview that move only transform and opacity; repaint-heavy effects play a few cycles, then rest. Above the fold, use data-enter and data-split="static".

Don’t

Loops that run off-screen or repaint forever, or first-screen copy that stays hidden until JavaScript runs.

Do

Semantic tokens: var(--surface), var(--r-lg), var(--shadow-md).

Don’t

Hex values, ad-hoc radii or one-off shadows inside components.

Do

Every user-facing string through i18n when implemented in Astro.

Don’t

Hard-coded copy in components — the prototype is English-only by design.
