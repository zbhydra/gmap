# 项目初次发布需要完善内容

项目首次生产发布的引导与准备清单。`host` 表示注册的根域名；首发功能范围以 [ROADMAP](ROADMAP.md) 的「当前首发范围」为准。各项完成生产配置并验证后再勾选。

## 1. 域名、DNS 与 Cloudflare

- [ ] 注册域名，确认所有权、管理账号和续费方式。
- [ ] 在 Cloudflare 添加域名；使用 Cloudflare DNS 时，在注册商完成 Nameserver 委派并确认生效。
- [ ] 按默认命名添加 DNS，记录指向对应服务器或入口，按实际目标选择 A / AAAA / CNAME。

| 服务     | 默认域名                       |
| -------- | ------------------------------ |
| backend  | `api.host`                     |
| website  | `host`                         |
| admin    | `admin9527.host`               |
| 其他节点 | `{节点name}-node{number}.host` |

- [ ] 确认是否接收 `www.host`，并统一跳转到选定的官网地址。
- [ ] 配置公网 HTTPS、证书续期与外层代理 / Nginx；Cloudflare 的回源协议须与实际 TLS 终止层匹配。后端部署边界见 [部署说明](../backend/deploy/README.md)。
- [ ] 为设备信任请求配置绕过缓存，使请求穿透到后端；使用 [设备信任缓存规则](../website/cloudflare/cache-rules.md)，替换为正式域名，核对规则优先级并清理旧缓存。
- [ ] 验证设备信任资源确实经过 Nginx 反代到后端，响应禁止缓存，重复请求仍到达后端。
- [ ] 核对 API、MCP、OAuth 和支付回调的 Cloudflare 规则，确保对应客户端可访问，带身份或授权信息的响应不被缓存。

## 2. 登录与邮件

### Google 登录

- [ ] 在 Google Cloud Console 创建项目，配置 OAuth 同意屏幕、应用名称、支持邮箱、授权域名、隐私政策和服务条款地址。
- [ ] 创建 Web 应用 OAuth Client ID 和 Client Secret，配置正式网站的 Authorized JavaScript origins，以及后端 Google OAuth callback 的 Authorized redirect URI。路径以 [Google 登录合同](feat/007.用户系统/tech-第三方登录.md) 为准。
- [ ] 完成面向正式用户的 OAuth 发布设置及控制台要求的域名 / 品牌验证。
- [ ] 在后端生产部署环境填写 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`；在网站生产构建环境填写同一个 `PUBLIC_GOOGLE_CLIENT_ID`。Secret 仅保留在后端。
- [ ] **需代码调整**：将 [Google 回跳白名单](../backend/src/app/services/google_redirect_login_service.py) 的 `GOOGLE_REDIRECT_ALLOWED_HOST_SUFFIXES` 收口为实际生产域名边界；该处仍有占位值，需确认调整方案并验证正式域名回跳。
- [ ] 使用正式域名完成一次 Google 登录及回跳；如发布插件，覆盖官网确认页到插件的登录流程，并核对确认页窄屏显示。

### Resend 与邮箱登录

- [ ] 在 Resend 添加发信域名，按控制台要求配置 DKIM / SPF 等 DNS 记录并通过验证；确认域名的 DMARC 配置。
- [ ] 创建发信凭据，确定验证码发件地址与品牌名称，通过 Resend SMTP 接入后端。
- [ ] 将 SMTP 账号写入后端部署环境的 `SMTP_CONFIG`，确认部署生成的 `backend/config.yaml` 生效。字段与发送合同见 [邮件发送](feat/000.架构/tech-邮件发送.md)。
- [ ] 为客服邮箱配置实际收件服务或邮件转发；使用转发时验证目标邮箱，核对收信 MX 与发信域名配置兼容。
- [ ] 实测验证码收信和邮箱登录，检查发件人、品牌、邮件链接及垃圾邮件情况；从另一个邮箱实测客服收信。

## 3. GSC 与 GA4

### Google Search Console

- [ ] 在 GSC 添加正式域名的 Domain 资源，按要求添加 DNS TXT 记录并完成所有权验证。
- [ ] 提交正式站点的 Sitemap，检查抓取、索引与 URL 检查结果。
- [ ] 核对正式站点的 canonical、Sitemap、robots.txt 与 llms.txt 使用同一个官网域名，检查测试站和用户工作区的 noindex。配置入口见 [网站说明](../website/README.md)。

### Google Analytics 4

- [ ] 创建 GA4 媒体资源和 Web 数据流，确认统计时区、币种与正式网站地址。
- [ ] 获取数据流的 Measurement ID（`G-` 开头），写入网站生产构建环境的 `PUBLIC_GA4_MEASUREMENT_ID`，重新构建发布。
- [ ] 在 GA4 实时报告 / DebugView 验证页面访问与现有事件，确认测试流量和内部操作不会混入正式分析。

GSC 的域名所有权验证与 GA4 数据流分别配置；本项目通过官方控制台查看数据，入口说明见 [网站待回填项](../website/README.md#待回填占位清单)。

## 4. 阿里云 SLS 打点

- [ ] 创建生产 Project 和 Logstore，选择地域、日志保留期并开启 WebTracking。
- [ ] 依据实际发送字段创建字段索引；Dashboard 使用的字段须支持对应统计查询。字段以 [SLS 合同](feat/000.架构/tech-可观测与SLS.md) 及各端 `buildSlsMarkFields` 为准。
- [ ] 在网站生产构建环境显式配置 `PUBLIC_ALI_SLS_*` 并启用；发布 Maps / Bing 插件时分别核对 `EXTENSION_ALI_SLS_*` 的目标项目与来源标识，避免沿用旧项目默认值。
- [ ] 重新构建相关产物，从真实浏览器验证 WebTracking 写入、跨域响应及各端日志可查询。
- [ ] 根据实际 `mark_type` 创建统计 Dashboard，覆盖访问、采集 / 导出行为和已接入的前端异常，确认筛选条件与查询时间范围正确。

## 5. 部署、配置与初始化

- [ ] 准备生产服务器、SSH、部署目录、进程管理及 Nginx，按 [后端部署说明](../backend/deploy/README.md) 初始化服务。
- [ ] 创建正式 MySQL 数据库与账号，准备独立于测试环境的 Redis 实例；完成结构同步、必要配置数据初始化和管理员账号配置。
- [ ] **需完善生产配置**：为 `auth.jwt_secret_key` 设置独立生产密钥，并打通可重复部署的注入方式；[后端模板](../backend/config.yaml.example) 仍含固定示例值，部署会重新生成配置，须验证再次部署后密钥保持正确。
- [ ] 回填后端 `PUBLIC_API_BASE_URL` / `PUBLIC_WEBSITE_BASE_URL`、网站 `PUBLIC_SITE_URL` / `PUBLIC_API_BASE_URL` / `PUBLIC_SHARED_COOKIE_DOMAIN`，以及 Admin 的 `ADMIN_API_BASE_URL` 与部署域名。模板分别见 [后端](../backend/deploy/.env.example)、[网站](../website/.env.production.example)、[Admin](../admin/deploy/.env.example)。
- [ ] 核对后端生成的 MCP 公开地址及 Host / Origin 清单，验证正式地址的协议发现和 OAuth 回跳，部署边界见 [API 与 MCP 合同](feat/014.Maps云端/tech-API与MCP.md)。
- [ ] 配置自己的飞书告警入口或明确关闭示例告警，确认运行日志可查询。
- [ ] 配置数据库备份，确认备份可恢复；记录部署备份与回滚入口。生产凭据通过实际部署配置管理，不写入本清单或提交到仓库。

## 6. 商品与支付

- [ ] 按实际发售范围运行 [商品初始化脚本](../backend/scripts/seed_subscription_products.py) 的 `seed`，核对三条产品线的免费额度、付费商品、价格与官网展示一致。
- [ ] 配置 PayPal 正式商户应用和渠道凭据，写入后端支付渠道配置；核对支付回跳与公网 webhook。配置合同见 [支付与履约](feat/004.订单系统/tech-支付与履约.md)。
- [ ] 完成真实渠道付款验证，核对订单状态、套餐权益与额度；确认 webhook 与用户回跳均可完成履约，重复通知不会重复发放权益。退款政策与实际处理方式一并确认。

## 7. Collector、代理与结果存储

发布 Online / API / MCP 时执行本节，对应发布门槛见 [Maps 云端合同](feat/014.Maps云端/feat.md)。

- [ ] 部署 Collector 实例及所需浏览器运行资源，配置鉴权 Key、实例目录与进程管理；在 Admin 保存节点和代理，验证连接。唯一配置入口见 [单一采集配置](feat/014.Maps云端/tech-Export与Collector重构.md#5-单一采集配置)。
- [ ] 真实调用 Collector → Google，验证首发涉及的搜索、评论与联系方式补全；节点健康检查之外还需取得实际业务结果。
- [ ] 发布 Online 时创建 R2 / AliOSS Bucket，在 Admin 配置并启用对象存储，设置结果生命周期；验证 CSV 发布、本人下载及过期清理。配置合同见 [对象存储](feat/008.管理后台/tech-系统设置.md#对象存储配置)。
- [ ] 按 [Export 实施记录](feat/014.Maps云端/plans/010.Export服务端实施.md) 完成仍待执行的 Collector 重启 / TTL 验证。
- [ ] 完成 ROADMAP B5 要求的长期封锁率和代理流量验证，再决定云端正式开放范围。

- [ ] 记录本次发布的产物、配置来源、验收结果与回滚入口；失败项、未执行项和已接受限制分别登记后，再确认正式开放范围。
