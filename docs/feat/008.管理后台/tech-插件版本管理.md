# 插件版本管理

> Google Maps 与 Bing 插件发布记录、新版提醒和指定版本禁用的共享合同。实施与验收记录见 [实施计划](plans/006.插件版本管理.md)。

## 管理流程

Admin 提供独立的“插件版本”菜单。管理员先上传可下载的安装包，再新增对应插件的版本记录。启用记录中，数字版本号最高的一条是该插件的推荐版本；新增更高版本并保存后，插件即可检查到更新。

- 列表按插件筛选、分页，展示插件、版本号、启用状态、推荐版本标记、更新地址和添加时间；默认按添加顺序倒序。
- 新增表单包含插件、版本号、更新地址和启用状态，默认启用；保存即生效。
- 已保存记录的插件和版本号不可修改；管理员可修改更新地址、禁用或重新启用该版本。
- 禁用前确认影响范围。禁用只阻止该版本开始新采集，已有采集及其导出仍可完成。即使没有更高的启用版本，管理员也可禁用；此时用户会看到暂无可升级版本。
- 记录保留供查询，不提供删除操作。两个插件分别计算推荐版本，订阅共享不影响版本归属。

插件内的“下载更新”进入该推荐版本配置的更新地址；地址可指向官网分浏览器安装教程。更新继续遵循 [官网分发合同](../013.Maps插件/feat.md#官网分发)，添加版本记录不会上传或替换安装包。

## 数据规格

业务表 `plugin_versions` 由 Admin 写入，客户端检查接口读取。

| 字段 | 类型 | 合同 |
| --- | --- | --- |
| `id` | BigInteger | 自增主键 |
| `plugin` | String(8) | `maps` 或 `bing`，分别对应两个独立安装包 |
| `version` | String(32) | 三段数字版本号，保存前去首尾空白，各段不含多余前导零 |
| `is_enabled` | Boolean | 默认启用；关闭表示明确禁用这个插件的这个版本 |
| `update_url` | String(1000) | 必填 HTTP / HTTPS 更新地址 |
| `created_at` | BigInteger | 创建时间，毫秒时间戳 |
| `updated_at` | BigInteger | 最后修改时间，毫秒时间戳 |

`plugin + version` 必须唯一。除主键和该唯一约束外，不新增索引；推荐版本按数值段比较，不能按字符串或添加时间选取。不增加可编辑的“当前版本”字段，避免它与启用记录产生两套事实。

版本格式在 API schema 边界统一校验，后续比较直接使用校验后的三段整数。插件标识独立于订阅的产品类别，不扩展共享订阅枚举。

## 接口

所有响应沿用 `{code, data, msg}` 信封。

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| GET | `/api/admin/plugin-versions` | 管理员鉴权；按 `plugin` 可选筛选，使用既有 `page / page_size` 分页合同 |
| POST | `/api/admin/plugin-versions` | 管理员鉴权；新增版本，接收插件、版本、启用状态和更新地址 |
| POST | `/api/admin/plugin-versions/{id}` | 管理员鉴权；修改更新地址或启用状态 |
| GET | `/api/client/plugin-versions/check` | 无需登录；必传 `plugin` 和本地 `version`，检查更新及禁用状态 |

Admin 列表返回 `rows / total / page / page_size`；各行附只读的 `is_recommended` 推荐标记。`page` 默认 1，`page_size` 默认 50、范围 1–100。新增时 `is_enabled` 默认 true；修改只接收 `update_url` 和 `is_enabled`，未提供或为 null 的字段不修改。新增和修改接口返回保存后的记录及推荐标记。

写入事务由 service 持有，管理员鉴权复用 `get_admin_user`。格式错误使用 `VALIDATION_ERROR`，重复版本使用 `INVALID_REQUEST`，修改不存在的记录使用 `NOT_FOUND`；响应文案走既有公共 i18n。

客户端成功响应的 `data`：

| 字段 | 合同 |
| --- | --- |
| `status` | `current`、`update_available` 或 `disabled` |
| `update` | 存在更高的启用版本时返回 `{version, url}`，否则为 `null` |

检查规则：

| 本地版本的记录 | 是否存在更高的启用版本 | 状态 | 用户行为 |
| --- | --- | --- | --- |
| 未登记或启用 | 否 | `current` | 正常使用 |
| 未登记或启用 | 是 | `update_available` | 显示新版号与“下载更新”；可继续采集 |
| 已禁用 | 是 | `disabled` | 拒绝开始新采集，显示“下载更新” |
| 已禁用 | 否 | `disabled` | 拒绝开始新采集，提示暂无可升级版本、联系支持 |

仅明确登记并禁用的版本受到拦截；不把“未登记”当作禁用。推荐版本低于本地版本时不提示降级。禁用最新版本后，推荐标记可回到较低的启用版本，但它不能成为该被禁用版本的升级目标。

检查接口直接读取数据库，不使用进程配置缓存、浏览器持久缓存或 HTTP 缓存，响应设置 `Cache-Control: no-store`。Admin 保存成功后的后续检查读取新状态，不等待现有远程配置的一小时缓存到期。

## 插件接入

两个插件各自的 background 负责 HTTP 调用，从本包 manifest 读取本地版本并使用固定插件标识；Popup、content 和 Dashboard 经现有 RPC 读取结果。类型边界遵循 [插件规范](../../references/specs/spec-extension.md)，内部代码使用已收窄的返回类型。

- 打开 Popup、地图面板和 Maps 批量 Dashboard 时检查一次，展示新版或禁用提示；当前页面不承诺后台实时推送。
- 开始每次新采集前重新检查，不因页面已打开而复用旧的“可用”结果。该检查独立于采集配置和用量查询，不改变后两者的现有行为。
- 普通更新提示显示新版号和“下载更新”，不阻止工作。禁用提示阻止新采集，已有结果的导出、结束当前采集、登录及打开更新地址仍可操作。
- 已启动的单次采集可以完成，包括同一会话的暂停与继续；批量队列以单条采集为边界，当前条目完成并导出后，下一条开始前重新检查。
- 评论和照片工作页的 Reset 会重新开始采集，属于新采集；版本检查必须先于清空已有结果，被拦截时保留可导出的原结果。
- 检查失败时，打开页面仅显示可重试的检查失败提示；开始新采集时拒绝本次启动并允许重试。正在执行的采集和已有结果导出不依赖这次检查。
- 批量启动或下一条目检查到禁用、检查失败时，沿用已有暂停状态并保留队列；不得将未运行条目记为失败、跳过或完成，也不得由 alarm 持续重启同一被拦截条目。重新启用后由用户手动续跑。
- 插件提示及按钮使用现有 i18n；版本号和更新地址作为数据，不由 Admin 填写 HTML 或提示文案。

Maps 必须覆盖普通搜索、列表模式、评论与照片工作页的自动启动、批量首次启动、批量续跑及后续条目；仅在 Popup 或主面板拦截不能满足禁用合同。Bing 在采集器真正开始采集前统一检查。

Maps 的版本提示统一来自此检查接口；公告和订阅地址继续由采集远程配置管理。Bing 的版本检查独立于其采集配置通道。

## 生效边界

- 禁用是已接入检查逻辑的官方插件的产品门控，不是修改过安装包后的防篡改授权边界。
- 没有预置该检查逻辑的旧安装包不会因为增加数据库记录而自动获得禁用能力。运营启用本机制前，需先发布并分发含检查能力的安装包；需要管理的版本由 Admin 显式登记。
- 更新仍由用户完成下载、替换原目录及重新加载；插件不在正在采集时强制刷新或卸载。
- 检查服务不可用会暂时阻止新采集，这是保证禁用状态不被“查询失败即放行”绕过的可用性取舍。

## 验收

1. 管理员能为两个插件分别新增版本；重复的插件与版本组合被拒绝，两个插件相同版本号可同时存在。
2. 先添加较高版本、再补录较低版本，推荐版本仍按数值选取；例如数值段中的 `10` 大于 `9`。
3. 新版提醒、指定版本禁用、禁用但无可升级目标、重新启用分别符合检查决策表；禁用一个插件的某版本不影响另一个插件。
4. Admin 保存后，不刷新已经打开的地图页也能在下一次开始采集时得到新状态；不存在旧远程配置缓存造成的一小时延迟。
5. Maps 各个直接启动入口及批量后续条目、Bing 开始入口均执行门控；已运行采集和导出可完成，批量被拦截后保留待执行条目且不会重复启动。
6. 未登录用户也能收到提醒或禁用提示；普通客户端不能调用管理写入接口；Admin 中英文及插件现有语言均能完整展示相关提示。
