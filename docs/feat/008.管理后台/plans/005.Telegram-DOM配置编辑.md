# 005 · Telegram DOM 配置编辑

## 1. 目标

在系统设置页增加「Telegram DOM」标签，让管理员读取和保存后端的全局稀疏 JSON 对象。页面默认显示 `{}`，不展示插件默认值，不建立字段表单或版本模型。

## 2. 依赖

- 只依赖 `@../../002.下载功能/plans/023.Telegram-DOM远端覆盖配置.md` §4.1 完成公共 GET 与 Admin GET/POST；不依赖该 plan 的扩展阶段。
- UI 与数据合同以 `@../tech-系统设置.md` 的「Telegram DOM 覆盖」为准。

## 3. 本轮范围

### 3.1 包含

- 系统设置第四个 tab。
- Telegram DOM 对象读取、文本编辑、显式保存、loading、成功和失败反馈。
- 浏览器端 JSON 解析与顶层对象判断。
- 中英文文案、Admin E2E 和生产构建。

### 3.2 不包含

- 不展示或拉取任一扩展版本的默认值。
- 不提供字段级表单、补全、selector 校验、格式化、自动保存、版本选择、历史、回滚或“恢复默认”。
- 不实现配置预览、Telegram 页面联动测试或未来 AI 写入入口。
- 不改后端数据合同；后端工作属于 plan 023。

## 4. 改动范围

- `admin/src/api/system-settings.ts`
  - 增加 Telegram DOM JSON value/object 类型，以及 GET/POST 方法；响应对象不增加 `config` 包装。
- `admin/src/views/SystemSettingsView.vue`
  - 增加第四个 tab、全宽多行文本框、保存按钮、读取重试和错误反馈。
  - 第一次进入 tab 时读取一次；保存失败保留原始文本。
- `admin/src/i18n/zh-CN.json`
- `admin/src/i18n/en-US.json`
  - 增加 tab、保存、成功、读取失败、重试、JSON 错误、顶层对象错误和刷新生效提示。
- `admin/e2e/system-settings.spec.ts`
  - 在现有系统设置流程中增加 Telegram DOM tab 覆盖，不新增重复 spec。

## 5. UI 与交互验收

- 系统设置顶部稳定显示四个 tab；已有配置缓存、API Key 和 Google 数据 tab 行为不变。
- Telegram DOM 文本框全宽、等宽字体、最小高度 360px；服务端返回 `{}` 时文本显示 `{}`。
- 页面不把客户端默认对象、字段清单或示例自动写入编辑器。
- 点击保存后按钮 loading 且不能重复提交；成功后保留输入并提示刷新 Telegram 页面生效。
- 非法 JSON 或数组/字符串/数字/布尔值/`null` 顶层值只显示本地错误，不调用保存接口。
- 单键对象、缺少已知键、未知键、嵌套 JSON value 和非 selector 字符串均允许提交；页面不裁剪或重排。
- 读取失败只影响 Telegram DOM tab，显示重试入口；保存失败保留未保存文本并允许再次点击。
- 页面没有格式化、自动保存、版本选择、历史、回滚和“恢复默认”控件；清空覆盖只能由管理员手工保存 `{}`。
- 所有新增文案支持中英文，窄屏下文本框和操作按钮不溢出。

## 6. E2E 场景

- 打开 Telegram DOM tab，读取并显示服务端对象；输入包含缺少项、多余项和任意 JSON value 的对象后可原样保存。
- 输入非法 JSON 或非对象顶层值时不提交，并保留当前文本。
- 一次读取失败后显示错误，管理员点击重试可恢复编辑器。

## 7. 验证命令

```bash
cd admin
pnpm test:e2e -- system-settings.spec.ts
pnpm build
```

## 8. 已知边界

- 管理员输入语义错误但合法的对象时页面仍会保存，这是宽松合同的预期；管理员修正后重新保存。

## 9. 实施状态

- 2026-08-19：本 plan 已完成。
- 页面只在首次进入 Telegram DOM tab 时自动读取；失败后切换 tab 不会再次请求，管理员可显式点击重新读取。
- Admin 生产构建通过；系统设置 E2E 在 Chromium 和 Firefox 共 22 条通过。
- E2E 只新增一条合并主流程，覆盖 `{}`、多余/缺少键和任意 JSON value 原样提交、保存后文本不重排，以及非法 JSON 不提交。
