# 统一每日额度服务

> 状态：已被 @docs/feat/feat.051.Credits下载积分.md 替代。
> 本文件为历史背景，不再作为额度实现依据。
> website 下载必须使用 Credits；订阅/状态接口里的旧 website 下载额度字段返回 0；extension 下载检查和展示继续使用每日次数规则，并共用 `EXTENSION_DOWNLOAD_DAILY_LIMIT = 9999`；播放功能已屏蔽。

## 1. 功能目标

> 历史说明：以下目标不再作为当前实现依据。

- 提供一个统一的每日额度管理能力，管理所有“按用户或设备作用域统计、每天自然重置”的额度需求。
- 确保跨天后只展示和使用当天额度数据。
- 让不同业务额度彼此独立，避免网页下载、网页播放、插件下载互相影响。
- 让额度数据可以直接判断所属日期，方便线上排查。

## 2. 当前管理的额度

### 2.1 网页下载额度（历史，已退场）

- 使用场景：用户在 website 发起下载。
- 当前状态：已被 Credits 替代，不再作为实现依据。
- 展示位置：订阅状态里的下载已用次数和剩余次数。
- 业务口径：不同下载链路只要属于 website 下载，都消耗网页下载额度。
- 权限口径：只管理额度，登录要求由下载入口判定。

### 2.2 网页播放额度（历史，已退场）

- 当前状态：播放功能已屏蔽，不再作为实现依据。
- 使用场景：用户在 website 创建播放会话。
- 展示位置：订阅状态里的播放已用次数和剩余次数。
- 业务口径：创建新播放会话消耗额度；续签、Range 播放流不重复消耗。
- 权限口径：只管理额度，播放权限由播放入口判定。

### 2.3 插件下载额度（保留，固定上限）

- 使用场景：浏览器插件端发起下载。
- 当前状态：`/api/client/quota/check` 继续使用每日次数规则，扣除和展示共用 `EXTENSION_DOWNLOAD_DAILY_LIMIT = 9999`。
- 业务口径：插件下载和网页下载分开统计，互不占用。
- 权限口径：只管理额度，插件下载权限由插件入口判定。

## 3. 不属于本功能的额度

- 邮箱验证码频率限制。
- 登录限流。
- IP 限流。
- 下载和播放链路内部的短锁、重复请求记录、授权记录的具体实现。
- 任何不是“每日自然日额度”的限制。
- 登录态、下载权限和播放权限。

## 4. 功能范围

### 4.1 包含

- 统一管理网页下载、网页播放、插件下载三类每日额度。
- 每类额度按用户或设备作用域独立统计。
- 用户作用域和设备作用域不做自动合并；调用业务自行选择用户 ID 或设备 ID。
- 每天按服务器本地自然日重置。
- 订阅状态只展示当天额度数据。
- 订阅状态新增结构化额度字段，分别展示网页下载、网页播放、插件下载。
- 原有订阅状态标量字段继续返回；website 新代码读取结构化额度字段，插件端本阶段不调整。

### 4.2 不包含

- 不调整订阅套餐的额度数值。
- 不新增用户可见页面。
- 不新增后台配置入口。
- 不做金融级强一致额度系统。

## 5. 业务流程

### 5.1 查询订阅状态

1. 用户打开 website 或插件端。
2. 后端识别当前用户或设备作用域。
3. 后端读取当天对应额度。
4. 如果当天没有额度记录，按已用 0 次返回。
5. 后端返回 `web_download`、`web_play`、`extension_download` 三个额度对象。
6. website 展示 `web_download` 和 `web_play`；插件端继续使用原有订阅状态字段。

### 5.2 消耗下载额度（历史，已退场）

website 下载扣费以 @docs/feat/feat.051.Credits下载积分.md 为准；extension 下载检查接口仍使用每日次数规则，并共用 `EXTENSION_DOWNLOAD_DAILY_LIMIT = 9999`。

1. 用户发起下载。
2. 后端识别这是网页下载还是插件下载。
3. 后端读取该用户或设备当天对应下载额度。
4. 如果额度不足，返回额度不足错误。
5. 如果额度充足，增加当天已用次数。
6. 下载链路执行。

### 5.3 消耗播放额度（历史，已退场）

播放功能已屏蔽，不再创建播放会话。

1. 用户创建新的播放会话。
2. 后端读取该用户当天网页播放额度。
3. 如果额度不足，返回额度不足错误。
4. 如果额度充足，创建播放会话并增加当天已用次数。
5. 同一用户同一资源 60 秒内重复播放不重复扣额度。

## 6. 边界和异常

| 场景 | 业务行为 |
| --- | --- |
| 今天没有额度记录 | 按已用 0 次处理。 |
| 昨天仍有额度记录 | 不影响今天。 |
| 用户是无限额度套餐 | 不增加每日额度计数。 |
| 额度读取失败 | 状态查询允许按已用 0 次展示，但必须能排查原因。 |
| 额度写入失败 | 本次消耗可以失败并提示用户重试。 |
| 并发同时消耗 | 同一额度类型同一作用域内必须按额度上限原子判断。 |
| 同一资源短时间重复请求 | 同一用户同一资源 60 秒内不重复扣额度。 |
| 服务器跨天 | 新一天从新的每日额度开始统计。 |
| 订阅状态同时返回结构化字段和标量字段 | 两类字段来自同一次当天额度读取。 |
| 无限额度 | 结构化字段返回 `use=0`、`remaining=-1`、`limit=-1`。 |

## 7. 非功能需求

- 设计必须简单直接，方便线上人工排查。
- 额度记录必须能看出所属自然日。
- 不新增第三方依赖。
- 不新增依赖注入。
- 失败错误必须明确，能定位到额度类型和用户或设备作用域。
- 订阅状态接口新增结构化额度字段，原有标量字段继续返回。

## 8. 数据埋点

不新增用户行为埋点。

后端日志需要覆盖额度读取和写入失败，便于立即定位线上问题。

## 9. 验收标准

> 历史说明：以下验收标准不再作为当前实现依据。当前口径以 @docs/feat/feat.051.Credits下载积分.md 为准。

- 用户跨天后不会看到昨天的已用额度。
- 网页下载、网页播放、插件下载三类额度互不影响。
- 用户首次在当天使用某类额度时，从 0 开始计数。
- 额度不足时返回额度不足语义。
- 无限额度套餐不产生每日用量。
- 旧 website 下载额度字段当前统一返回 0。
- website 当前使用 Credits 余额展示下载额度。
- 插件端本阶段不改读取字段。
