## 1. 目标

- 把已验证的 A/K 资源身份、WebPage、Worker ready、LocalDb、立即取消、队列排重、运行时日志、OPFS、任务指标和统一远端配置迁入 Extension Pro 自己的实现。

- 所有正式下载入口继续汇入当前 document 唯一队列；不建立共享包、第二队列或备用下载路径。
- 实施范围只包含 `extension-pro/`。公共 `/api/client/tg/config` 由主插件 Plan 031 提供，本计划不修改 backend、Admin、主插件或 docs。

## 2. 非目标

- 不迁移主插件 Popup、Sidebar、多平台 scanner、其它站点 canonical ID、主站桥接、视觉或 locale 矩阵。
- 不新增依赖注入、第三方依赖、持久队列、跨标签页状态、恢复、补偿、版本、幂等层、兼容或 fallback。
- 不为删除实验、旧数据、旧版本、理论碰撞、取消消息必达或资源清理绝对成功增加测试。
- 不在本计划实现或验收 Pro 官网支付闭环。

- P0 实验旁路源码、UI、RPC、i18n、fixture 和默认 project 已从工作区清理，`extension-pro` 当前无 Git diff；构建、启动和默认 Playwright 尚未复验。

## 7. 实施规则

- 用户批准本修订计划前不得执行 P1–P6。
- 实施范围绝对限制在 `extension-pro/`；公共远端配置不可用时 P5 阻塞，不扩大修改 backend/Admin。
- 新增防护、测试或分支前先证明 Pro 真实入口可达；已有同层证据足够时不新增。
- 普通失败允许用户重试；不为未复现异常提高可靠性等级。
- 只处理页面崩溃、大量泄露或用户卡死等已证大问题。低概率轻微泄露、清理不完整、并发轻微丢失或旧请求短暂继续默认接受；不得为它们等待 ACK、阻塞 FIFO、增加恢复/补偿或防御测试。
- 发现需要状态机、持久状态、兼容、备用链、恢复、复杂重试、新依赖或共享包时立即暂停询问用户。
- 新方案落地后删除旧实现，不保留 wrapper、feature flag 或 fallback。
