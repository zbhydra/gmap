## 2 · 配置契约(contract 形状)

五组,全部可被服务端稀疏覆盖(Object.assign 浅覆盖,语义同 013 拍板):

- `adapters`:适配器版本数组,每项 `{ name: 'legacy'|'new', priority, detectors[], fallbackDetectors[], selectors: { listContainer[], listItems[], listItemsAlt[], scrollContainer[], searchAreaButton[], loadingIndicator[], openHours[], paginationButton?, infiniteScroll } }`。默认值 = 调研报告 §4.2 表格逐项(legacy: `.b_vList`/`.bm_oneMap` 体系 + `a.bm_rightChevron` 翻页,infiniteScroll=false;new: `.b_lstcards`/`#appShellRoot` 体系 + searchThisAreaButton 多候选,infiniteScroll=true)。
- `parse`:`dataEntityAttr='data-entity'`、评分来源开关(结构化字段 `entity.ratingValue` 优先,`infoboxHtml` 星级图类兜底)、去重键 = `entity.id`。
- `scrape`:检测轮询 1500ms、循环轮距 500ms、翻页后等待 2000ms、连续失败上限 12、列表就绪等待 8000ms/轮询 250ms、免费单次上限 20。
- `export`:文件名前缀 `Bing_Maps_Scraper_`、CSV 分隔符/换行/BOM 开关。
- `panel`:停靠 top 80px/right 40px、宽度 300–500px、示例搜索词 URL。

## 3 · 解析与行结构(18 列)

输出行字段与顺序以 `references/golden-samples/export.csv` 表头为唯一基线:ID、Name、Address、Featured image、Bing Maps URL、Latitude、Longitude、Rating、Rating Info、Category、Open Hours、Website、Phone、Emails、Social Medias、Facebook、Instagram、Twitter。

映射合同(来源 = data-entity JSON,字段清单见调研报告 §4.1):ID=`entity.id`;Name/Address/Website/Phone/Category=`entity.title/address/website/phone/primaryCategoryName`;Featured image=`entity.imageUrl`;经纬度=`routablePoint.latitude/longitude`;Bing Maps URL = `cp={lat}~{lon}&lvl=16.0&q={title, address}` 拼接;Rating/Rating Info 优先 `entity.ratingValue/ratingSourceName`,缺失走 infoboxHtml 星级类兜底;Open Hours 优先 `entity.openHoursText`,缺失走条目 DOM `.opHours`;Emails/Social Medias/Facebook/Instagram/Twitter 一期占位:免费行填 `###PRO###`,Pro 行留空(二期已于 2026-09-02 回填:免费保持占位,Pro 采集完成边沿自动补全,见域 changelog)。CSV 文件名 `{prefix}{N}_{timestamp}`,CSV 加 BOM。

CSV 写出在 [csvText.ts](../../../../extension-bing/src/sites/bing/content/export/csvText.ts) 的 `escapeCsvCell` 应用 [CSV 文本规则](../../013.Maps插件/tech-采集与批量.md#csv-文本规则)，数值与空值沿用既有序列化。XLSX 导出不经过该边界，保留原值。

## 5 · 登录与门控(background)

- **登录(v3 浏览器身份,2026-09-01 起;协议合同见 `../../007.用户系统/tech-第三方登录.md` §9)**:popup 与面板未登录态 `Sign in` 两入口走同一 background RPC——PKCE verifier/challenge(S256)生成 → `chrome.identity.launchWebAuthFlow` 打开官网统一确认页 `/extension-login` → 用户复用 Google/邮箱登录并显式确认账号 → 一次性 code 经回调 URL fragment 回跳 → exchange 换插件独立 token → 快照比对后原子写 storage 三键;写入成功后 `invalidateSubscription()` + `refreshSubscription()` 强制重拉订阅态。原 v2 官网桥(`WebsiteAuthBridge` 整文件、`onMessageExternal`、manifest 固定 key 与 `externally_connectable`、`applyWebsiteToken`)已随迁移整体删除,manifest permissions 为 `['storage', 'identity']`。
- 门控:匿名(device_id)即免费;Pro 判定 = 既有订阅状态接口(007/006 域 client 已有),普通查询内存缓存 5 分钟，登录写入成功后失效重拉。冷启动时 background 恢复与 `authStore.initialize()` 各自共享在途 Promise，并发门控等待认证恢复完成。background 的 `syncBackgroundAuthState` 在 token 对变化及订阅请求前后核对 storage 账号：同账号轮换仅更新 token，退出/换号才失效认证与订阅；RPC 返回同步后的真实认证态。content 在 `gate.ts` 的 `watchGateAuthStorage` 监听 auth 三键，合并同批变化并强刷快照，刷新期间的 USER_INFO 资料回写不再触发刷新。`collector.start()` 首轮前等待 `refreshGateState({ force: true })`，force 经门控 RPC 传到订阅刷新，绕过缓存；已有请求在途时等其结束后另发请求。订阅查询失败时有缓存则回退缓存，无缓存则通过 RPC 抛错，让 content 保留当前快照继续采集；成功查询到免费档才更新为非 Pro。Stop/reset 沿用 generation 失效检查。免费:达 20 条停止 + 尾行提示 + Upgrade 引导;Pro / Business:无单次上限，受共享月额度约束。
- 完成收尾(补全中,013 同源交互):`BingCollectState.finishing` 是完成态的子状态,由 collector 独占——三个完成入口(手动 Stop / 行数上限 / 连续失败)经同一入口把 `phase=completed` 与 `finishing={done:0,total:0}` 放进同一快照广播,再执行月用量幂等上报 → `refreshGateState()` → Pro 时 `enrichRows(onProgress)` → `finally` 置 null。`total=0` 表示门控确认中或无补全目标;`total>0` 时面板显示批次进度(单位:website 去重后的目标数)。非 null 期间面板禁用 Export / Go Back 并守卫点击,`reset()` 拒绝换代,所以收尾不会跨会话写状态。门控失败保留快照、单批失败收敛空列后继续,RPC 超时(门控 30s、单批 35s)保证放行有上界;面板只消费 collector 状态,不新增事件。

- 订阅入口:面板徽标与达限升级按钮调用 `core/utils/navigation.ts` 的 `openPricingPage`，由 `buildPricingUrl` 集中组装网站地址与归因参数；URL 产品线合同见 [Pricing 页面入口](../../011.Pricing页/tech-pricing与自动续费.md)。插件仅消费权益状态，报价、购买、升级及管理交互由网站负责。

### 共享月 records 计量

- 复用 `GET /api/client/maps/usage` 与 `POST /api/client/maps/usage/report`，与 Google Maps 同属 `maps_extension` 账本；登录按账号、匿名按设备归属。Bing 免费单次权益仍取 `scrape.freeRowLimit`，不套用 Google 的 `run_limits`。
- Start 首轮前强刷订阅，再经 content RPC `getBingUsage` 查询最新月余额；上限取单次权益与 `max(0,total-used)` 的较小值。`exhausted` 或余额为零拒绝开始；查询或待结算补报失败均拒绝开始，显示可重试提示，不回退旧余额或无限额。
- 每次开始成功生成 UUID；完成、Stop、达限与连续零增长共用收尾，按去重后的实际 records 上报，零条不发消费请求。免费达限与月额达限分别展示，Pro 因月余额停止不显示免费升级警告。
- background 的 `sites/bing/usage/usageService.ts` 串行维护 `chrome.storage.local` 待上报记录：HTTP 前持久化原 request_id、records、身份与会话创建时间 `createdAt`（毫秒），成功后删除；失败不阻断补全与导出，面板可仅重试用量，不重新采集。下一次 Start / SW 重启后先补报同身份记录，再查余额。换号时保留原身份待办，不扣到新账号；HTTP 首次注入与重试均核对开始前固定的 token 对。
- 两条 usage 请求显式传 `expected_user_id`（账号 ID，匿名为 0），服务端在业务操作前核对解析身份；过期 token 降级匿名或身份失配返回 401，复用现有刷新链。刷新失败保留待办，不把匿名成功当作账号结算；共享接口合同见 [额度基建](../../000.架构/tech-额度基建.md#42-插件-http-身份约束)。
- 匿名待办只在服务端幂等窗口内重放（TTL 真源为 `backend/src/app/constants/usage.py` 的 `dedup_key_ttl_seconds`）；达到窗口边界或旧记录缺少时间时，记录诊断并清理，不再发送。手动 Retry 沿用原创建时间，不重新开启窗口；窗口外未成功记账的用量允许丢失。账号待办依赖 MySQL 唯一键，不受匿名窗口限制。
- 当前接口是查询后消费，无并发预留；多端同时采集可能各自使用同一余额快照。活动采集在页面被强制关闭前尚未进入完成收尾的行不会持久化；持久化恢复范围为已经提交到 background 的待上报记录。

## 6 · E2E 基建(真实界面主验收)

单层真实界面设计(2026-09-02 hydra 拍板,替代原「离线 fixture 主验收 + 真实 smoke 辅助」双层,fixture 页与全部 route mock 已删除):

1. **真实 Bing 界面(唯一主验收)**:Playwright persistent context(`--load-extension=dist-real`,headful)打开真实 `www.bing.com/maps`,零 route mock、零本地 fixture 页,采集真实数据。断言链:面板注入 → 列表检测态 → Start → 匿名免费档 20 条截断(完成态 + 警告条 + Upgrade 引导)/ Pro 无单次上限（受月额度约束） → 手动 Stop → 补全中首帧锁定 Export / Go Back 并显示进度 → 放行 → CSV 导出(18 列表头 + 行数 + 末行提示)。批次失败、门控失败等真实界面造不出的分支由 `tests/integration/bing-finishing.spec.ts` 覆盖。
2. **反自动化身份**:去掉 Playwright 默认 `--enable-automation`、追加 `--disable-blink-features=AutomationControlled`,context 注入身份兜底 init script(website `scripts/playwright-browser-identity.mjs` 同款:webdriver 置否 + Client Hints brands 去 Headless);只消除已知自曝字段,不承诺绕过第三方 bot 检测。
3. **构建变体 dist-real**(`scripts/build-real.mjs`):API base 指向本地真实 backend(`127.0.0.1:7600`),SLS WebTracking 构建期禁用(真实 e2e 不污染生产日志库,打点失败由插件打点层容错);不跑 vue-tsc / zip(类型与产物校验由 `pnpm build` 覆盖)。
4. **登录态(Pro 用例,token 直注)**:登录流程不做 e2e(2026-09-02 hydra 拍板)。globalSetup 探测本地 backend 可达时 spawn `backend/scripts/e2e_seed_user.py --scenario bing-extension-pro`(幂等建号 + maps_extension Pro 订阅 30 天 + 与 `/auth/extension-login/exchange` 同构的 access/refresh token 对注册 Redis 白名单),spec 内经扩展 service worker 直写 chrome.storage auth 三键;auth/me 与 `subscription/status?product_kind=maps_extension` 全走真实验证链。backend 不可达或 seed 失败 → 用例条件 skip,匿名用例不受影响。
5. **环境降级分界**:网络不可达 / 人机验证 / 落地域偏离(302 到 cn.bing.com 等)/ DOM 改版迹象 → `skipSmoke` 条件跳过并记 skip-reason 注解;插件自身行为(门控 / 计数 / 导出)失败照常 fail,不让环境波动掩盖产品缺陷,也不让上游改版打红日常门禁。

harness 要求:headful(扩展要求);每用例独立临时 profile;locale 固定 en-US(演示词结果形态稳定);产物断言读下载文件;构建前置 `pnpm build:real`;单命令 `pnpm test:e2e` 可重复执行。
