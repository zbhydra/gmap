状态：后端与官网实现及本轮测试环境验收已完成；Clink 真实扣款失败演练未执行，不列为本轮交付门禁。生产发布另行安排。设计合同见 [Stripe 支付接入设计](../tech-Stripe支付.md)。

## 接入范围

- 按官网现有美元商品接入，保留商品级单一计费模式；不在本次接入中批量调整现售商品的计费方式。
- 普通订单沿用既有支付与履约流程；公共订单层只接入新增渠道及订阅升级所需数据，历史订单和快照不回填或改写。
- 单次购买接入已有补差升级；自动续费支持订阅购买、协议内升级、续期、更新付款方式与期末取消。
- 两种升档都采用旧权益抵扣新档完整周期价格，付款与换档成功后重开完整账期；业务目标以 [订阅升级合同](../../006.订阅系统/tech-订阅升级.md) 为准。
- 用量保持纽约自然月计量，升档只提高 `total`、保留 `used`：300 条已用、5000 条新上限时显示 300 / 5000，剩余 4700；本次不改用量账本和统计周期。
- 本次只开放 Stripe / Clink 的两种计费与升档能力；PayPal 暂不开新销售，后续仅支持一次性商品，已有订单与协议继续处理。
- 沿用商品级计费模式和商品渠道价格表；自动续费商品在缺少渠道自动续费配置时隐藏该渠道，不降成一次性付款。详细筛选和能力合同见设计，不扩展价格表唯一键。
- Stripe 取消回跳表示退出收银台，本地订单保留待支付；通用取消接口拒绝仅取消本站的 Stripe 订单，付款结果继续由渠道核实。

## 最少验收

1. **真实渠道测试支付**：Stripe / Clink 从本站下单进入各自 Hosted Checkout，分别完成单次与订阅首期；确认支付金额、订单、交易引用及权益正确。success 回跳轮询与同一付款 Webhook 重投不重复履约；回调延迟时保持等待。
2. **真实续费与管理**：通过渠道官方测试时钟推进已创建订阅的一周期，产生一笔真实已付续费订单并正确推进权益；打开本人 Portal，期末取消及生效前恢复都保留本期权益。
3. **真实升级**：单次与自动续费实例分别升到同线更高月付档，收取新档完整周期价减旧权益抵扣的净额，成功后换档并采用新账期；以 30 天旧周期、10 美元旧档、使用 3 天、50 美元新档验证 41 美元。一次性从支付完成时间起算新周期；自动续费核对渠道已付新账期，不以 Webhook 接收时间另加一个月。待付款或失败不提前发放新档，关闭页面后事件仍能同步，重复事件不重复加时，后续续费不恢复旧档；同一流程验证升档保留本月已用量；已申请期末取消时拒绝升档，恢复续费后重新放行；存量 PayPal 按产品合同限制升档且保留历史付款处理。
4. **必要边界验证**：用最少定向用例覆盖签名篡改 / 过期、金额或订单关联不符、未到账通知不履约、重复付款通知幂等；验证取消回跳保留待支付、通用取消接口拒绝直接取消 Stripe 订单，随后真实付款仍可履约。合并可共用真实支付证据的断言，不新增重复用例。
5. **受影响端门禁**：后端执行 black、ruff、mypy、构建与启动检查；网站执行 `pnpm build:test` 并启动，人工核对 Stripe checkout、回跳和 Dashboard 管理入口。复用未变化公共路径的已有验证证据，不运行全仓测试。

配置验收核对商品计费模式与渠道配置匹配；同一渠道价存在不代表已具备协议换价能力，Stripe / Clink 的自动续费路径须连同升档一起验收。

本次新购入口仅包含已配置的 Stripe / Clink，PayPal 不展示；停止新销售不关闭历史付款通知或协议处理。换档策略与事件分工见 [Stripe 渠道合同](../tech-Stripe支付.md#与-clink-的统一业务规则)。

一次性旧权益抵扣以本期已生效的整期价格快照为基数，目标价读取当前渠道配置。复用既有订单查询读取原周期价值，新升档的 `product_snapshot.amount` 统一保存目标整期价，`orders.amount` 保存净应付；上次净实付 41 美元、实际换得 50 美元套餐时，下次折算的整期价值是 50 美元，不使用 41 美元或后来改动的标价。不新增订阅表价格字段。上线前核对是否存在旧升档单：旧实现的快照金额为净额，不能直接按新语义使用，需依据实际订单数据确定回填或暂停该实例升档。

真实收款与 Webhook 验收需要该环境的 API 凭据、对应事件接收端签名密钥及可达回调。开发机可使用 Stripe CLI 转发；最终环境还需验证公网事件接收。所有密钥经后端配置提供，不进入源码、文档或浏览器前端。
