# 001 · ClinkBill 支付渠道接入计划

> 状态：待用户批准，禁止实施。
>
> 设计合同：`@../tech-ClinkBill支付.md`

## 1. 交付原则

- 一次交付同时完成 Credits 一次性支付、Unlimited 一次性支付和 Unlimited 自动续费。
- 不发布只有一次性支付的中间版本。Clink 渠道只能在三条路径全部自动化测试通过后启用。
- 复用现有 OrderService；不新增一套 Clink 订单系统、Webhook 表、支付尝试表或依赖注入。
- 未提供 Sandbox Secret Key 时可完成代码和本地签名验证，但不宣称真实首笔支付完成。

## 2. 执行单元

### 2.1 配置与数据合同

- [ ] 在支付常量中增加 `clink` 渠道标识、支持币种/金额转换合同。
- [ ] `config_subscription_product_price` 新增可空 `provider_product_id VARCHAR(128)` 并补充 model/service 字段；不改现有 `(product_id, channel_code)` 唯一约束，不加新索引。
- [ ] 订阅 checkout 配置和订单快照透传 `provider_product_id`；现有 `provider_sku` 在 Clink 渠道表示 `priceId`。
- [ ] 把 `CLINK_SECRET_KEY` / `CLINK_WEBHOOK_SIGNING_KEY` 加入运维 `.env.*` 模板；部署脚本通过标准输入同步到业务服务器 `0600` 运行时 `.env`，Supervisor 启动时加载，不进入 download 节点。
- [ ] 更新部署脚本测试，确认密钥不进入命令行参数、生成 YAML、Supervisor 模板或日志。
- [ ] 执行 schema 同步并用 `information_schema` 确认字段类型、可空性和注释。

验收：不启用 `clink` 渠道时，现有 PayPal/Telegram Stars 配置和下单行为不变；Clink 密钥不在 Git diff 和生成配置中。

### 2.2 Clink Provider

- [ ] 新增 `ClinkPaymentProvider`，使用现有 `httpx.AsyncClient`，不引入 SDK。
- [ ] 解析渠道非密配置，直接从服务端环境读两个 Clink 密钥；错误中不回显密钥或 Checkout token。
- [ ] `create_payment` 按创建本地订单时已冻结的 `PaymentRequest.auto_renew` 分支：`false` 发送 `priceDataList`，`true` 发送 `productId + priceId`；创建 Session 时不重读运营配置。
- [ ] 严格转换项目 6 位精度金额为 Clink 主币种单位，测试捕获实际 HTTP JSON 验证没有倍数错误。
- [ ] 解析 `data.sessionId/data.url`，返回 `sessionId/checkoutUrl/payment_url/url`，不在 Session 阶段返回 `channel_order_id`。
- [ ] 将 Provider 注册进现有 `PaymentService`，已停止新销售的历史 Clink 订单仍能构造 Provider 验证回调。

验收：Provider 单元测试同时证明 Credits、Unlimited 一次性、Unlimited recurring 三种请求映射和响应解析。

### 2.3 Webhook 与续费映射

- [ ] 新增 `POST /api/callback/clink/payment`，按原始 body 验证 SignType、前后 300 秒时间窗和 HMAC-SHA256。
- [ ] 只接受 canonical `order.succeeded` / `invoice.paid` envelope，从 `event.data.object` 取业务对象。
- [ ] 一次性 `order.succeeded` 用 `merchantReferenceId` 读本地订单，同时比对本地 `payment_data.sessionId`、渠道、金额、币种和订单快照计费模式。
- [ ] `type=onetime` 用 `orderId` 作为 `channel_order_no`。
- [ ] recurring `order.succeeded` 验签后返回 2xx，但不履约；自动续费统一由 `invoice.paid` 驱动。
- [ ] `invoice.paid` 用 `subscriptionId` 查询 Clink Subscription，以返回的 `merchantReference + sessionId` 双重定位首单，再用 `invoiceId` 作为 `channel_order_no`、`orderId` 作为 `transaction_id`。
- [ ] 把 Provider 验证结果交给现有 `handle_payment_callback`，不在路由里复制订单更新/履约逻辑。
- [ ] 结构/签名/对账失败返回非 2xx；首次或幂等成功返回 2xx。

验收：直接测试有效签名、被篡改 body、错误 SignType、过期时间戳、双引用不一致、金额/币种不一致、recurring Order 不履约、一次性重投和 Invoice 续费重投。

### 2.4 前端渠道与 Checkout URL

- [ ] 在 `website-shared` 公共 checkout 与 `website-tgd-pro` 独立支付入口增加 `clink`，不建新的支付状态机。
- [ ] 两套入口都读取 `checkoutUrl/payment_url/url`，允许 Sandbox/正式 Clink Checkout HTTPS host，拒绝其他 URL。
- [ ] 渠道选择、新窗口打开、订单轮询、关闭和失败状态复用现有组件。
- [ ] 同步维护 website-tgd-pro 的共用支付入口，不出现两站点渠道白名单漂移。

验收：前端模块测试证明 Clink 官方 URL 可打开、非官方 URL 被拒绝，原页仍以本地订单轮询为支付结果。

### 2.5 Catalog、运营配置与部署

- [ ] 从当前 Unlimited 商品/价格/图片生成 `clink-catalog.json`，每个注册商品仅使用一种图片来源。
- [ ] 运行官方 catalog validate/plan/import，把 Sandbox `productId/priceId` 写入 Unlimited + Clink 渠道价配置。
- [ ] 添加 Credits 和 Unlimited 的 Clink 渠道价，使用项目 `sql_executor.py`；不在业务代码/测试中写配置表。
- [ ] 用 `clink webhook endpoint ensure` 注册公网 HTTPS `order.succeeded,invoice.paid` 端点并同步签名密钥。
- [ ] 部署后重启业务进程，确认健康检查和现有支付渠道正常。

验收：运营只修改 Unlimited `metadata.auto_renew` 就能控制之后新 Clink 订单的一次性/recurring 模式；创建订单时该值已经进入 `product_snapshot.metadata`，无需新增订单字段，也不修改已创建订单。配置缓存最多 3 分钟后生效。

### 2.6 自动化验证与真实首笔支付

- [ ] 运行后端 formatter、ruff、mypy 和 Clink 相关的最小测试集。
- [ ] 运行网站 TypeScript 检查、模块测试和 build。
- [ ] 用真实 MySQL 和现有 Redis 验证首期成功、重复 Webhook 不重复履约、新 `invoiceId` 创建一条续费订单。
- [ ] 交付项目下单 curl、直连 Sandbox 排查 curl、Webhook simulate 命令和启动命令。
- [ ] 人工打开真实 Sandbox `checkoutUrl` 完成 Credits 首笔支付，核对真实 Webhook、订单状态与 Credits 到账。
- [ ] 分别验收 Unlimited `auto_renew=false/true` 首期支付，再用 Test Clock 验收一次自动续费扣款和本地续期。

验收：只有真实 Hosted Checkout 支付、真实 Clink-to-endpoint Webhook、本地订单已支付且权益已实际变化，才标记首笔支付完成。

## 3. 不可独立发布的依赖

```text
配置/数据合同
  -> Clink Provider + Webhook
  -> 前端渠道
  -> Catalog + Sandbox 配置
  -> 自动化验证
  -> 真实 Credits + Unlimited 首期 + Unlimited 续费验收
  -> 启用 clink 渠道
```

步骤可分单元实施和验证，但在三种购买路径都通过前，`clink` 渠道配置保持禁用，不形成用户可见中间版本。

## 5. 批准闸门

用户批准本计划后才能实施。批准同时确认：

- 允许给 `config_subscription_product_price` 新增 `provider_product_id` 持久字段。
- 不新增 Webhook Inbox/支付尝试表或 Clink 专用 Redis 幂等层；一次性使用 Clink `orderId`，recurring 使用 Clink `invoiceId`，复用现有订单 CAS 和自动续费 Redis 短锁。
- 运营 `metadata.auto_renew` 只影响新订单，已创建订单和已生效的 Clink 订阅继续使用其订单快照。
- 退款、争议、用户取消自动续费不在本计划。
