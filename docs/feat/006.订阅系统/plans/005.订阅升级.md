# 005 · 订阅升级

> 设计合同：`@../tech-订阅升级.md`；产品口径见 `@../feat.md`「升级订阅」。

> 实例字段、自然月账期、Clink 渠道之上）。

## 目标

同产品线未过期订阅补差升级到更高档位：一次性线（online / api）差额单走收银台；
自动续费线（maps_extension）渠道协议内换价；立即生效、到期日不变。

## 执行单元

### U1 报价与升级判定（后端）

- [ ] 档位序判定：同线内按商品配置 `sort_order` 升序判高；补差计算（剩余占比 × 旧档月价，`start_at` 缺失按 30 天）。
- [ ] `GET /api/client/subscription/upgrade-quote`：可升级判定 + 实时报价合同（`available/reason/amount/...`）。
- [ ] 一次性线履约收紧为同时写 `start_at`（历史行无 `start_at` 走 30 天折算）。
- [ ] 错误码与 i18n 文案（不可升级各 reason）。

验收：报价接口对各线有效订阅/无订阅/最高档/补差≤0 的返回正确；金额 6 位精度口径与 money 工具一致。

### U2 一次性线差额订单（后端）

- [ ] `POST /api/client/subscription/upgrade/checkout`：服务端定价建升级订单（快照冻结
  `purpose=upgrade`/`target_product_id`/`base_expires_at`/折算输入），跳过同线拦截与客户端价比对，调 Provider 返回支付数据。
- [ ] 履约分支：`purpose=upgrade` 只换档（`product_id`/`product_price_id`/`payment_method`），
  `expires_at` 保持 `base_expires_at`，渠道引用字段清空；回调时行已过期则履约失败转人工。
- [ ] 升级订单在管理后台订单列表带升级标记。

验收：Lite→Growth 补差支付后档位/配额立即新档、`expires_at` 不变；过期套利路径被拦截。

### U3 自动续费线渠道换价（后端）

- [ ] `POST /api/client/subscription/upgrade/confirm`：PayPal `revise` / ClinkBill update（preview→confirm），
  成功后本地同步换档（`product_id`/`product_price_id` 更新，`expires_at`、渠道引用、`auto_renew` 不变，`cancelled_at=null`）。
- [ ] **续费履约档位保护**：自动续费履约仅在回调单号 = `original_order_no`（首购单）时覆盖行内档位；
  续费/折算发票回调只推进账期事实。
- [ ] 幂等：重复 confirm 按渠道"已是该价"幂等成功。

验收：Maps Pro→Business 渠道扣折算差额、本地立即换档；下一期续费按新价且不回退档位（该验收依赖渠道沙箱/真实凭据，无凭据时以 Provider 层测试为准）。

### U4 Pricing 页升级交互（前端）

- [ ] 当前档"Current Plan"标记；更高档 CTA 切升级态（展示补差金额，报价接口）；低档灰化。
- [ ] 一次性线：升级差额单复用统一 checkout 弹窗（服务端定价金额）。
- [ ] 自动续费线：升级确认弹窗（补差估算 + 立即扣款提示）→ confirm → 刷新账号区与按钮态。
- [ ] i18n（en-US 基线）与埋点（`upgrade_quote_shown` / `upgrade_confirmed`）。

验收：线上口径与 `011/feat.md`「升级订阅」一致；四线按钮态正确（extension 线无升级场景维持现状）。

### U5 测试与文档收尾

- [ ] 后端：报价判定、差额计算、升级履约、渠道换价 Provider 层、档位保护规则的测试（布局随 gmap 现状）。
