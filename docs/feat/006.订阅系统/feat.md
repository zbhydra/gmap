## 系统定性

订阅系统按产品类别隔离权益:Maps 浏览器插件、Online Scraper 与 Scraper API。同一账号可同时持有三类产品的订阅,不同类别互不续期、互不影响重复购买判断。Google Maps 与 Bing 插件共享同一类插件订阅。三条产品线按商品配置提供一次性或自动续费权益,本次新销售开放 Stripe / Clink。

- 每类产品都有独立 Free 档与月度额度。
- 付费档的续费方式由商品配置决定；套餐额度与实际采集计量合同分别由本域与额度基建维护。
- 购买入口只在 website pricing 页,见 `@../011.Pricing页/feat.md`。
- extension 不再承载订阅套餐购买页;旧 options 订阅卡和订阅提示弹窗已删除。
- Telegram Stars 保留为共享支付基建;具体商品是否可用该渠道由渠道价配置决定。

## 功能目标

为三类 Maps 产品提供可配置的订阅权益:

1. 免费用户有明确的月度额度。
2. 付费用户按所购类别与档位获得订阅权益。
3. 订阅状态可由双插件与已登录账号摘要读取。
4. 付费权益到期后回到 Free，用户可再次单次购买。

## 功能范围

### 包含

- 订阅商品定义:三类 Maps 产品的 Free 与付费档位。
- 订阅权益:对应产品的月度额度与档位。
- 用户订阅状态:当前档位、生效/到期时间。
- 订阅到期降级:有效期结束后自动回到 Free。
- 订阅状态查询:给 extension 展示与已登录账号摘要读取当前档位与账期。
- 与自动续费账单衔接:Stripe / Clink 首期成功、后续续费成功、到期降级;历史渠道协议继续处理。
- 已有未过期订阅时拒绝同产品线普通重复购买(升级到更高档除外,见「升级订阅」);不增加并发锁或渠道协议状态机来保证绝不会重复订阅。
- 同产品线升级订阅:抵扣未过期旧套餐的剩余价值,购买更高档位的完整新周期;付款与换档成功后生效并重开账期。一次性支付走原渠道收银台,自动续费在原协议内换价收款。
- 自动续费订阅管理:Dashboard 订阅管理页按当前产品线打开 Stripe / Clink 客户门户，历史渠道保留原管理入口；不在站内直接取消。
- 好评赠送 7 天活动保持关闭,保留服务能力;重新开放前需确认赠送产品。

### 不包含

- Credits 余额、扣费、积分包购买。
- 下载解析、下载执行、节点调度。
- 退款、补偿、发票、税务、对账。
- 同产品线降级与折算退差;降级(下期生效)属后续需求。
- 其他订阅档位、多席位、优惠码。
- extension 端直接拉起支付;购买入口首版只在 website pricing 页。
- extension options 订阅套餐页、订阅卡片、插件内订阅支付提示弹窗。
- 站内直接取消或恢复自动续费；用户从 Dashboard 订阅管理页进入支付渠道完成操作。
- 取消后的退款、按比例退费、立即降级。
- 注册试用订阅的新设计;注册赠送 Credits 属于积分系统。
- 验证用户是否真实提交好评、读取评价内容或与 Chrome Web Store 账号关联。
- 好评赠送的补偿、对账、人工补发和倒计时恢复。

## 业务流程

### 免费用户使用

1. 用户在未持有有效付费订阅的产品类别下处于 Free 档。
2. 采集与调用额度由对应产品的消费入口计量,见额度基建与产品域合同。
3. 双插件的升级入口引导到 website pricing 页。

### 购买订阅

1. 用户在 website pricing 页选择产品类别与档位。
2. 如用户在该产品线上已有未过期订阅,pricing 页订阅按钮灰化;点击后提示存在有效订阅,不可重复购买(重复购买校验按产品线隔离,适用于包括 `maps_online`/`maps_api` 在内的全部产品线,互不影响另一产品线的购买)。
3. 该产品类别无有效付费订阅时，用户选择该商品已配置的 Stripe / Clink 渠道，按商品计费方式购买。
4. 支付渠道付款成功后,系统按商品周期发放自然月订阅权益。
5. 用户刷新订阅状态后,对应产品显示新档位与权益。

购买页面、支付确认、轮询和异常见 `@../011.Pricing页/feat.md`。

### 自动续费账单

商品按配置提供自动续费，扣款由支付渠道执行；已有协议保留原处理能力。

1. 支付渠道在每个周期自动扣款。
2. 扣款成功后,系统延长订阅有效期。
3. 扣款失败时,当前已付周期内权益保留;到期仍未续费则回到 Free。
4. 重复 webhook 不重复延长同一周期。

### 领取好评赠送订阅(已下线)

活动保持关闭,前端无领取入口,后端拒绝领取且不产生副作用。7 天赠送服务能力保留;重新开放前需确认赠送产品并显式传入类别与档位。以下为下线前的历史流程:

1. 系统读取好评赠送活动开关;关闭、缺失或配置非法时不展示入口且不允许领取。
2. 未领取账号在 Pricing 的订阅购买确认中选择“去好评”。
3. Pricing 打开插件的 Chrome Web Store 评价页,并在原页面显示 30 秒检测倒计时。
4. 倒计时结束后,系统按登录账号检查永久领取次数。
5. 未领取时先将永久次数增加 1,再把当前订阅到期时间增加 7 天;无有效订阅时从当前时间起算 7 天。
6. 已领取时不再增加订阅,按已完成返回。
7. 领取成功后 Pricing 刷新账号订阅状态,不再进入本次付费购买。

该流程不验证真实评价。界面与交互见 `@../011.Pricing页/feat.md`,技术合同见 `@tech-好评赠送订阅.md`。

### 管理自动续费

1. 已登录用户在 Dashboard 订阅管理页查看当前产品线的有效自动续费订阅。
2. 页面展示“Manage subscription”;点击后由服务端根据当前产品线和订阅实例确定支付渠道。
3. Stripe / Clink 打开 Customer Portal；历史 PayPal 打开 Automatic Payments；没有网页管理入口的渠道展示渠道内操作路径。
4. 页面只负责打开渠道入口,不在站内直接取消、不修改订阅状态或到期时间。
5. 渠道侧取消不改变当前已付周期权益；Stripe / Clink 的期末取消安排可在生效前从原渠道恢复。渠道未通知本站时，页面状态允许暂时滞后。

### 升级订阅

1. 适用范围:同一产品类别内从当前付费档换到更高档位(Maps 插件 Pro → Business,Online 与 API 各档位向上)。
2. 已登录用户在 pricing 页当前产品线的更高档卡片上看到升级入口与补差金额;当前档卡片标记为当前套餐。
3. 本次应付为新套餐完整周期价格减旧套餐剩余价值。旧权益按剩余时间折算抵扣,不再叠加旧剩余时长;成功后使用本次升档对应的新账期。按 30 天估算,10 美元套餐使用 3 天后抵扣 9 美元,升级 50 美元套餐支付 41 美元并重开一个月。自动续费的新账期以支付渠道给出的已付周期为准。
4. 升级沿用当前订阅的支付渠道与续费方式,不跨渠道换档。一次性支付成功后切换新档并更新账期开始和到期时间。
5. 自动续费通过 Stripe / Clink 在原协议内重开账期并折算收款。确认弹窗展示抵扣后应付及新账期,付款成功且渠道换档生效后更新权益;处理中或需要跳转时等待终态,不重复扣款。用户关闭页面后仍接收渠道结果,后续按新账期和新档价格续费。
6. 用量继续按自然月统计,升级只提高本月额度上限,不清空已用量。已用 300 条、升级后上限 5000 条时显示 300 / 5000,剩余 4700 条；付费账期重开不重置用量。
7. 不可升级情形:同线无有效订阅(走正常购买)、目标不是更高档、补差金额不为正;升级入口灰化并提示原因。已申请期末取消的自动续费订阅,需先在渠道管理页恢复续费,再允许升档。
8. 本次新销售与两种升档路径开放 Stripe / Clink;PayPal 暂不开新销售,保留历史付款和协议处理。存量 PayPal 订阅本期不提供升档,到期后可改用 Stripe / Clink 购买;Telegram Stars 不参与升级。

### 订阅状态查询

1. 已登录用户按账号读取订阅状态;账户摘要按产品线分别携带各线状态对象。
2. 匿名用户按该产品线 Free 档处理,不展示购买档位。
3. 状态表达当前档位与账期:档位名、计费周期、到期时间与续费方式;不含每日额度或旧下载标量字段。
4. Credits 与订阅产品类别独立。
5. 订阅配置异常时状态按不可用降级展示,不阻断登录态与其他业务。

状态接口与字段的完整合同见 `@tech-订阅商品与状态.md`。

### extension 升级入口

1. extension popup 或内容页只展示当前额度状态、额度不足升级引导和登录入口。
2. 双插件的购买与管理入口统一打开网站 Pricing，插件只保留权益状态与入口；页面交互合同见 [Pricing 域](../011.Pricing页/feat.md)。
3. 官网 pricing 页负责登录、套餐展示、支付确认、订单轮询和订阅生效。
4. 插件端不展示旧订阅方案,不展示购买卡片,不弹插件内订阅支付提示。

## 异常流程

- 自动续费首期支付失败:不生效付费权益,用户仍为 Free。
- 已有同类有效订阅时再次购买:前端订阅按钮灰化并提示不可重复购买;后端下单校验同样拒绝创建订阅订单;更高档位改走升级流程。
- 升级差额订单支付完成时原订阅已过期或已被其他操作修改:不覆盖当前订阅,订单转人工处理。
- 自动续费线渠道换价失败或原订阅协议不存在:本地权益保持不变,用户可重试或到期后按新档重新购买;渠道已完成换价但页面关闭时,服务端仍通过渠道事件同步档位。
- 渠道返回处理中时保持等待，不能提前展示升级成功或重复扣款；明确失败时不换档。
- 用户在两个未完成的普通购买 checkout 中分别确认付款:不做并发锁或跨渠道协议协调;两笔成功付款按正常订单履约,极少数重复订阅由支持处理。
- 后续续费失败:当前周期到期前保持权益,到期后降级。
- 渠道管理入口创建失败:页面展示重试,不修改订阅状态或到期时间。
- 用户在渠道侧取消但本站未收到通知:本站可继续显示自动续费状态,不主动猜测或改写渠道事实。
- webhook 重复到达:不重复延长。
- 订阅状态读取失败:前端展示重试;采集计量失败语义见额度基建与各产品域。
- 支付成功但订阅写入失败：按[订单域恢复边界](../004.订单系统/feat.md#履约补偿分支)进入补偿或人工排查，已确认的付款保留；确定性失败或结果仍不明时提示联系支持。
- 好评赠送活动关闭、配置缺失或配置非法:不展示入口;旧页面或直接请求领取时返回请求无效,不写 Counter 或订阅。(2026-09-02 起活动下线,任何请求领取均返回请求无效)
- 好评赠送抢锁失败或 Redis 不可用:返回服务器繁忙,用户可在检测界面直接重试。(活动下线,当前不可达)
- 好评赠送永久次数已存在:按已领取完成,不报错、不重复加时。(活动下线,当前不可达)
- 好评赠送 Counter 已写入但订阅加时失败:本次返回失败;不回滚 Counter、不补偿,后续请求按已领取跳过。(活动下线,当前不可达)

## 非功能性需求

- 不新增第三方依赖;不新增依赖注入。
- 订阅配置、价格、权益只走配置表,不写死在前端。
- 文案需 i18n。
- 不做金融级对账;失败让用户重试,已支付未履约走补偿或人工排查。
- 好评赠送只使用 5 秒 Redis 短锁,不续租、不增加复杂状态机或跨数据库事务。
- 所有业务时间口径以 `America/New_York` 为准。

## 验收标准

- 三类产品的 Free 与付费订阅独立,Google Maps 与 Bing 共享插件订阅。
- 匿名设备按对应产品 Free 档处理。
- 付费档通过 pricing 页按商品配置和可用渠道购买。
- 已有同类有效订阅时不能普通重复购买,更高档位走升级入口。
- 有效订阅可抵扣剩余价值升级到同线更高档:支付新档完整周期的净价,成功后换档并重开完整账期,不叠加已抵扣的旧剩余时间。
- 一次性与自动续费升档均沿用当前渠道和续费方式;Stripe / Clink 在付款及换档终态确认后生效,关闭页面仍可同步,重复通知不重复重开周期。续费后权益不得回退到首购档位。
- 非更高档、补差金额不为正、同线无有效订阅时,升级入口不可用并有明确提示。
- 有效自动续费订阅在 Dashboard 展示本人渠道管理入口；Stripe / Clink 与历史渠道分别打开对应管理页。
- 打开、返回或关闭渠道管理页不会修改本站订阅状态与到期时间。
- extension options 不再出现订阅套餐购买页;旧订阅卡片和插件内订阅提示弹窗已移除或不再被引用。
- 已登录与匿名用户都能查看当前产品线的档位与账期;订阅配置异常时按不可用降级展示,不报错、不阻断其他业务。
- 续费 webhook 重复到达不重复延长权益。

## 用户操作逻辑与 UI 元素

### extension 订阅状态展示

extension UI 只做状态展示和升级引导,不做套餐选择和购买。

| 元素 | 形式 | 可点击 | 行为 |
| --- | --- | --- | --- |
| 当前档位 | 文本 | 否 | 按插件产品合同展示免费或付费状态 |
| 月度用量 | 文本 | 否 | 按额度基建与插件产品合同展示用量 |
| 升级按钮 | 按钮 | 是 | 打开 website pricing 页 |
| 到期提示 | 文本 | 否 | 付费订阅显示到期或续费状态 |
