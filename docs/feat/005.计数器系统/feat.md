## 功能目标

为 extension(浏览器插件)端提供"每日下载次数额度"能力:按登录用户或匿名设备作用域,统计当天已发起的下载次数,按服务器本地自然日(0 点为界)重置,并在下载发起前做额度扣减拦截。匿名用户通过设备标识符参与计数,规则见 `@tech-device_id与匿名下载.md`(下文"设备标识"即指该标识符)。

## 功能范围

### 包含

- extension 端每日下载次数额度:当天已用次数、剩余次数、当日重置。
- 匿名下载(设备标识作用域)的次数额度:与登录用户额度分桶独立、互不占用。
- 下载发起前的额度扣减拦截:下载链路在解析成功、准备让用户在浏览器本地落盘前,先扣减当日次数(下载链路本身在 `@../002.下载功能/feat.md`)。
- 额度查询口径:插件通过订阅状态接口获取插件下载当日用量,供插件端展示剩余次数。
- extension 端额度上限配置:从订阅配置读取,Free 当前 5 次/天,Unlimited 为不限次数。
- extension 端额度服务的失败策略(可失败放行,见下文)。

### 不包含

- website 下载额度 → 完全走 Credits,见 `@../003.积分系统/feat.md`。website 下载不消耗本域次数、不写本域计数。
- extension 端下载**不消耗 Credits、不写积分流水、不写下载记录**(口径与 `@../003.积分系统/feat.md` 一致,互相呼应)。
- 下载解析、下载授权、下载执行、三种下载模式、续传、断流 → 见 `@../002.下载功能/feat.md`,本域只在下载发起前扣一次次数。
- 节点角色、节点调度、节点健康、节点管理 → 见 `@../001.节点系统/feat.md`。
- 邮箱验证码频率限制、登录限流、IP 限流等非"每日下载次数"的限制。
- 网页播放额度(播放功能已屏蔽)。
- 任何不是"extension 每日下载次数"的计数。
- 匿名用户计数与登录用户计数的自动合并(本域不做合并,见下文)。

## 现状说明

extension 端下载额度是**按天计数的次数口径**:每个登录用户或匿名设备在当天有一个"已用次数",达到当日上限后拦截下载,服务器本地次日 0 点重置。当前上限来自订阅配置:Free 为 5 次/天,Unlimited 为不限次数(`-1`)。

website 下载**不走本域**:website 下载额度以 Credits 为准(`@../003.积分系统/feat.md`);订阅状态接口里给 website 用的网页下载额度字段固定回 0。

## 业务流程

### 主流程:extension 下载前扣次数

1. 用户在插件点击下载(单条或批量)。
2. 插件端的下载链路在准备让浏览器本地落盘前,先调用本域的次数扣减入口,传入本次要下载的资源条数(下载链路本身在 `@../002.下载功能/feat.md`)。
3. 服务端识别当前作用域:已登录用户按用户标识计数,匿名用户按设备标识计数。
4. 服务端按"服务器本地自然日"读取当天已用次数,原子判断"已用 + 本次条数"是否超过当日上限。
5. 未超上限:增加当天已用次数,返回允许;插件继续完成本地下载落盘。
6. 超过上限:不增加已用次数,返回不允许;插件展示升级引导(见"用户操作逻辑与 UI")。
7. 用户点击升级引导的主按钮时,插件打开官网 Pricing 页。

### 匿名下载

- 匿名用户不要求登录,通过设备标识请求头携带设备标识符参与计数(请求头名称与生成、校验规则见 `@tech-device_id与匿名下载.md`)。
- 匿名设备的次数额度独立存储,与任何登录用户额度分桶独立、互不占用。
- **本域不做匿名 → 登录的计数合并**:匿名设备上的已用次数不会在用户登录后累加到用户账号。用户登录后切换为按用户标识作用域计数,匿名设备上的旧计数不跟随。
- 既无登录凭据又无设备标识的请求,由下载入口按其登录要求处理(本域不额外兜底)。

### 按天重置

- 以**服务器系统时区**的 0 点为界:跨过 0 点即进入新一天,从 0 重新计数。
- 当天的计数记录在跨天后自然失效(实现见 `@tech-计数数据与重置.md`),不会被新一天读到。
- 用户看到的"剩余次数 / 已用次数"始终只反映当天。

### 额度查询(订阅状态回带)

- 插件端通过订阅状态接口获取当日下载次数用量(接口规格、镜像字段口径见 `@tech-额度查询与前端.md`)。
- 该接口支持已登录用户和匿名设备:已登录按用户标识读,匿名按设备标识读。
- 订阅状态每次都返回插件下载当日用量;插件端读取并展示。
- 下载扣减成功后,插件端也可基于本次扣减返回的已用 / 剩余即时刷新本地展示,无需额外查询。

### 异常流程

- **额度服务异常(Redis 不可用等)**:本域对 extension 下载采用**可失败放行(fail-open)**策略——扣减入口在底层读写异常时记录详细错误日志,但仍然返回"允许下载",不阻断用户。原因:下载失败对用户伤害大于少量额度漏扣;线上可通过日志定位异常。具体实现见 `@tech-计数数据与重置.md`。
- **作用域无效**:设备标识缺失或格式非法、既无登录凭据又无设备标识,按各自入口的登录/参数要求返回明确错误,不进入计数。
- **单次扣减条数越界**:本次请求扣减的条数不在允许区间内,返回参数错误,不增加计数。
- **并发同时下载**:同一作用域并发扣减必须原子判断,不能因并发超过当日上限(实现见 `@tech-计数数据与重置.md`)。

## 非功能性需求

- 简体中文;文案需 i18n(插件端展示文案的多语言由插件国际化体系提供,本域只定义口径)。
- 不新增第三方依赖;不新增依赖注入。
- 按天结算以服务器系统时区 0 点为界。
- 失败错误信息必须能定位到作用域(用户标识或设备标识)和额度类型,不抛泛化错误。
- 允许局部出错让用户重试;不做金融级强一致;extension 下载在底层异常时放行(见上文)。
- 单次扣减条数必须在合理区间内(具体区间见 `@tech-计数数据与重置.md`),拒绝离谱值。

## 验收标准

产品视角的关键验收(技术层验收见各 `@tech-*.md`):

- extension 端发起下载前会扣减当日下载次数;达到当日上限时拦截并展示升级引导。
- Free 用户每日上限为 5 次;Unlimited 有效用户每日不限次数。
- 匿名设备(设备标识)与登录用户(用户标识)的当日下载次数分桶独立、互不占用。
- 匿名用户登录后,其匿名设备上的旧下载次数**不会**累加到用户账号(本域不合并)。
- 跨过服务器本地 0 点后,用户看到的"已用 / 剩余"从 0 重新开始,不出现昨天的已用次数。
- extension 下载**不消耗 Credits、不写积分流水、不写下载记录**(口径见 `@../003.积分系统/feat.md`)。
- website 下载**不走本域**,website 下载额度以 Credits 为准;订阅状态里给 website 用的网页下载额度字段固定回 0。
- 同一作用域并发下载不会因并发超过当日上限。
- 额度服务底层异常时,extension 下载仍被放行(可失败放行),且日志能定位到作用域。
- 插件端能从订阅状态拿到当日插件下载用量并展示剩余次数。

## 用户操作逻辑与 UI 元素

> 本功能的 UI 在 extension 端。文案需 i18n。下载链路本身的 UI(下载按钮、批量下载、续传)在 `@../002.下载功能/feat.md`,本域只描述与"次数额度"相关的展示和拦截。

### 插件端次数展示

| 元素 | 形式 | 行为 |
| --- | --- | --- |
| 剩余次数 / 已用次数 | 文本 | 展示当日剩余次数(或已用次数),数据来自订阅状态或最近一次扣减返回 |
| 无限额度状态 | 隐藏计数器 | 当额度上限为"不限制"语义时,插件端不展示计数器(具体判断见 `@tech-额度查询与前端.md`) |

### 额度不足拦截

| 元素 | 形式 | 可点击 | 行为 |
| --- | --- | --- | --- |
| 升级引导弹窗 | 弹窗 | 是 | 当次下载因当日次数上限被拦截时弹出,引导用户升级(升级动线本身不在本域) |
| 升级按钮 | 主按钮 | 是 | 打开官网 Pricing 页 |
| 下载按钮 | 按钮 | 是 | 额度不足时本次下载不发起,按钮回到可重试状态 |

交互规则:

- 额度不足时不静默失败,必须向用户展示可操作的升级引导。
- 升级引导主按钮打开 website Pricing 页,不再打开 extension options 订阅页。
- 批量下载在发起前一次性扣减全部条数;条数超出当日剩余时,整批不扣减、不发起,直接弹升级引导。
- 额度服务底层异常(可失败放行)时,不打断用户下载,也不弹升级引导。

## 数据埋点

- `upgrade_modal_open`:升级引导弹窗每次从隐藏进入显示时记录一次 extension SLS,不区分 Popup、页面下载按钮或其他打开入口。
- 弹窗已显示时的重复打开请求不重复记录;用户关闭后再次打开,重新记录一次。
- SLS 上报失败不影响弹窗展示和后续升级操作。
