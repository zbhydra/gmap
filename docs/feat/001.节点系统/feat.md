# 001 · 节点系统

> 产品需求文档。只描述"功能是什么 + 边界条件 + 用户操作 / UI"。技术实现(角色与路由、表结构、Admin API、节点本地管理、发布配置)见同目录 `tech-*.md`。
> 本域是通用执行节点底座。下载业务流程和下载接口规格见 `@../002.下载功能/feat.md`,计费见 `@../003.积分系统/feat.md`。

## 功能目标

把后端做成一套可水平扩展、多地区部署的通用执行节点底座,从架构层面解决:

- 业务服务器带宽和并发压力(把执行能力从单台业务服务器外移到多台节点)。
- 上游账号资源(如 Telegram session)在单机上的集中压力。
- 多地区就近执行能力。

节点系统本身不绑定任何具体业务语义:首阶段承载下载执行,后续可承载其他需要外移的执行能力。下载业务只是第一个跑在节点上的业务,接口规格和业务流程不在本域。

## 功能范围

### 包含

- 同一套后端代码以两种角色启动:业务服务器(`business`)和执行节点(`download`)。
- 业务服务器负责节点管理、节点调度、节点健康检查。
- 执行节点不连业务数据库,只提供执行能力、节点健康检查、节点本地管理。
- 节点统一调度规则:启用、健康、权重大于零的节点进入同一候选池,按权重加权随机抽取。
- 业务节点(具备业务数据库的节点)和执行节点同池参与调度。
- 节点生命周期管理:新增、启用、停用、手动健康检查、编辑基础信息。
- 节点本地资源管理:管理员可直连指定节点管理其本地资源(首阶段为 Telegram session、X Cookie 和 Instagram Cookie 文件)。
- 节点独立发布能力:复用同一份后端代码和镜像,不要求业务数据库、不执行数据库结构同步。
- admin 节点管理页对节点状态、健康、本地资源做可视化运维。

### 不包含

- 下载业务流程、下载授权 token、下载接口规格(parse / download 接口请求响应、错误码、文件大小分档)→ 见 `@../002.下载功能/feat.md`。
- 积分扣费、额度、订单 → 见 `@../003.积分系统/feat.md`。
- 下载过程中单次请求的自动迁移、跨节点 session 共享、字节缓存、对象存储落盘。
- 节点级"支持哪些平台 / 下载模式"的能力配置:所有节点统一暴露执行接口,具体能否在某节点跑由该节点本地 cookie / session / 平台配置 / 执行依赖 / 上游权限决定,失败时由节点本地接口返回节点不可用,客户端试下一个。
- 依赖外部负载均衡器(如 Cloudflare Load Balancer):节点列表由业务服务器按调度规则返回。

### 域边界事实

- 节点系统只提供执行环境、调度规则、健康检查、节点 Admin 与节点本地管理。
- 下载业务的 V2 接口规格、token 设计、前端切换属 `@../002.下载功能`。
- 计费属 `@../003.积分系统`。
- 节点本地管理暴露 Telegram session 与媒体 Cookie 管理接口;session / cookie 池的产品规则分别沿用 TG 账号池与管理后台渠道设置的边界,本域只提供"在节点上管理本地副本"的运维能力。

## 业务流程

### 节点加入流程(主流程)

1. 在目标地区部署同一份后端包或镜像,以执行节点角色启动。
2. 挂载该节点自己的本地数据目录(Telegram session、X / Instagram Cookie 文件等)。
3. 管理员在 admin 服务节点管理页新增节点,填写名称、类型、地区、公网地址、内网地址、权重、启用状态。
4. 业务服务器健康检查调度定期访问节点健康接口,状态从 unknown 转为 healthy。
5. 健康通过且启用、权重大于零后,节点进入候选池,开始参与调度。
6. (可选)管理员在该节点上配置本地资源(Telegram session、X / Instagram Cookie),再启用。

### 节点切换(异常分支)

调度返回的节点对调用方不可达(超时、连不上、DNS / TCP / TLS 失败、网关不可达、节点返回不可用)→ 调用方按候选列表试下一个节点。明确业务错误(token 无效 / 过期、资源不存在、权限不足、文件过大)不换节点,直接失败。

### 节点下线 / 维护(分支)

- 维护:管理员在 admin 停用节点(`enabled=false`),节点不再参与调度,但保留健康检查和本地管理入口,允许先配置再启用。
- 下线:停用 + 健康状态置为不可用,业务服务器不再返回该节点;已发出的请求由调用方按切换规则处理。

### 节点本地资源管理(分支)

管理员按目标节点公网地址直连节点本地管理接口,不经业务服务器代理;业务服务器只提供节点列表、节点配置和 admin 登录 / token 刷新。本地管理请求的可用前提是节点存在、最近健康状态为 healthy、公网地址合法;停用节点允许执行本地管理(先配置后启用)。

## 非功能性需求

- 执行节点不连业务数据库,降低部署成本和泄露半径。
- 支持在不同地区部署多个执行节点,统一调度。
- 节点调度只依赖内存内候选池规则,不引入新的调度中间件。
- 节点健康检查在业务服务器后台以固定间隔运行,单节点失败不影响其他节点。
- admin access token 有效期固定 30 分钟,refresh token 有效期固定 7 天。
- 节点本地管理接口鉴权只做 JWT 纯验签,不访问业务数据库、不访问 Redis。
- 管理员被停用后,已签发的 admin access token 最长仍可用到 30 分钟过期(本架构接受的短窗口风险;需立即阻断时通过防火墙、停用节点或回收节点 JWT 密钥处理)。

## 验收标准

产品视角的关键验收(技术层验收见各 `tech-*.md`):

- 后端可通过配置启动为业务服务器或执行节点;执行节点不连业务数据库也能完成健康上报和节点本地管理鉴权。
- 管理员可在 admin 新增、激活、停用、编辑、手动健康检查节点。
- 业务节点(类型为业务)和执行节点(类型为下载)进入同一个候选池,候选池不按节点类型区分。
- 调度规则统一:只选启用、健康、权重大于零且公网地址合法的节点;按权重加权随机抽取最多若干个;候选不足时返回实际可用数量,候选池为空时返回节点不可用错误。
- 业务节点既能管理本机 Telegram session,也能作为普通节点被调度;执行节点通过 admin 直连管理其本地 session 与 cookie。
- 停用的节点保留健康检查和本地管理入口,但不参与调度。
- 节点缺少本地 cookie、session、平台配置或执行依赖时,由节点本地接口返回节点不可用,而不是在调度层过滤。
- admin 可在指定节点查看、添加、验证、删除 Telegram session;直连节点分别查看、新增、更新、删除本地 X / Instagram Cookie。
- 节点本地管理接口校验 admin token 时不访问 Redis 或业务数据库。
- 执行节点独立发布流程能跳过数据库结构同步,在没有业务数据库和 SMTP 配置时正常启动并通过健康检查。

## 用户操作逻辑与 UI 元素

> 节点系统的 UI 集中在 admin 服务节点管理页。文案需 i18n。

### 服务节点管理页

节点列表表格,列:节点 ID、节点类型(业务 / 下载)、名称、地区、公网地址、内网地址、启用状态、权重、本地运行态诊断(session 数、各媒体 cookie 文件状态、版本、最近错误)、最近健康状态、最近健康时间、session 数、版本、最近错误、操作。

行操作(可点击):

- 新增节点:打开表单,填写类型、名称、地区、公网地址、内网地址、启用状态、权重。
- 编辑节点:修改上述字段。
- 启用 / 停用:切换是否参与调度。
- 手动健康检查:立即检查并刷新该节点状态。

是否参与调度由"启用状态 + 健康状态 + 权重"共同决定。

### 节点 Telegram client 管理页

复用现有 Telegram 客户端管理交互,增加节点上下文:

- 页面顶部显示当前节点名称、类型、健康状态。
- 业务节点显示本机 session;执行节点显示远端节点 session。
- 添加、验证、删除、登录流程都按目标节点执行。
- 健康但停用的节点允许执行这些操作(先配置后启用)。

### 节点媒体 Cookie 管理页

复用管理后台渠道设置的 X / Instagram Cookie 双 Tab 交互,增加节点上下文:

- 页面顶部显示当前节点名称、类型、健康状态。
- 业务节点显示本机各平台 cookie 文件;执行节点显示远端节点本地各平台 cookie 文件。
- 新增、更新、删除按目标节点执行。
- 健康但停用的节点允许操作(先配置后启用)。

### 节点本地管理可用条件

Telegram client 管理、媒体 Cookie 管理的目标节点可用条件是:节点存在 + 最近健康状态为 healthy + 公网地址合法。`enabled=false` 只表示不参与调度,不阻止本地管理请求(管理员必须能先给健康但停用的节点配置 session / cookie,再启用)。
