# 001 · GSC 与 GA4 采集扩展

## 目标

扩展现有运行时 GSC / GA4 快照采集,仍然每轮写入 `GSC` 与 `GA4` 两条 `google_metric_snapshots` JSON,不新增表、不新增依赖、不改授权流程。

## 依赖 plan

无。

## 改动范围

- 文档:`docs/feat/009.SEO与增长/tech-GSC与GA4采集.md`
- 后端:`backend/src/app/services/google_metrics_collect_service.py`
- 测试:`backend/tests/test_server/services/test_google_metrics_collect_service.py`

## 文件或模块责任

- `GoogleMetricsCollectService.collect_gsc()`:采 24H fresh 聚合与 24H top queries;在 7D / 28D 聚合窗口外,采 top queries / pages / countries / devices / dates;28D 生成高曝光低 CTR 列表。
- `GoogleMetricsCollectService.collect_ga4()`:保留现有 activeUsers 窗口,为 7D / 28D 增加 overview、用户首次来源、会话来源、入口页、国家、事件、核心业务事件、页面参与。
- 纯辅助函数:负责 Google API 请求体构造、GA4/GSC 响应解析、指标字段归一化。

## 验收标准

- GSC JSON 保留现有 `24h` / `7d` / `28d` 聚合指标。
- GSC 24H 含 `top_queries`,由 `query + hour` fresh rows 按最近 24 个可用小时聚合。
- GSC 7D / 28D 含 `top_queries`、`top_pages`、`countries`、`devices`、`dates`。
- GSC 28D 含 `high_impression_low_ctr_queries`、`high_impression_low_ctr_pages`。
- GA4 JSON 保留 `realtime_30m.active_users` 和 today / 7D / 28D `active_users`。
- GA4 `realtime_30m` 新增 `event_count`、`screen_page_views`。
- GA4 7D / 28D 含 `overview`、`user_acquisition`、`traffic_acquisition`、`landing_pages`、`countries`、`events`、`business_events`、`page_engagement`。
- `user_acquisition` 使用 `firstUser*` 字段;`traffic_acquisition` 使用 `session*` 字段。
- GSC 或 GA4 任一侧失败仍不影响另一侧写入。

## 风险与回滚

- 风险:Google Data API 对部分维度/指标组合返回 `INVALID_ARGUMENT`。
- 缓解:每侧采集失败只记录本侧错误,不影响另一侧;请求组合优先使用官方常见 acquisition / engagement 口径。
- 回滚:还原 `google_metrics_collect_service.py` 的扩展请求与 JSON 字段,保留旧 `activeUsers` / GSC 聚合快照结构。
