# 首页预览与 Dashboard 任务创建

> 已批准方案。执行与验收见 [实施清单](plans/004.首页预览与Dashboard创建.md)。

## 目标与边界

首页提供单关键词的快速采集体验；正式 Online 任务在现有 Dashboard 创建，继续使用既有任务、计量、历史与下载链路。

用户已确定：匿名只采一页基础数据，不创建任务；允许查看首屏结果的前 3 行基础预览，完整查看与导出必须登录；匿名记录不随登录保留，用户必须重新提交。

## 用户流程

- 首页操作区改为单关键词输入，去除原多行批量输入和 100 条占位上限。提交期间禁用重复提交，显示加载状态；失败就地提示重试，零结果显示真实空态。
- 基础字段为名称、地址、分类、评分、评论数、电话；只使用首屏已有值，缺值显示空缺，不为补字段追加网络请求。数量文案只称本次首屏条数，不声称全量搜索结果。
- 结果区按截图提供预览表和登录引导；隐藏部分由占位行表达，不能把未授权数据发给浏览器后仅用透明度遮挡。服务端只返回允许公开的样本行。
- 结果区的继续操作使用站级登录入口，登录后进入当前语言的 Dashboard。匿名结果和关键词不写浏览器持久存储、URL、任务表或对象存储，不携带到登录后；不会自动提交、解锁旧结果或补扣匿名用量。
- 已登录用户在首页操作区看到进入 Dashboard 的入口，正式采集仍需在 Dashboard 手动提交。
- Dashboard 默认历史页上方增加任务创建表单，下方保留唯一历史列表。侧栏该项改称 Online Scraper，不增加第二套历史页或新工作区路由。
- 创建表单包含多行关键词、去空行并去重后的数量与上限、Email/社媒开关、月度已用与总额度、额度按纽约时间每月重置的说明和提交按钮。权益、关键词上限、计量及任务状态遵循 [Online 需求](feat.md) 与 [任务合同](tech-Online任务与结果.md)。
- 创建约束加载失败时显示重试，不能猜免费档。提交失败保留当前页面输入并提示；成功后清空输入，刷新历史第一页并展示新任务。提交不自动重试；响应丢失时用户可先刷新历史确认。
- 当前页出现 Processing 任务时每 5 秒串行刷新当前页列表及已展开的处理中明细；页面内没有 Processing 任务或组件卸载时停止。列表读取与提交互斥，提交结束后统一刷新目标页并恢复轮询；明细每次展开重新读取。轮询失败停止并给出手动刷新，完成后刷新用量；沿用当前 CSV/ZIP 下载能力。
- Online 落地页的开始采集 CTA 接入同一个 Dashboard 入口；导航 Online 仍指向产品介绍页。首页和落地页相关占位、批量承诺与导出文案随实际能力同步，完整任务仍为 CSV/ZIP。

## 后端边界

### 匿名首屏接口

公开 `POST /api/client/maps-online/preview`，请求仅含 `keyword`：去首尾空白后 1–500 字符，单行、单关键词；不接受页数、字段模式、联系方式或 Provider 选择。额外字段按项目 Pydantic 默认规则忽略，但不参与执行。

采集链路：公开入口 → 当前引擎配置的 HTTP 代理与并发参数 → 现有唯一 HTTP Provider → NID 初始化 → regular 搜索 offset=0 → 解析首屏 → 对外字段白名单。

- `gmap/http.py` 的 `preview_places` 提供基础首屏；`_regular_page` 持有共用单页请求步骤，完整搜索继续复用，不在 API 层直接访问 RPC 客户端，也不复制 URL 模板或解析器。
- 仅做一个逻辑搜索页，最多使用其前 20 条有效结果；同页按 fid 保序去重。NID 初始化仍需额外请求，底层既有代理重试继续存在，不能把“一页”表述成“仅一次 HTTP 请求”。
- 复用 `regular_search_url`、`parse_regular_response` 及已有 DTO 字段转换；跳过 browser 搜索、L2 详情、官网补全、CSV 序列化、对象存储和任务服务。首屏固定走 HTTP，不随正式任务的 gosom 选择切换。
- 入口用标准库超时给整个预览采集预算 15 秒，含初始化、排队、NID、既有重试和解析；到期返回可重试错误。该预算是等待上限，不承诺所有网络条件下都能成功。
- 成功数据为 `count`（本次首屏有效条数）与 `rows`（最多 3 行，不足 3 行按实际返回）。每行仅含 `name`、`address`、`category`、`rating`、`review_count`、`phone`；名称为字符串，其余允许空值，分类用现有映射得到的分类文本。不返回原始 RPC、fid、网站、联系方式补全或剩余行。
- 统一响应信封、业务错误与 i18n；匿名响应设置 `Cache-Control: no-store`。不写任务或结果文件、不扣 Online/API/插件月度额度；复用现有请求日志，日志不保存商家结果正文。
- 复用 `RedisFixedLimiter`，独立子前缀 `maps_online_preview`，按 `get_client_ip` 每 IP 每分钟 3 次，在出网前检查，超限使用现有频繁请求业务码。该计数仅为限流，不是任务记录；复用工具的 Redis 故障放行语义。IP 不可获取时拒绝预览，不创建匿名账号或新 token。

已接受的限制：固定窗口边界可突发，共享 IP 共用预算；现有 IP 工具信任代理头，公网发布需核对可信入口覆盖这些头；Redis 故障放行不提供硬费用上限。不增加验证码、全局费用控制或独立并发池。

### Dashboard 创建约束

登录保护的 `GET /api/client/maps-online/options`，返回 `keyword_limit`、`contacts_allowed` 与 `usage`（复用 `usage_service.usage_payload` 的 `used/total/period/exhausted` 合同）。读取既有订阅配置、`KEYWORD_LIMITS` 和 `online_usage_service`，不扩展通用账号摘要，不在前端维护套餐映射。

创建入口和 options 在本模块复用同一份权益读取逻辑，创建请求仍重新校验实时上限、有效订阅和用量。options 不初始化采集引擎、不探测代理或对象存储。配置或用量不可用时按现有错误合同返回，前端不放行提交。

现有 `POST /api/client/maps-online/tasks`、历史、详情和下载 URL 与业务行为保持。router 前缀为 `/maps-online`，任务路由显式带 `/tasks`。

## 前端归属

- 首页的状态和结果渲染放在一个 Vue 采集组件，由 `HomePage.astro` 装配；删除被替代的占位计数脚本和操作区样式，静态营销段保留。已有 Astro/Vue 集成与 `client:load` 的核实依据见 [Dashboard 技术合同](../015.工具与增长/tech-用户Dashboard.md#集成依据)，此次不变更框架版本或引入依赖。
- `DashboardApp.vue` 继续负责会话和工作区外壳；现有 `HistoryView.vue` 承载创建及历史，必要时仅将表单拆为实际有职责的局部组件，不建立新状态管理层。
- `scripts/dashboard/api.ts` 继续封装登录业务请求并处理 401；匿名预览使用已有 `homepage/api.ts` 请求信封与请求头边界。站级登录通过现有 `open({ redirectTo: '/dashboard/' })` 进入 Dashboard；当前站点仅启用 en-US 且无路径前缀，现有回跳白名单已覆盖，不新增会话或回跳存储机制。
- 响应字段在现有解析边界收窄，禁止新增 `any`、宽泛 `unknown` 或用断言代替校验。所有用户文字走现有 i18n，服务端地点名称等原始数据用文本插值渲染。
- 视觉使用 [亮色](../../references/specs/design.md) 与 [暗色](../../references/specs/design.dark.md) token；截图仅参考信息层次。表格窄屏可横向滚动，表单标签、加载/结果提示、错误与键盘焦点可访问。

## 验证与限制

验收结果归 [实施清单](plans/004.首页预览与Dashboard创建.md)。预览字段仅使用首屏已有值，字段覆盖随 Google 结果而变化；15 秒预算的长期成功率与可信代理头部署仍需发布环境核对。
