# 官网联系方式采集

本文定义可移植采集库与本项目补全编排的边界。Online 权益、任务字段与执行时机归 [Online 任务与结果](tech-Online任务与结果.md)；实施状态归 [003 实施清单](plans/003.可选联系方式与独立采集库.md)。

## 1. 职责

- `MapsOnlineTaskService` 持有任务事实、恢复与完成流程；有效采集选项在创建入口确定并保存。
- `MapsOnlineProvider.execute` 在单关键词 Maps 结果返回后调用补全，得到结果后生成最终 CSV、上传 OSS。item 此时仍在执行；只有文件交付或错误收口后才报告完成。
- 现有 `app/provider/maps_enrich.py` 负责批内域名去重、Redis 缓存、进程共享官网并发名额、代理选择、业务输入输出适配，以及单站失败转空结果。不同 item 的 Maps 与官网请求可交错执行。
- 独立 Python 包 `contact_scraper` 负责单个网站的 HTTP 抓取、安全校验与联系方式解析，源码入口为 `backend/src/contact_scraper/__init__.py:scrape_contacts`，与 `app/` 平级。

## 2. 独立库合同

公开异步操作名为 `scrape_contacts`，一次调用处理一个目标网站。

| 输入 | 合同 |
| --- | --- |
| `target` | 裸域名或完整 HTTP(S) URL；裸域名补 HTTPS，完整 URL 保留路径 |
| `proxy` | 必须显式提供；代理 URL 指定出口，None 明确表示直连 |
| `timeout` | 单次网站抓取的总时限，默认 12 秒，含 DNS、安全校验及重定向；业务队列等待不计入，不叠加独立 curl 超时 |

返回库自身定义的 `ContactResult`，包含 `emails` 列表与 `medias` 平台到链接的映射。数据类型使用标准库，不暴露项目 schema、账号或任务信息。

- 获取目标页面 HTML，一次解析同时提取 Email 和已有六类社媒外链；不访问社媒平台本身，不做站内深爬。沿用现有解析、去重和误报过滤行为。
- 成功访问但未发现联系方式，正常返回空结果；安全拒绝、网络失败、非成功响应或抓取超时以脱敏异常返回，调用方决定如何处理。取消必须继续向上传播，不转成普通空结果。
- 同一次调用的请求和重定向使用同一代理；不读取代理环境变量，不在失败后自动转直连或更换代理。
- 同一次调用复用一个 HTTP 会话；同源重定向尽量复用连接，跨主机或协议变更允许新建连接。Email 与社媒从同一份 HTML 提取，不分别请求。
- 库通过标准 `logging` 输出逐跳安全校验、连接 ID、新建连接数、DNS、TCP、隧道/TLS、首字节及正文等待耗时；只记录主机名与请求标识。宿主应用负责接入日志输出，库不配置处理器。
- URL 协议与凭证限制、DNS 公网地址判定、逐跳重定向检查、HTML 大小上限和有限重定向规则随采集实现迁入库。库不提供关闭安全校验的快捷分支。
- 除标准库与后端已有的 `curl_cffi`，仅导入同级中立 `traffic_scope` 包读取可选、不解析的 `scope_id` 与计数；默认无 scope，不依赖 Online 业务。禁止导入 `app`、FastAPI、Pydantic、Redis、MySQL、项目配置或日志初始化。异常由业务处理边界记录，库不初始化项目日志。

移植需一并复制 `contact_scraper` 与标准库中立包 `traffic_scope`，并安装匹配的 `curl_cffi`。本仓 wheel 必须包含两个顶层包；不要求另建采集服务、发布 PyPI 或增加依赖注入接口。

## 3. 本项目编排

补全入口先逐条识别官网 URL：命中现有六类社媒时直接返回 `medias`，`emails` 为空，不访问社媒网站、不读写域名缓存。识别与 HTML 外链解析共用 `contact_scraper.classify_social_url` 的平台主机匹配及分享、登录等路径排除规则；只接受无凭证、端口合法的 HTTP(S) URL，输出沿用 HTTPS、去查询串与片段的规范化。此纯解析分支不做 DNS；实际抓取仍执行完整 SSRF 校验。不同商家的同平台主页分别返回，不按平台域名合并。

Maps 与 Bing 插件按官网 URL 保留不同目标并按请求位置对应的目标写回；Maps 同时保留 domain 归属。相同目标可复用请求，普通官网的域名去重归后端处理。Online 保持逐条传入、按位置合并 CSV。

未命中直接归类的目标复用现有域名缓存及批内去重；缓存命中直接返回，成功解析的空结果也可缓存，失败不缓存。不同批次或任务同时首次请求相同域名仍可能重复抓取，不为此新增锁或跨任务协调。

官网并发与 Google 出站并发独立，采用每进程共享的 50 路信号量，不叠加每 item 限流器。编排层取得官网并发名额后才调用库，使库的抓取时限不包含排队。库不管理代理池、批处理、缓存或用户权益。

Online 官网补全先显式直连；单站总预算 12 秒，直连最多使用前 8 秒。遇到网络故障、单次抓取超时或 HTTP 401/403/407/429 时，在剩余单站及批预算内使用配置代理重试一次。其他 HTTP 错误、输入或安全校验失败不触发代理重试；外部取消继续传播。代理列表沿用 service 已读取并经 Online Provider 传入的引擎配置，Provider 不反向读取配置 service。没有可用代理时仍可直连，需回退而无代理时按单站补全失败处理。出口切换由补全编排层负责，采集库单次调用保持显式固定出口；Google Maps 采集出站策略不变。

插件已有补全入口复用同一个库，显式指定直连；不新增插件对引擎配置的依赖，不在本轮变更插件权限。可移植性不要求所有调用方采用同一出口或业务策略。

插件保留调用方的 25 秒批量响应期限及 50 条外部请求上限。Online 以基础商家结果为交付主体，邮箱和社媒尽力补全，不保证获得联系方式。每个 item 整体调用一次补全，不做 50 条切片；补全失败或达到采集期限时保留基础结果及已完成的补全，继续生成并上传 CSV。采集与文件交付的期限边界归 [Online 任务与结果](tech-Online任务与结果.md)。单站总时限从获得并发名额后开始；进程关闭等外部取消继续传播。补全编排通过剩余批预算回收未完成站点，逐站处理异常并保留已完成结果；预算已耗尽时不启动新抓取，仍保留纯解析的社媒归类。批内超时或异常标记为内部 partial warning；整个补全调用异常由 Online Provider 记录并继续基础结果交付。

## 4. 外部边界

- `curl_cffi` 版本使用 `backend/uv.lock`；迁移复用现有 AsyncSession、显式代理、手动重定向和流式读取能力。[官方文档](https://curl-cffi.readthedocs.io/en/latest/)
- Fake-IP 返回的非公网地址仍会被前置安全校验拒绝；显式代理不自动解决该问题。真实采集验收需要返回实际公网地址的 DNS 环境，不新增自有 DNS 服务。[Mihomo DNS 文档](https://wiki.metacubex.one/config/dns/)
- 保留现有 DNS 重绑定防护边界：本地解析检查不等于连接地址固定，也不证明远端代理解析与本地完全一致；本轮不宣称实现连接级 pinning。[OWASP SSRF 指引](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
