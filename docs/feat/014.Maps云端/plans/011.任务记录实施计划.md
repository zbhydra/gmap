# 任务记录实施计划

用户已确认分开存储、两个独立列表。领域合同归 [采集记录](../tech-采集记录.md)，管理界面与查询接口归 [后台任务记录](../../008.管理后台/tech-任务记录.md)。2026-10-28 三步均已实施并通过审查，验收证据与遗留项见 §6。

## 1. 执行范围

- Online 沿用现有 Job/Run；API 与 MCP 共用独立调用记录分表 `export_api_jobs_00` ~ `export_api_jobs_09`，以数字来源区分。
- 管理后台一个“任务记录”菜单，分别提供 Online 任务、API/MCP 调用记录两个标签页；各自筛选、分页和详情。
- 用户 Dashboard 保持现有 Online 历史；请求参数与结果摘要仅在管理后台查看。

## 2. 实施顺序

1. 后端调用记录：增加调用记录 Model、存储 schema 与 service；REST/MCP 在现有共享业务入口指定来源，接入受理、终态与原 usage 同事务结算。只同步新表结构。
2. 后台查询：新增两组只读列表与详情；Online 直接读取既有 Job/Run，调用记录读取新表。复用原 admin 认证与用户信息弹窗。
3. Admin 页面：增加菜单、路由、两个标签页和独立查询状态，接入中英文文案；不提供跨两类记录的混合分页。

Online 的模型、Runtime、用户端历史、下载及原有用量事务不需要为新增调用记录改变；不回填类型、不放宽既有必填列、不搬迁数据。后台查询需分别处理 Online 与 API/MCP 两组分表的全局分页。

## 3. 最少验收

- 覆盖 REST/MCP 来源与搜索、评论、照片操作归类；已有准入拒绝不写记录。
- 已受理调用可见；有效零结果、局部结果、成功和普通失败正确收口；失败不误扣量，记录和成功用量同事务提交。
- 通过实现入口与序列化调用链确认只保存校验后的业务参数与摘要，不保存凭证或完整返回结果；不为这条模型投影另增专项测试。
- 两个后台列表各自分页、筛选、计数与详情一致，管理员认证生效，用户 ID 可打开原用户信息弹窗。
- 复用现有 Online 行为证据；不为未修改的模型、Runtime 或用户历史新增重复测试。

后端实施需完成受影响文件的 black、ruff、mypy、新表结构同步、构建与启动；Admin 需构建、启动及一条关键界面验证。仅跑证明本次改动的最少定向测试。规划阶段只检查文档。

## 4. 边界与证据

- 既有 API/MCP 用量流水不含请求参数或来源，不补造历史调用记录。
- API/MCP 取消、进程硬退出、失败状态写入失败或结算回滚可能遗留处理中记录；接受局部失败，不增加取消落库、恢复、重采或补偿。
- Herdr 中 Opus 5.5 指出分开存储可减少 Online 改造；用户进一步确认两个独立列表，省去跨类型合并查询。此前针对合并方案的审查通过不代表本方案已经实施。
- 线上结构、存量和性能未核实；文档批准不等于运行验收。

## 6. 实施与验收记录

2026-10-28 三步全部实施。U1 后端经 opus 与 codex 独立审查，均无阻塞。U2 Admin 首轮 codex 提出两项阻塞：切回标签页需重新读取，已返修；时间筛选时区经架构师裁定为非阻塞。两单元均已审查通过，文档已按实现同步。

- 后端调用记录：结构同步只新建 `export_api_jobs_00` ~ `export_api_jobs_09`，同步后复核一致；受影响文件 black / ruff / mypy 通过。定向 real 测试 7 条通过，无 skip。真实 Collector 与 Google 下，REST/MCP 来源与操作归类正确，用量 `request_id` 与记录一一对应；替换 Collector 出口后，局部成功、空页成功与失败收口正确，只对有效结果扣量；鉴权、参数与额度拒绝均不写记录。
- 后台查询：real 测试覆盖四个接口的未认证 401、两类列表跨分表分页、各项筛选、计数、无效时间范围、详情与 `NOT_FOUND`；独立端口启动后健康检查通过。
- Admin 页面：`pnpm build`（含 vue-tsc）与 UI token lint 通过。Chromium 目标 e2e 使用 mock 接口，覆盖菜单入口、两个标签页的筛选与详情、调用记录翻页、进入标签页读取并保留各自条件、用户信息弹窗及无写操作按钮。dev server 直连独立后端实例，用 service 造数完成真实界面验证，数据已清理。

未执行全量 real 测试。Firefox e2e 因本机缺少对应浏览器版本而启动失败。Chromium 既有回归 29 条中 28 条通过，唯一失败是 TG 路由删除后遗留的 `login.spec.ts`「未登录访问 /tg-clients」旧用例。

遗留项：

- 时间筛选按浏览器本地时区解析日期选择器输入，与 Orders / Users 一致；列表固定按 UTC+8 展示，非 UTC+8 浏览器按展示时间筛选会有偏移。架构师已裁定为非阻塞。
- 发布须先在目标库运行 `sync_database_schema` 建表，再发布代码；否则通过准入的 API/MCP 调用都会在建记录时报错。
- 后台筛选不建额外索引。不带用户 ID 或编号时，列表与计数扫描十张分表，深分页随偏移量变慢；线上数据量与性能未核实。
- §4 已接受的遗留处理中记录不做恢复。MCP 来源的真实证据只来自依赖 Collector 与 Google 的测试，环境缺失时该测试整体 skip。
