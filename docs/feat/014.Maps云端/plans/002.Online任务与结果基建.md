## U1 · 对象存储运行时

### 改动

- 建立模块级 `object_storage_service`，按任务快照的 Provider、endpoint、bucket 和后台当前凭据执行写入、签名与下载；进入 SDK 前校验任务对应凭据块，官方 SDK 的同步 I/O 全部放入 `asyncio.to_thread`。
- 固定 `{feature}/{Ymd}/...` key 构建；Online key 使用技术合同规定的 item attempt CSV 路径。
- CSV 以 Provider 29 列为基础，按调研 §12.30 追加 Email 与 6 个社媒列；只复用 013 的 RFC 4180、CRLF 与 BOM 序列化规则，不复用插件列序。

### 验收

- R2 与 AliOSS 分别完成一份真实最小 CSV 的写入、下载和短期签名冒烟；无凭据时按 real 测试规范 skip。
- 日志和异常不出现 access key、secret 或签名 URL query。
- 测试 bucket 禁止匿名 GET 和 public listing。
- 真实零结果写表头 CSV；最终存储失败由调用方按错误 item 收口。

## U2 · 父任务与 20 个 item 分表

### 改动

- 增加父任务 Model/service；item 模型模块从一个抽象模型生成 20 个物理模型，由 `models/__init__.py` 导入并注册到 `Base.metadata`。
- item 模型模块暴露唯一的 `task_id % 20` 路由函数，service 直接使用；创建任务时父表和全部 item 使用同一事务。
- 实现用户任务列表、任务详情、worker 父任务扫描和 item 首次完成事务。
- 按实际查询完成索引三件套审查，并在 `spec-mysql.md` 登记固定分表 service 例外。
- `config.yaml.example` 模板固定使用 `redis.db: 0` 和 `redis.key_prefix: gmapsexporter`，与 `RedisSettings` 默认值保持一致；同步 `.env.example` 与部署 README。

### 验收

- `sync_database_schema --yes` 创建 1 张父表与 20 张 item 表，字段、注释、UK/INDEX 与技术合同一致。
- 同一 task 的创建、读取和完成只访问一个分表。
- 重复完成同一 item 时，父任务进度和记录数只增加一次。
- 不同 `APP_NAME` 的业务节点使用相同 `gmapsexporter` 前缀；不同环境连接不同 Redis 实例。

## U3 · Worker 与终态

### 改动

- `main.py` 在 business lifespan 中创建 Online worker 协程。worker 用 `asyncio.TaskGroup` 持有 item 协程，每秒扫描当前 `APP_NAME` 的未完成任务并补满空闲名额；关闭数据库前取消 worker 及 item，等待文件锁释放。
- 使用 item 级 `fcntl.flock` 协调同机多进程。`gmap_engine.concurrency` 同时作为每进程活跃 item 和 HTTP Provider 出站请求的上限。
- HTTP item 直接执行；gosom item 分两次短操作持久化 handle 并查询。
- gosom 查询使用固定 5 秒冷却；`extra=true` 时复用 `maps_enrich_service` 按 50 条分批补全并合并结果。
- item 执行前以父任务 `created_at + 24h` 判断超时；超时、Provider 最终失败和对象存储最终失败都使用同一首次完成事务按 0 条收口。
- 全部 item 收口后按实际记录数调用 `online_usage_service`，成功后完成父任务。

### 验收

- HTTP 成功与最终错误都能结束任务；partial 保留已有 CSV。
- gosom handle 落库后重启可以继续查询；上游排队不占用本地执行槽等待。
- 进程中断后文件锁释放，未完成 item 能被新进程执行。
- 实际用量按 `task_no` 幂等；当前任务可以超过剩余额度，后续 exhausted 用户不能创建任务。

## U4 · Client API 与下载

### 改动

- 增加创建、列表和详情接口，并在创建入口完成关键词固定档位上限、当前额度、对象配置以及 gosom `gl/ll` 边界校验。
- 增加单 item CSV 签名下载和整任务 ZIP 下载。
- ZIP 顺序下载 item 文件到独立临时目录，只把同步压缩放入线程；响应完成后删除临时目录。
- 所有下载入口先校验当前用户的任务归属，内部错误与对象 key 不进入响应。

### 验收

- Free 与付费用户的关键词数量按当前权益限制；提交不预扣额度。
- 任务刷新后进度和可下载文件列表来自 MySQL。
- 单 item 下载文件名为 `{item_id}_{关键字}.csv`，关键字清理后为空时使用 `{item_id}.csv`；ZIP 包含全部可用 item CSV。
- 跨用户任务或 item 不可读取、签名或打包；无文件任务不能下载 ZIP。
