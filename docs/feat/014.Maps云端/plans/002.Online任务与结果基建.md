# 002 · Online 任务与结果基建

> 状态：待实施。稳定合同见 `@../tech-Online任务与结果.md`；Provider 见 `@../tech-引擎Provider层.md`；对象存储后台配置已由 `@../../008.管理后台/tech-系统设置.md` 落地。

## 目标

交付 Online Scraper 的后端闭环：创建关键词任务、多进程执行、20 个 item 分表、R2 / AliOSS CSV、重启恢复、实际用量计量、单文件与整任务 ZIP 下载。

## 非目标

- 不实现 Online 前端任务台。
- 不实现 Search / Reviews API 或 Photos。
- 不实现任务删除、取消、用户重试、自动对象清理或跨 R2 account 迁移。
- 执行协调固定使用 MySQL 完成事实与本机 item 文件锁。

## 依赖

1. Admin `object_storage` 双配置已经可读写。
2. HTTP Search 与 gosom submit/get Provider 已完成。
3. 开始对象存储代码前，按仓库规则确认并加入 R2 与 AliOSS 官方 Python SDK；不手写签名协议。
4. 同一 `APP_NAME` 只运行在一台共享本地锁目录的机器上。
5. 全部环境的 Redis key prefix 固定为 `gmapsexporter`；开发、测试和生产使用不同 Redis DB 或实例。

## U1 · 对象存储运行时

### 改动

- 建立模块级 `object_storage_service`，按任务快照的 Provider、endpoint、bucket 和后台当前凭据执行写入、签名与下载；进入 SDK 前校验任务对应凭据块，官方 SDK 的同步 I/O 全部放入 `asyncio.to_thread`。
- 固定 `{feature}/{Ymd}/...` key 构建；Online key 使用技术合同规定的 item attempt CSV 路径。
- CSV 以 Provider 29 列为基础，按调研 §12.30 追加 Email 与 6 个社媒列；只复用 013 的 RFC 4180、CRLF 与 BOM 序列化规则，不复用插件列序。

### 验收

- R2 与 AliOSS 分别完成一份真实最小 CSV 的写入、下载和短期签名冒烟；无凭据时按 real 测试规范 skip。
- 日志和异常不出现 access key、secret 或签名 URL query。
- 测试 bucket 禁止匿名 GET 和 public listing。
- 真实零结果写表头 CSV；最终存储失败由调用方按错误 item 收口。

## U2 · 父任务与 20 个 item 分表

### 改动

- 增加父任务 Model/service，并把同构 item 表一次性注册到 `Base.metadata`。
- 只通过 `task_id % 20` 路由 item；创建任务时父表和全部 item 使用同一事务。
- 实现用户任务列表、任务详情、worker 父任务扫描和 item 首次完成事务。
- 按实际查询完成索引三件套审查，并在 `spec-mysql.md` 登记固定分表 service 例外。
- 保留 `redis.key_prefix` 配置字段，但把 `config.yaml.example` 的值与 `RedisSettings` 默认值固定为 `gmapsexporter`，不再从 `APP_NAME` 渲染；部署环境通过不同 Redis DB 或实例隔离。
- `deploy/.env.example` 增加 `REDIS_DB`，配置模板据此生成 `redis.db`；同步修改部署 README 与 `spec-redis.md`。切换前缀时不读取或迁移旧 key，已有用户重新登录，匿名月度用量重新计数；`APP_NAME` 只承担任务实例归属、supervisor program 与 Nginx vhost 命名。

### 验收

- `sync_database_schema --yes` 创建 1 张父表与 20 张 item 表，字段、注释、UK/INDEX 与技术合同一致。
- 同一 task 的创建、读取和完成只访问一个分表。
- 重复完成同一 item 时，父任务进度和记录数只增加一次。
- 不同 `APP_NAME` 的业务节点使用相同 `gmapsexporter` 前缀；不同环境使用不同 Redis DB 或实例。

U1 与 U2 可以并行；U3 同时依赖两者。

## U3 · Worker 与终态

### 改动

- 在 business 进程启动 Online worker，扫描当前 `APP_NAME` 的未完成任务。
- 使用 item 级 `fcntl.flock` 协调同机多进程，并以现有引擎并发值限制每进程活跃 item。
- HTTP item 直接执行；gosom item 分两次短操作持久化 handle 并查询。
- gosom 查询使用固定 5 秒冷却；`extra=true` 时复用 `maps_enrich_service` 按 50 条分批补全并合并结果。
- Provider、对象存储和任务期限的最终错误统一按 0 条内部错误收口。
- 全部 item 收口后按实际记录数调用 `online_usage_service`，成功后完成父任务。

### 验收

- HTTP 成功与最终错误都能结束任务；partial 保留已有 CSV。
- gosom handle 落库后重启可以继续查询；上游排队不占用本地执行槽等待。
- 进程中断后文件锁释放，未完成 item 能被新进程执行。
- 实际用量按 `task_no` 幂等；当前任务可以超过剩余额度，后续 exhausted 用户不能创建任务。

## U4 · Client API 与下载

### 改动

- 增加创建、列表和详情接口，并在创建入口完成关键词固定档位上限、当前额度、对象配置以及 gosom `gl/ll` 边界校验。
- 增加单 item CSV 签名下载和整任务 ZIP 下载。
- ZIP 顺序下载 item 文件到独立临时目录，只把同步压缩放入线程；响应完成后删除临时目录。
- 所有下载入口先校验当前用户的任务归属，内部错误与对象 key 不进入响应。

### 验收

- Free 与付费用户的关键词数量按当前权益限制；提交不预扣额度。
- 任务刷新后进度和可下载文件列表来自 MySQL。
- 单 item 下载文件名为 `{item_id}_{关键字}.csv`；ZIP 包含全部可用 item CSV。
- 跨用户任务或 item 不可读取、签名或打包；无文件任务不能下载 ZIP。

## U5 · 最少验证与交付

- 每项能力默认只保留一个最短主流程；只有 CAS、跨用户下载和崩溃恢复等高风险非平凡分支单独覆盖，不为 20 张同构表复制测试。
- 不测试旧数据、已删除方案、标准库或 SDK 自身行为，不为构造失败分支增加依赖注入或内部 mock。
- 修改 Model 后运行 schema sync；随后只运行本计划相关 real 测试、black、ruff、mypy 和 business 启动。
- 使用真实测试 bucket 做 R2 / AliOSS 冒烟；测试对象放在独立日期/测试前缀并在测试结束清理。
- 静态检索确认活文档、接口、数据模型和实现符合 `@../tech-Online任务与结果.md`。
