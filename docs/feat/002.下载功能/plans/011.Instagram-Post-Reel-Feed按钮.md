# 011 · Instagram Post、Reel 与 Feed 按钮

## 1. 目标

在 Home Feed、Post 详情、Reel 详情和 Reels Feed 上建立归属明确的按钮扫描与渲染。

每个 Post/Reel 无论只有一个还是多个主媒体，都显示两个入口：

- 操作区按钮下载该内容全部主媒体。
- 媒体层按钮下载当前显示项。

Reel 主入口下载视频；操作菜单额外提供封面下载。封面不进入“全部”，也不进入 Popup。

## 2. 非目标

- 不处理 Profile、Explore、Search、Hashtag Grid。
- 不处理 Story/Highlight。
- 不接入 Popup。
- 不修改共享额度与下载函数。
- 不从 DOM 媒体 URL 构造下载资源。
- 不增加依赖注入。

## 3. 依赖

- Plan 009：PageContext 与当前路由资源 Map。
- Plan 010：媒体 parser 与按需 resolver。

## 4. 改动范围

- 新增 `extension/src/sites/instagram/content/scanner.ts`，只识别 Post/Reel 容器、canonical shortcode、按钮锚点和当前轮播序号。
- 重写 `extension/src/sites/instagram/content/buttons.ts`，负责创建、移动、更新和移除按钮。
- 修改 Instagram content 入口，重扫后按当前 DOM 锚点更新按钮。
- Feed 只扫描拥有 canonical permalink 的帖子容器；详情页只扫描与当前路由 shortcode 相同的 article/dialog。
- Reels Feed 只绑定当前可见 Reel，忽略相邻预加载内容。
- 按钮可以显示当前调用的瞬时 loading，但 loading 不禁用点击。调用结束后恢复默认显示；并发调用的显示互相覆盖属于允许行为。
- 固定按钮尺寸，所有用户文案使用 i18n。

## 5. 执行步骤

1. 完成 Feed、详情、Reels 和推荐内容负向 DOM fixture。
2. 将 scanner 限制为输出 shortcode、序号、按钮锚点和页面顺序。
3. 实现操作区与媒体层两个入口。
4. 接入 Carousel 当前项切换。
5. 接入 Reel 视频主入口和封面菜单。
6. 删除整页 `main` 扫描、`resources[0]` 和 DOM URL 下载路径。

## 6. 验收标准

- [x] 单图、单视频、Carousel 和 Reel 都同时显示“全部”与“当前项”。
- [x] Carousel 切换后媒体层按钮下载当前序号，操作区按钮仍下载整帖。
- [x] Reel 主入口只下载 MP4；封面只从菜单下载并单独计作一个资源。
- [x] 推荐内容不会被归入详情页当前 shortcode。
- [x] Instagram 替换 DOM 容器后按钮可以重新出现，页面中没有重复按钮。
- [x] 重复点击不会被前端下载中判断阻止。
- [x] 按钮尺寸稳定、文案已本地化。
- [x] Telegram、X 与共享下载代码未改变。

## 8. 失败与回退

- 无法证明 DOM 内容归属时不注入按钮，并打印包含页面类型和锚点信息的错误。
- Instagram 锚点变化时修改 scanner，不扩大到整页猜测。
- 本阶段可回退按钮接线；回退期间允许按钮缺失，不允许使用缩略图作为替代下载源。
