# 006 · Instagram Story 网站解析执行计划

## 1. 目标

让 website 输入框支持公开 Instagram Story 链接：

- `/stories/{username}/` 解析当前公开可见的 active story 列表。
- `/stories/{username}/{story_id}/` 按 story id 精确解析单条 Story。
- 仍走现有 V2 parse/download 与 `direct` 下载模式。

- `docs/feat/002.下载功能/tech-站点适配.md`

## 3. 改动范围

- `backend/src/app/provider/media/instagram_media.py`
  - Instagram canonical 支持 `/stories/{username}` 与可选 `story_id`。
  - Story 分支复用 Meta SSR HTML 抓取、Web Relay fallback 与 Meta CDN URL 探测。
  - Story 图片/视频资源返回 `direct`，不暴露 CDN URL。
  - Story parse/format 缓存 TTL 使用 5 分钟，避免长时间保留过期资源。
- `backend/tests/test_server/provider/test_instagram_media.py`
  - 覆盖 URL 规范化、路径识别、Story SSR 提取、parse 响应与短 TTL。
- `backend/tests/integration/real/api/client/test_instagram_media_api_real.py`
  - 增加可选真实 Story 解析用例，仍由 `RUN_REAL_INSTAGRAM_TESTS=1` 控制。
- `docs/feat/002.下载功能/tech-站点适配.md`
  - 同步 Instagram Story 支持边界。

不新增依赖、不新增数据库表、不新增前端组件。

## 4. 验收标准

- `https://www.instagram.com/stories/rabbiilovey/` 不再因 unsupported path 失败。
- 公开 Story 图片/视频解析结果包含 `resource_token`、`download_mode=direct`，且不包含 `download_url`。
- 私密、登录墙、已过期、Highlights 仍按资源不可访问或解析失败处理。
- Story 直链刷新仍复用现有 `download-pre-v2 -> download-v2` 机制。

## 6. 风险与回滚

风险：

- Instagram 未登录 SSR/Relay 对 Story 的公开程度不稳定；若平台只返回登录墙或空 `reels`，失败时返回用户可重试的解析失败/资源不可访问。
- `/stories/{username}/` 会返回当前 active story，内容随时间变化；因此缓存只保留 5 分钟。

回滚：

- 移除 Instagram Provider 的 `story` 分支和 canonical 支持即可恢复原行为。
