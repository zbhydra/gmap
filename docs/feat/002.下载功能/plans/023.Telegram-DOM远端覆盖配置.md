# 023 · Telegram DOM 远端覆盖配置

## 1. 目标

让支持该能力的 Telegram 扩展在每个页面打开时读取一次全局 DOM 稀疏覆盖，并与当前扩展包内完整默认值浅合并。Telegram 仅改变现有 DOM 定位时，运营可更新后端对象并让用户刷新页面生效，不需要为每次 selector 变化立即发布扩展。

## 2. 依赖

- 以 `@../tech-扩展端TG扫描.md` §4.7 的扁平键、初始化顺序和宽松合并合同为唯一技术基线。
- 复用已有 `system_data` 表和 `system_data_service`；不新增表、Redis、锁或依赖注入。
- Admin UI 由 `@../../008.管理后台/plans/005.Telegram-DOM配置编辑.md` 承接；本 plan 先提供公共读取与 Admin 读写接口。
- 实施时保护当前工作区已有的 Telegram A Story 调用链和文档，不回退相关改动。

## 实施边界

- §4.1 后端存储与接口，以及 Admin plan 005 已在基线提交完成。
- §4.2 扩展配置加载、§4.3 活动 DOM 消费方统一、§4.4 CSS 与侧栏 markup 解耦已在插件分支完成；该阶段未修改后端或 Admin。

## 3. 完整范围

### 3.1 包含

- 后端公共读取接口与 Admin 读取/覆盖保存接口。
- 扩展完整默认 DOM 配置、单次远端加载、宽松浅合并和模块级唯一运行时配置。
- A 主消息、A 侧栏、A Story、K 主消息、共享 URL/大小读取和主题判断统一消费同一个运行时配置。
- Telegram content 初始化等待 Background RPC 配置请求完成或失败后，再启动扫描和观察器；后端 HTTP 请求只从 Background 发起。
- 主消息与侧栏样式改用插件自有 host/theme class；侧栏批量按钮改用插件自有 markup/style。
- 后端与 Admin 验证、扩展单元/集成测试、构建与文档收口。

### 3.2 不包含

- 不按扩展版本或 Telegram 版本存储、请求或响应配置，不上传客户端版本。
- 不做逐字段 schema、类型、字段完整性、未知字段或 selector 语法校验。
- 不做历史、回滚、恢复默认按钮、发布状态、审批、灰度、轮询、WebSocket、`chrome.storage` 持久缓存或自动重试。
- 不实现未来 AI 上游巡检或自动写配置。
- 不把 K 侧栏残留选择器加入配置；当前 K 侧栏没有可达下载资源。
- 不尝试用配置修复媒体身份语义、资源读取协议或下载算法变化。

## 4. 执行单元

### 4.1 后端存储与接口

修改：

- `backend/src/app/api/client/tg_client.py`
- `backend/src/app/api/admin/admin_system_settings.py`

实现责任：

- `GET /api/client/tg/dom-config` 无鉴权，按 `telegram_dom` 精确读取；记录不存在返回 `{}`。
- Admin GET 返回同一对象；Admin POST 只接受顶层对象并原样 upsert。
- 直接复用 `system_data_service.system_data_info()` 与 `set()`；不修改该 service，也不新建 Telegram 配置 service。
- 三个接口使用统一响应 envelope，但对象直接位于 `data`，不增加 `config` 包装层。
- 保存清理既有 `system_data` 进程缓存。
- 公共接口只能读取 `telegram_dom`，不能按任意 key 查询 `system_data`。

### 4.2 扩展配置加载

新增或修改：

- 新增 `extension/src/sites/telegram/content/dom/TelegramDomConfig.ts`，承载完整默认对象、模块级当前对象、浅合并和读取入口。
- 新增 `extension/src/core/api/telegram-dom/` 的请求类型与 API，端点登记到 `extension/src/core/api/config.ts`；content 通过既有 typed RPC 调用 Background，由 Background 发起 HTTP 请求。
- 修改 `extension/src/sites/telegram/content/index.ts`，把 injected ready 与 DOM 配置读取并行等待。
- 新增 `extension/tests/unit/telegram-dom-config.spec.ts` 和一条初始化集成测试；文件名可按实施时现有测试归属合并，禁止制造重复测试文件。

实现责任：

- 模块不接受构造参数或注入对象，不新增依赖注入；所有 Telegram DOM 消费方读取同一模块级配置。
- 每个 document 只有一个 GET；请求显式关闭 HTTP 5xx 重试，失败记录可定位错误并返回完整本地默认值。
- 合并不枚举允许键：缺少项保留默认，多余项保留，已存在同名项直接覆盖。
- 在配置结果确定前不启动主消息、Sidebar、Story 的 scanner/controller/observer。

### 4.3 活动 DOM 消费方统一

修改范围至少包括：

- `scanner/AVersionScanner.ts`
- `scanner/KVersionScanner.ts`
- `scanner/SidebarScanner.ts`
- `scanner/AStoryViewerScanner.ts`
- `scanner/URLExtractor.ts`
- `services/TelegramMessageListRoot.ts`
- `services/TelegramAAlbumMedia.ts`
- `services/TelegramMediaSurfaceLocator.ts`
- `services/ButtonPositioner.ts`
- `services/CheckboxManager.ts`
- `services/MediaDownloadButtonRenderer.ts`
- `services/constants.ts`
- `sidebar/SidebarButtonRenderer.ts`
- `story/AStoryDownloadController.ts`

统一规则：

- 删除这些活动链路中重复的 Telegram selector/class/attribute 字面量，由运行时配置提供。
- 直接子级定位仍保持直接子级约束，不因配置化改变现有 DOM 定位语义。
- ID 只配置语义前缀，客户端继续按既有数字身份规则解析，不从后端接收正则。
- 插件自己的 `tg-dl-*` class/attribute、DOM RPC 事件、URL 协议和下载参数不进入远端配置。
- `VersionDetector` 未使用配置与 `MediaViewerExtractor` 无生产调用链保持非活动，不为它们扩展配置。

### 4.4 CSS 与侧栏 markup 解耦

修改：

- `extension/src/sites/telegram/content/styles/buttons.css`
- `extension/src/sites/telegram/content/styles/sidebar-buttons.css`
- `extension/src/sites/telegram/content/services/MediaDownloadButtonRenderer.ts`
- `extension/src/sites/telegram/content/sidebar/SidebarButtonRenderer.ts`

验收责任：

- JS 给已定位宿主添加插件自有 host class，hover/focus 规则不再直接查询 `.media-inner`、`.attachment`、`.album-item.grouped-item`、`.search-super-item`、`.Media.scroll-item` 或 `.grid-item`。
- JS 按 `darkThemeSelector` 结果添加插件自有 theme class，CSS 不再查询 `.night`、`[data-theme='dark']` 或 `html.dark`。
- Sidebar 批量按钮不再生成 Telegram `ListItem*` / `title` class，外观和交互完全由插件自有 class 提供。
- DOM 重建时 host/theme class 与按钮一起重新同步，不增加持久状态。

## 5. 测试与验收

本次后端与 Admin 验收：

- 记录不存在时公共 GET 与 Admin GET 都返回 `{}`。
- Admin 保存一个包含缺少项、多余项和任意 JSON value 的稀疏对象后，Admin GET 与公共 GET 原样返回。
- 非 JSON 或非对象顶层值不保存。
- 后端不新增会改写真实 `system_data.telegram_dom` 的 real 测试；保存主流程由 Admin E2E 覆盖请求合同，后端执行格式、类型和启动检查。

扩展测试：

- `{}` 得到全部当前版本默认值；单键覆盖只改变该键；未知键保留且不会阻断已知键读取。
- 配置请求失败时使用默认值，且不发起第二次请求。
- injected ready 与配置请求并行；scanner/controller 只在两者完成后启动。
- A/K 主消息、A Sidebar、A Story 的代表性 override 能改变实际查询位置；默认配置下现有扫描测试继续通过。
- 主消息和侧栏按钮在插件自有 host/theme class 与 markup 下保持现有显示和交互。

## 7. 已知边界

- 管理员写错已知键会影响读取该键的客户端；本设计接受人工修正后刷新页面，不增加自动校验或回滚。
- 首次支持该能力之前发布的旧扩展不会请求后端，仍需用户升级。
- 管理员保存 `{}` 表示远端不覆盖，各扩展继续使用各自包内默认值；Admin 不提供“恢复默认”按钮。
