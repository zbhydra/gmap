# 014 · Instagram Popup 当前 Tab 直接查询

## 1. 目标

让 Popup 正式支持 Instagram，并在每次打开或点击刷新时直接查询当前 tab 的当前路由资源 Map。

Popup 不维护 Instagram 资源副本，不订阅页面事件。详情页和弹窗只列当前实体；集合页列当前路由中已经发现且解析成功的主媒体；Story/Highlight 只列当前项。封面、缩略图和解析失败项不展示。

## 2. 非目标

- 不在 Popup 中解析 Instagram 页面。
- 不保存跨刷新状态。
- 不展示 Reel 封面。
- 不增加 Instagram“清理缓存”按钮。
- 不修改 Telegram 的资源列表和清理缓存行为。
- 不增加依赖注入。

## 3. 依赖

- Plan 012：集合页与 Grid 资源。
- Plan 013：Story/Highlight 当前资源。

## 4. 改动范围

- 在 content register 增加或调整简单的 `getResources`，由目标 tab 的 content 直接返回当前 Map 内容。
- Popup 使用 Chrome transport 指定当前 `tabId`；content 不接受业务数据自报其他 tab。
- 修改 `extension/src/popup/stores/resourceStore.ts`，打开和刷新时替换整个 Instagram 列表。
- 资源按页面发现顺序排列，同一 Carousel 按媒体序号排列。
- Popup 单项、已选和全部下载只把资源 ID 列表发送给当前 tab。
- Instagram 隐藏清理缓存；Telegram 保持现有 UI 和逻辑。
- 查询失败时清空 loading，显示普通错误；用户可关闭后重开或再次刷新。

## 5. 执行步骤

1. 增加 Instagram 当前 tab 识别和 content 查询测试。
2. 接入 Popup 资源列表整体替换。
3. 接入页面顺序、Carousel 顺序和资源过滤。
4. 接入单项、选择项和全部下载 ID 请求。
5. 隐藏 Instagram 清理缓存入口，并复跑 Telegram Popup。

## 6. 验收标准

- [x] Instagram 打开 Popup 时保持当前 tab，不跳转 Telegram。
- [x] 每次打开或刷新都直接读取当前 tab 的当前 Map。
- [x] 另一个 Instagram tab 的资源不会进入当前 Popup。
- [x] Popup 只列可下载主媒体，不列封面、缩略图或失败项。
- [x] 集合页资源和 Carousel 项顺序正确。
- [x] Instagram 没有清理缓存按钮，Telegram 仍有。
- [x] 查询或 Popup 关闭期间发生页面变化允许显示旧一次结果，用户再次刷新即可纠正。
- [x] 不存在 Instagram 专用长期缓存或事件合并逻辑。

## 8. 失败与回退

- 当前 tab 没有 content script 时显示连接错误，不自动切换到其他站点。
- 页面恰好在查询期间变化时允许本次列表短暂过时，用户再次刷新即可。
- 本阶段可回退 Instagram Popup 接线；Telegram Popup 的现有逻辑必须保持可用。

## 9. 实施记录（2026-07-11）

- Popup store、tab 固定、Instagram 按 ID 回查与真实 content RPC E2E 通过。
- Popup/sidebar 受控 E2E 6/6 通过；Instagram 不提供 `clearBuffer` handler，也不显示清理入口。
