# 008 · 扩展平台开关与 Instagram 契约基线

## 1. 目标

建立一份纯数据平台注册表，让构建入口、Manifest、CSP、样式资源和 Popup 站点识别共同读取同一个开关。

发布状态固定为：

- Telegram、X、Instagram：启用。
- Threads、Vimeo：关闭且不进入生产构建产物。

同时固定 Instagram 的产品底线：只下载解析出的原媒体；Post/Reel 保留“全部”和“当前项”两个入口；Grid 可直接下载；Story/Highlight 只下载当前媒体；Reel 封面只在页面菜单出现；Instagram 数据不发送到本项目后端。

## 2. 非目标

- 不实现 Instagram 解析、按钮、Popup 或下载流程。
- 不验证或开启 Threads/Vimeo。
- 不增加运行时平台开关、第三方依赖或依赖注入。
- 不修改 Telegram 的产品行为。

## 3. 依赖

- 无前置计划。
- 实施前遵循 `docs/references/specs/spec-extension.md`。

## 4. 改动范围

- 新增 `extension/src/platforms/registry.ts`，声明平台 ID、是否发布、页面匹配、入口、权限、CSP 域名、样式和 Popup host。
- 修改 `extension/vite.config.ts`，只从注册表生成 Manifest。
- 修改 `extension/src/popup/utils/tabs.ts`，只从注册表判断当前站点；仅 Telegram 保留自动查找或打开页面的行为。
- 更新平台注册表、Popup tab 和构建产物测试。
- 注册表保持纯数据，不 import DOM、Chrome API 或站点运行时代码；`core` 不感知具体平台。

## 5. 执行步骤

1. 建立平台注册表并写正向、负向单测。
2. 让 Vite 的入口、权限、CSP 和样式资源从注册表生成。
3. 让 Popup host 判断读取同一注册表。
4. 构建生产包并直接检查 `dist/manifest.json`。
5. 复跑 Telegram Popup 导航测试。

## 6. 验收标准

- [x] 平台注册表是发布开关的唯一事实源。
- [x] 生产包只包含 Telegram、X、Instagram 的页面入口和权限。
- [x] Threads/Vimeo 的入口、host 权限、CSP 和样式资源均不在生产 Manifest。
- [x] Instagram/X 页面打开 Popup 时保持当前 tab。
- [x] Telegram 原有自动导航行为不变。
- [x] Instagram 产品底线已由单测或静态断言固定。
- [x] `pnpm check` 和 `pnpm build` 通过。

## 7. 验证命令

```bash
cd extension
pnpm test:unit:run -- tests/unit/platform-registry.spec.ts tests/unit/api-domain-config.spec.ts tests/unit/popup-tabs.spec.ts
pnpm check
pnpm build
pnpm exec playwright test tests/check-extension.spec.ts --project=extension-e2e-ui
```

## 8. 失败与回退

- 构建配置无法加载时，先检查注册表是否误引入浏览器运行时代码。
- Telegram 导航测试失败时，只修正注册表消费者，不添加 Telegram 特例副本。
- 本阶段可以整体回退注册表接线，但 Threads/Vimeo 必须继续由明确的全局开关保持关闭。

- 发布注册表当前只启用 Telegram、X、Instagram；Threads/Vimeo 保持 `disabled-unverified`。
