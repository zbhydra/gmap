# 013 · Instagram Story 与 Highlight 当前媒体

## 1. 目标

Story 和 Highlight 只下载用户当前正在观看的媒体。

当前项必须由可见主容器和 Instagram media ID 确定。图片、视频分别使用 parser 得到的原媒体地址；用户名、资源数量、分辨率最大值和 DOM 数组顺序都不能代替当前 media ID。

## 2. 非目标

- 不下载整组 Story 或整个 Highlight。
- 不支持头像、私信、Live 或音轨提取。
- 不使用 DOM 图片、poster 或 blob URL 下载。
- 不持久化浏览历史或媒体列表。
- 不修改 Popup 与共享下载函数。
- 不增加依赖注入。

## 3. 依赖

- Plan 009：PageContext 与当前路由资源 Map。
- Plan 010：媒体 parser。
- Plan 011：按钮渲染基础。

## 4. 改动范围

- 扩展 `pageContext.ts`，明确识别 Story 与 Highlight 路由。
- 扩展 `scanner.ts`，从当前可见容器提取 media ID、媒体类型提示和按钮挂载位置。
- 扩展 network capture、`media.ts` 和 `resolver.ts`，按 media ID 提供当前图片或视频原地址。
- 扩展 `buttons.ts`，在当前 Story/Highlight 主媒体上挂载一个下载按钮。
- 当前 media ID 改变时，用新资源替换 Map 中上一项 Story/Highlight 资源。
- 当前项缺少可验证 media ID 或原媒体时不显示可下载状态，并打印详细错误。

## 5. 执行步骤

1. 增加同一账号连续多条 Story、图片和视频混合 fixture。
2. 实现当前可见容器与 media ID 提取。
3. 将捕获数据按 media ID 解析为单个当前资源。
4. 接入按钮并验证前进、后退、自动播放和 Highlight 切换。
5. 删除用户名聚合、最大分辨率选择当前项和整组下载旧逻辑。

## 6. 验收标准

- [x] Story 前进或后退后按钮始终下载当前 media ID。
- [x] Highlight 使用相同规则，只下载当前项。
- [x] 同一账号多条 Story 不会因用户名相同而混合。
- [x] 当前图片不会误下载相邻视频，当前视频不会误下载 poster。
- [x] 当前项切换后 Map 中不保留上一项供页面下载。
- [x] 无精确 media ID 时宁可不下载，也不猜测。
- [x] 本阶段不影响 Post、Grid、Telegram 或 X。

## 8. 失败与回退

- Instagram 暂时没有提供当前 media ID 时不注入可用按钮，等待下一次 DOM 或网络变化后重扫。
- Story DOM 改版时只修改当前容器识别，不添加用户名或分辨率猜测。
- 本阶段可回退 Story/Highlight 按钮接线；不得重新启用整组下载。
