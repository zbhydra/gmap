# 031 · Telegram 统一远端配置

## 1. 目标

为新版扩展新增独立的 `tg-config`，把 Telegram DOM 与可远端调节的下载参数收进同一份配置。扩展包始终携带完整默认值；新接口返回稀疏覆盖时按分组合并，请求失败或后端没有配置时直接使用包内默认值。

现有 `tg-dom` 只服务已发布旧版，接口、存储、Admin 编辑入口、前端默认字段和值全部保持不变。新旧配置不迁移、不投影、不双写。

## 2. 范围

### 2.1 包含

- 新增独立 `telegram_config` 存储键及公共、Admin 读写接口。
- 新增 Admin「Telegram Config」JSON 编辑标签。
- 新版扩展增加完整 `DEFAULT_TELEGRAM_CONFIG`，首批包含完整 `dom` 默认对象和 OPFS 字节阈值。
- 新版扩展只请求 `tg-config`；成功后按分组浅覆盖，失败或空对象时保留完整包内默认值。
- content 使用 `dom`，并在 Telegram injected ready 后把下载配置一次性同步到 injected。
- `SegmentDownloader` 使用生效的 OPFS 阈值选择 memory 或 OPFS，其余下载合同不变。
- 后端、Admin 与扩展的直接验收测试，以及三个受影响端的构建和启动。

### 2.2 不包含

- 不修改或删除 `/api/client/tg/dom-config`、Admin Telegram DOM 接口、`telegram_dom` 数据或现有 Telegram DOM Admin 标签。
- 不从 `telegram_dom` 迁移、复制或回退读取数据；管理员需要为新版本单独保存 `telegram_config`。
- 不让旧版读取新配置，也不让新版请求旧配置。
- 本轮不远端配置分块并发、重试间隔、扫描间隔、任务期限、RPC 限额、URL 校验、内部批量上限或 UI 尺寸。
- 不增加配置版本、客户端版本上报、缓存、轮询、重试、灰度、历史、回滚、审批或恢复默认。
- 不新增表、字段、索引、依赖或 UI 组件。

## 3. 配置合同

### 3.1 完整前端默认值

`DEFAULT_TELEGRAM_CONFIG` 是新版扩展的完整默认配置，结构如下：

```json
{
  "dom": {
    "aMessageSelector": ".Message[data-message-id]"
  },
  "download": {
    "opfsThresholdBytes": 209715200
  }
}
```

示例中的 `dom` 只展示一个字段；真实默认值直接复用现有完整 `DEFAULT_TELEGRAM_DOM_CONFIG`，不复制或修改 selector 清单。`opfsThresholdBytes` 单位为字节，默认 `200 * 1024 * 1024`。

### 3.2 后端稀疏覆盖

后端保存顶层 JSON 对象，允许缺少分组、缺少字段和出现当前客户端不认识的键。公共接口未配置时返回 `{}`，不返回服务器维护的默认值。

新版客户端把接口结果视为可信内部合同：

- `dom` 对完整本地 DOM 默认值执行一次 `Object.assign` 浅覆盖；缺少键保留本地值，未知键保留供宽松对象读取。
- `download` 对完整本地下载默认值执行一次 `Object.assign` 浅覆盖；`opfsThresholdBytes` 由内部配置合同保证类型和值正确，客户端不重复校验。
- 未知顶层分组由不认识它的客户端忽略，允许后续客户端扩展合同。

配置只在每个 Telegram document 初始化时读取一次。成功保存后，已打开页面仍使用初始化时的生效值，管理员提示刷新 Telegram 页面。

## 4. 接口与存储

所有接口沿用统一 `{code, data, msg}` envelope，配置对象直接放在 `data` 或请求体，不再增加 `config` 包装。

| 方法 | 路径 | 鉴权 | 请求体 | 成功 `data` |
| --- | --- | --- | --- | --- |
| GET | `/api/client/tg/config` | 无 | 无 | Telegram 稀疏配置对象；未配置为 `{}` |
| GET | `/api/admin/system-settings/telegram-config` | Admin | 无 | Telegram 稀疏配置对象；未配置为 `{}` |
| POST | `/api/admin/system-settings/telegram-config` | Admin | 顶层 JSON 对象 | 原样保存后的对象 |

后端复用 `system_data_service`，固定读取和覆盖 `system_data.data_key="telegram_config"`。只校验请求顶层为对象；内部字段由写入方遵守统一合同，扩展不重复判断。旧 `telegram_dom` 的三个接口和存储行为不进入修改范围。

## 5. 扩展流程

### 5.1 所有权

- 现有 `TelegramDomConfig.ts` 继续拥有完整 DOM 默认对象和当前 content document 的 DOM 生效对象，不修改其默认字段和值。
- 新增 Telegram 总配置模块，拥有完整默认结构、当前下载生效配置、单次远端加载任务和已知字段合并。
- 新模块直接把现有 `DEFAULT_TELEGRAM_DOM_CONFIG` 作为 `DEFAULT_TELEGRAM_CONFIG.dom` 的来源；远端 `dom` 覆盖写入现有 `telegramDomConfig`，现有 DOM 消费方无需建立第二份状态。
- injected 侧新增 Telegram 下载配置模块级状态；不使用构造函数依赖注入，不持久化到 `chrome.storage`。

### 5.2 初始化顺序

1. Telegram content 同时等待 injected ready 并通过 Background RPC 请求一次 `/api/client/tg/config`。
2. 请求成功时在完整本地默认值上分别浅覆盖 `dom` 和 `download`；请求失败时记录端点与错误并使用完整本地默认值。
3. injected ready 后，继续执行现有 `synchronizeRuntimeConfig()`，保持 `debugLogging` 的 background → content → injected 同步；其失败仍由现有函数局部记录，不与 Telegram Config 成败绑定。
4. content 把生效 `dom` 浅覆盖到现有 `telegramDomConfig`，再通过新增 EventRpc 方法把 typed `download` 分组同步到 injected。
5. injected 直接 `Object.assign` 当前模块级下载配置；同步失败只记录错误并继续，injected 保持包内默认值。
6. 随后启动 scanner、observer、资源缓存、Story、Sidebar 和下载管理入口。
7. `DownloadServices` 从 injected 模块级配置读取阈值，并在调用 `SegmentDownloader.download` 时显式传入；core 下载器不依赖 Telegram 站点模块。

配置请求失败使用本地默认值，Telegram Config 同步失败只影响 injected 下载配置且不阻断页面功能。现有日志运行时配置有自己的默认与错误处理。

### 5.3 OPFS 选择

只替换 `SegmentDownloader` 当前固定 `200 MiB` 阈值的来源：

| 条件 | Sink |
| --- | --- |
| `totalSize < opfsThresholdBytes` | memory |
| `totalSize >= opfsThresholdBytes` 且 OPFS writable 可用 | OPFS |
| `totalSize >= opfsThresholdBytes` 但 OPFS 不支持 | memory |

当阈值为 `0` 时，任何取得可靠大小的资源都满足阈值。存储只在预检后选择一次；OPFS 已选中后的失败、清理、取消、进度、并发和重试行为全部保持现有合同。

## 6. Admin 行为

系统设置保留现有「Telegram DOM」标签，并新增独立「Telegram Config」标签。新标签沿用现有 JSON 文本编辑交互：

- 首次进入时读取一次；未配置显示 `{}`。
- 只校验合法 JSON 和顶层对象，不维护字段表单或扩展版本 schema。
- 显式保存，保存中禁止重复提交；成功后保留原文本并提示刷新 Telegram 页面。
- 读取失败提供重试；保存失败保留未保存文本。
- 不展示扩展包默认值，不提供格式化、自动保存、恢复默认、版本、历史或回滚。

## 8. 验收标准

- 旧 public/Admin Telegram DOM 接口、存储键、Admin 标签及现有测试行为保持不变。
- 新接口未配置或请求失败时，新版扩展完整使用包内 DOM 与 `200 MiB` 默认阈值。
- 新接口只覆盖一个 DOM selector 时，其余 DOM 默认值不变；新插件不请求旧 `dom-config`。
- 新接口把 `opfsThresholdBytes` 设为测试文件大小时，该文件选择 OPFS；设为更大值时同一文件选择 memory。
- Telegram Config 同步成功时，业务 owner 启动前 content DOM 与 injected 下载配置均已应用；同步拒绝时保留 content DOM 覆盖，injected 使用默认下载配置并继续启动。
- 现有 `synchronizeRuntimeConfig()` 仍在 injected ready 后执行，Telegram Config 请求或同步的成败不改变其行为。
- Admin 可独立读取、保存 Telegram Config；操作不改写 Telegram DOM 标签内容。
- Backend real API 测试证明未配置 GET、鉴权、Admin POST 后两个新 GET、顶层非对象拒绝，以及整个流程前后 `telegram_dom` 值不变。
- 不新增表、字段、索引、依赖、持久配置缓存或 UI 组件。

## 10. 已知边界

- 新配置上线时不会继承现有 `telegram_dom` 内容；在 Admin 保存 `telegram_config.dom` 前，新版使用自身 DOM 默认值。
- 老版本永远看不到 Telegram Config 的更新，新版本也看不到后续 Telegram DOM 更新，这是新旧接口独立的明确结果。
- Admin 是宽松 JSON 编辑器，内部字段由写入方遵守统一合同；不增加后端版本 schema 或客户端重复校验。
- 本轮只证明统一容器与一个下载参数，后续新增字段仍需明确真实消费方、默认值、类型语义和直接验收，不能仅因常量存在就远端配置化。
