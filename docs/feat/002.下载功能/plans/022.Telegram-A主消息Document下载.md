# 022 · Telegram A 主消息 Document 下载执行计划

## 1. 目标

让 Telegram Web A 版主消息流识别并下载所有可下载的 message document，而不是只补截图中的 OGG：

| Telegram document 语义 | ResourceType | 示例 |
| --- | --- | --- |
| round video attribute | `round` | 圆形视频 |
| animated attribute | `gif` | GIF / 动画 document |
| audio attribute + voice | `voice` | Telegram 语音 |
| audio attribute 或 `audio/*` | `audio` | OGG、MP3、M4A |
| video attribute | `video` | 作为 document 存储的视频 |
| `image/*` MIME | `image` | 作为文件发送的图片、WebP |
| 其他 document | `document` | PDF、ZIP、TXT、未知二进制文件 |

下载结果必须来自 Telegram 原始 document 元数据和下载能力，不保存封面、缩略图或播放器临时资源，也不依赖文件是否已打开或播放。

## 2. 范围

### 2.1 本轮包含

- A 版当前活动消息列表的完整 message identity 收集。
- content 扫描期只按 `.Audio/.File` 与 `chatId/messageId` 建立待解析资源，用户点击时单次查询 MAIN world。
- MAIN world 通过 `LocalDbMirror.documents[].localRepairInfo` 精确关联消息与 document。
- K/A 共享 document 元数据归一化和类型判定。
- A document 主下载源选择：保留现有可用 progressive/DOM 视觉媒体源，其余使用 `telegram-a-mediahash` 原文件链路。
- audio/voice/普通 document 的消息父下载按钮；已有视觉媒体继续保留父按钮和圆形单项入口。
- popup、额度、队列、状态与错误提示沿用共享下载链路。
- 单元测试、固定频道真实下载、技术文档与 changelog。

### 2.2 本轮不包含

- 不改后端、website、扩展权限和 CSP。
- 不新增依赖，不新增依赖注入。
- 不把 Telegram photo 改造成 document；`messageMediaPhoto` 继续走 A 现有 photo 链路。
- 不下载 sticker set、custom emoji、story 或网页预览缓存中的非 message document；只接受 `localRepairInfo.type === 'message'`。
- 不把 LocalDb 中同一消息的候选/替代质量全部下载一遍；一条 Telegram 消息只生成一个主 document 资源。
- 不给 audio/voice/普通 document 添加覆盖原生控件的圆形按钮。它们使用消息下方现有父按钮。
- 不从 DOM blob、封面、可见文件名或扩展名反推 document ID 和媒体类型。
- 不为大文件增加断点续传或第二套流式协议；失败记录原因并允许用户重试。

## 3. 核心设计

### 3.1 单一身份链路

```text
当前活动 A MessageList
  -> content 收集每个可定位 Message 的 chatId + data-message-id
  -> Audio/File 立即建立唯一待解析资源；photo/video 只取自身 DOM URL
  -> ResourceBuffer / 页面按钮 / popup
  -> 用户点击时 FIFO 当前项调用 getAMediaResources([{ chatId, messageId }])
  -> MAIN world 按 localRepairInfo 精确匹配、归一化并返回主 document
  -> downloadMedia
```

身份规则：

- content 只提交 `findActiveAMessageListRoot()` 中真实可定位的消息，不读取隐藏/旧聊天 DOM。
- MAIN world 必须同时匹配 `localRepairInfo.type`、`peerId` 和 `id`。
- 不按 LocalDb 插入时间、文件名、MIME、document 顺序或最近播放状态猜消息归属。
- `.Audio` / `.File` 已出现但 LocalDb 尚未同步时立即返回待解析资源；不从文件名、MIME 或 DOM URL 猜内部参数。
- 相册继续使用每个 `.media-inner` 的子消息 ID；不从父消息身份复制内部 document。
- 同一消息存在多个不同 document ID 时，由明确的主资源选择规则选一个并记录 warning，不把替代质量当成多附件。

### 3.2 RPC 合同

在 injected register 增加 `getAMediaResources`：

```text
request:
  messages: Array<{ chatId: string; messageId: string }>

response:
  resources: AInternalMediaResource[]

AInternalMediaResource:
  chatId: string
  messageId: string
  index: 0
  type: round | gif | voice | audio | video | image | document
  sourceKind: telegram-a-mediahash
  url: mediaHash:document{documentId}
  filename: string
  size: number
  mimeType: string
  documentId: string
  codec?: string
  width?: number
  height?: number
  duration?: number
```

合同约束：

- 合同最多接受 50 条，主消息点击固定只传当前一条 identity；RPC parser 执行硬上限校验。
- 响应每个 identity 最多一项。
- 只允许 `content` 通过 `event` transport 调用。
- 使用 16 KiB 请求、256 KiB 响应量级，不传完整 document、fileReference 或 Blob。
- register 修改后执行 `pnpm rpc-generate` 并提交生成客户端。
- EventRpc 是不可信 DOM 通道；handler 只返回请求身份对应的有限描述，不暴露整个 LocalDb。

### 3.3 共享 Document 元数据模型

新增无状态纯函数模块 `TelegramDocumentMetadata.ts`，统一 K/A 的以下规则：

- 兼容 K 的 snake_case/`_` 与 A 的 camelCase/`className`，在边界归一化一次。
- 提取 document ID、MIME、size、filename、attributes、codec、width、height、duration。
- 构造名按语义归一化，不能在 K/A service 各自维护大小写不同的字符串判断。
- 分类顺序固定：`round -> gif -> voice -> audio -> video -> image/* -> document`。
- `DocumentEmpty` 或缺少 ID/MIME 的不生成资源。
- filename 优先取 Telegram filename attribute；统一 canonical 规则保留合法内部空格与 Unicode，只替换跨平台禁用字符、清理首尾空白/尾句点和 Windows 设备名，并在缺失时使用 MIME 扩展名兜底。
- 为已知 Telegram MIME 补正确扩展名映射，例如 `application/x-tgsticker -> .tgs`；未知 MIME 保留 Telegram filename，仍缺失时才回退 `.bin`。

共享模块只处理元数据，不读取 K chat、A LocalDb、DOM 或下载 URL。K/A service 各自保留资源定位与 URL 构造，避免形成混合版本服务。

### 3.4 A Document 服务

新增具体单例 `AMediaResourceService`，直接使用 `ALocalDbServices`，不引入依赖注入。

处理流程：

1. 将请求 identity 组成集合，一次遍历 LocalDb documents，避免每条消息重复全表扫描。
2. 只保留 message repair info 与请求完全匹配的有效 Document。
3. 按 document ID 去重，通过共享模块归一化。
4. 每个 identity 选择一个主 document。正常单 document 直接返回；出现多个候选时按非 playlist、尺寸更大、document ID 更小的顺序稳定选择，并输出 identity、候选 ID/类型/大小 warning。
5. 构造 `mediaHash:document{documentId}` 与 `telegram-a-mediahash`，不返回 accessHash/fileReference。
6. 响应仅返回结构化、可序列化字段。

`ALocalDbServices` 增加按有限 identity 批量读取 document 的公开方法，返回只读结果副本或新数组，不暴露内部可变 Map。全量 LocalDb snapshot 也必须在查询时按 repair info 精确过滤，避免旧聊天条目误绑。

### 3.5 A DOM 扫描与点击解析

`AVersionScanner.scan()` 不调用 LocalDb RPC：

1. 收集当前活动消息上下文、相册子项 identity 和媒体元素上下文。
2. `.Audio/.File` 优先生成空 URL、无 `documentId` 的 `telegram-a-mediahash document` placeholder；组件内部封面和 full-media 不参与判型。
3. 其余 photo/video 仅从 DOM 生成现有资源，不新增 placeholder。

点击规则：

- 只有 A 主消息 placeholder 的四字段组合进入 `getAMediaResources`，Sidebar/K/其他资源不解析。
- DownloadManager 先按当前 placeholder 的 `chatId/messageId` 单次解析，再扣额并执行原下载。
- 解析成功后使用真实 type、mediaHash、filename、size、MIME、documentId 与音视频元数据。
- 当前项解析失败时输出 identity 与响应字段状态；批量 FIFO 继续后续项。

`URLExtractor` 应明确返回 progressive 与 DOM URL 的来源语义，使 A progressive 资源标记为 `telegram-a-progressive`，普通 blob/完整 DOM URL 标记为 `telegram-a-dom-url`，不再一律标为 DOM 来源。

### 3.6 下载源与 Worker

下载源优先级：

1. 已验证的 A progressive URL：适合现有 video-like 大媒体，继续复用 SegmentDownloader。
2. 已验证的完整 DOM/blob 媒体：保持现有 photo/video 行为。
3. `mediaHash:document{id}`：所有 document 的通用原文件能力，普通文件和音频默认走此路径。

Worker 改造：

- `callMethod` 每次生成唯一 request ID，禁止固定 `123456789`。
- 成功、Worker 返回错误、抛错和超时都清理 timer/waiter/request 记录。
- timeout 覆盖正常 document 下载耗时，并与 content 长任务语义一致；超时后允许重试。
- 保留 Worker 返回 Blob 后由扩展触发保存的现有机制，不把 Blob 放进 EventRpc。
- 所有 document 都向 Worker 开启 `isHtmlAllowed`；只要返回 Blob 就直接保存，不因 MIME 缺失、未知或与声明不一致而拒绝。
- Worker 请求开启原生方法回调，将 GramJS 的 0-1 分块进度转换为页面 0-100 百分比。
- 记录错误时包含 sourceId、type、documentId、声明 size 和错误阶段，不输出敏感下载参数。
- `downloadMedia` 的不可信 RPC parser 必须显式保留并校验 `documentId`、`codec`，不能依赖 TypeScript 类型在 JSON 边界自动透传。

### 3.7 页面按钮与 Popup

- audio/voice/document：只显示消息下方 `DOWNLOAD (1/1)` 父按钮，不加入 `VISUAL_MEDIA_TYPES`。
- image/video/round/gif：能定位稳定视觉面时继续显示圆形单项入口，同时保留父按钮。
- 相册视觉媒体保持现有 DOM 资源、复选框和父按钮，不在扫描期补内部 document 元数据。
- Popup 中 `.Audio/.File` 只展示 generic document placeholder；真实 type、MIME 和 filename 仅供 FIFO 当前项下载使用，不回写 Popup 或资源缓存。
- 普通 document 不新增播放器、预览卡或新文案，不产生新的 i18n UI。

## 9. 风险与处理

- LocalDb BroadcastChannel 未同步：Audio/File 先以消息身份生成待解析入口，点击仍取不到真实参数时输出可定位错误并让用户重试，不从 DOM 临时 URL 猜 document。
- 同一消息存在多个 document：只选主项并记录候选信息，不把替代质量重复展示为附件。
- Worker 整体 Blob 占用内存：视觉大媒体优先保留 progressive/DOM 路径；普通大 document 超出浏览器能力时记录阶段和 size 后报错，让用户重试，不新增复杂续传协议。
- Telegram attribute 形状变化：真实 fixture 与共享 parser 测试共同锁定；无法归一化时按 `document` 保留原文件能力，缺少必要下载身份时才跳过。
- 未知 MIME：优先 Telegram filename；缺失 filename 时用 MIME/`.bin` 兜底，不能因展示类型未知而拒绝下载。
- HTML/JSON document：与其他 document 一样直接保存 Worker 返回的 Blob，不根据响应 MIME 判断内容是否合法。
- 固定频道 fixture 变化：E2E 输出 chatId/messageId/documentId/type/selector 和下载文件信息，恢复 fixture 后重跑，不以 mock 媒体替代真实下载。
