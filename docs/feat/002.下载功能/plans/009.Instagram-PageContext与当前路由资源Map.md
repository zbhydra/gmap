# 009 · Instagram PageContext 与当前路由资源 Map

## 1. 目标

用显式 `PageContext` 和一个当前路由资源 `Map` 取代隐式路由判断与多份资源缓存。

`PageContext` 覆盖 Home Feed、Post、Reel、Reels Feed、Profile、Profile Reels、Explore、Search、Hashtag、Story、Highlight 和 `unsupported`。当前路由只维护一个 `Map<entityKey, MediaResource[]>`；真实路由变化时直接换成空 Map，随后重新扫描。集合页已滚动发现的资源在离开该集合路由前保留。

Post/Reel 弹窗存在时只扫描弹窗；关闭弹窗后重新扫描底层页面。轮播序号变化只更新当前项，不清空整帖资源。

## 2. 非目标

- 不解析 Instagram JSON 或选择媒体质量。
- 不注入最终下载按钮。
- 不保存跨刷新状态，不写 storage。
- 不遍历未滚动加载的账号或无限列表。
- 不增加依赖注入。

## 3. 依赖

- Plan 008：平台开关与 Instagram 契约基线。

## 4. 改动范围

- 新增 `extension/src/sites/instagram/content/pageContext.ts`，提供路由到显式上下文的纯函数。
- 新增 `extension/src/sites/instagram/content/routeMediaStore.ts`，只封装当前上下文和一个资源 Map。
- 修改 Instagram content 入口，在 `popstate` 或现有 DOM observer 触发时直接比较 `location`、弹窗和轮播，并重新识别上下文。
- observer 只发出“需要重扫”信号；由一个短 debounce 合并高频 DOM 变化。
- 未识别路由不扫描、不注入、不保留旧资源。

## 5. 执行步骤

1. 先完成路由纯函数和保留路径负向测试。
2. 实现当前路由资源 Map 的整组覆盖、读取和清空。
3. 接入 `popstate` 与稳定 document/body observer；不增加 MAIN 导航事件。
4. 接入弹窗优先和轮播当前项更新。
5. 删除旧的 `null` 路由兜底与 Instagram 平行资源缓存。

## 6. 验收标准

- [x] 每个支持页面都得到明确 `PageContext`，未知页面只得到 `unsupported`。
- [x] 每个 tab 只有一个当前路由资源 Map。
- [x] Profile、Search、Hashtag 等路由身份变化会清空旧 Map。
- [x] 打开 Post/Reel 弹窗后只暴露弹窗资源，关闭后重新扫描底层页面。
- [x] 轮播切换只改变当前项指针，不丢失同帖其他资源。
- [x] Instagram 替换 `main` 后仍能触发重扫，且不会创建多个 observer。
- [x] 页面刷新后从空 Map 重新开始。
- [x] 本阶段不修改共享下载和 Telegram 源码。

## 8. 失败与回退

- 弹窗没有独立 URL 时，以 dialog 内 canonical permalink 判定；无法判定就不扫描。
- DOM 变化过多时只调整 debounce，不增加第二套观察链。
- 本阶段可整体回退路由比较和资源 Map 接线；回退时仍不得把未知路由当作 Feed 扫描。

## 9. 实施记录（2026-07-11）

- Instagram content 只有 `routeMediaStore.ts` 一份当前路由 Map；旧 ResourceBuffer/平行 cache 已删除。
