# 017 · Instagram 可控 E2E 与真实 Canary

## 1. 目标

建立两条测试链路：

1. 本地可控 Instagram 页面加载真实 unpacked extension、content、injected、background、Popup 和 Chrome API，作为功能硬门禁。
2. 真实登录态 Instagram 页面只检查外部 DOM、页面数据和按钮兼容性，作为发布前 Canary。

所有 E2E 命令必须验证当前源码构建，不能因旧 `dist` 存在而复用旧产物。

## 2. 非目标

- 不让真实 Instagram 页面承担额度异常和下载错误的确定性断言。
- 不做像素级截图测试。
- 不使用固定 sleep 等待页面变化。
- 不 mock `chrome.*`。
- 不验证 Threads/Vimeo。
- 不为测试增加生产专用开关或依赖注入。

## 3. 依赖

- Plan 008 至 Plan 016 全部完成并通过各自门禁。

## 4. 改动范围

- 新增或扩充 `extension/tests/helpers/instagram-controlled.ts`、controlled Playwright project 和 Instagram fixture 数据。
- 增加单图、单视频、Carousel、Reel 与封面、Grid、Story、Highlight、失败响应和媒体文件 fixture。
- 可控页面继续使用 `https://www.instagram.com/*`，通过 Playwright route 返回本地 HTML、JSON 和媒体字节。
- 增加当前路由、按钮、Popup、额度和真实文件下载 E2E。
- 修改 E2E scripts，使运行前构建当前源码并检查关键产物。
- 真实 Canary 使用环境变量提供账号可访问样本，不硬编码个人内容。

## 5. 可控场景

- 独立页面覆盖 Home、Post、Reel、Profile、Explore、Search、Hashtag、Story 和 Highlight；另在同一 document 内用 `history.pushState` 和 body fixture 切换 Post → Profile Grid → Story，断言旧路由按钮、Map 与 Popup 资源被当前路由替换。
- Post/Reel 始终有“全部”和“当前项”；Carousel 当前项正确；Reel 主下载不请求 cover。
- Grid 单图、Reel 和 Carousel 不导航即可下载原媒体，且不请求 thumbnail。
- Story/Highlight 只下载当前 media ID。
- Popup 每次直接查询当前 tab，只列主媒体，不列封面，并且 Instagram 没有清理缓存按钮。
- 每个资源调用一次额度；额度服务异常仍下载；明确不足只跳过当前项。
- 一项下载错误后下一项继续；之前成功项不受影响。
- 同一资源点击两次会产生两次额度调用和两次下载尝试。
- 页面刷新后旧显示状态消失，重新点击仍可下载。
- 下载文件非空，文件名、MIME、扩展名和 fixture 内容正确。

## 6. 真实 Canary

- 检查登录态并区分登录失效、样本不可用、布局变化和网络不可用。
- 每个样本先从环境变量 URL 解析页面身份；Post/Reel 按 URL shortcode、Story 按 URL media ID、Highlight 按可见 DOM media ID 核对按钮的生产 marker、dataset 与所属 permalink，详情页推荐内容不能代替当前 route 通过。
- Profile/Profile Reels 的每个 Grid 按钮 entity 必须等于自身 tile permalink；Home 的 current/all 必须成对属于同一 Feed permalink。
- Reel 样本先确认页面外没有 Cover，再真实点击当前 route 内的 operation 按钮，只接受 operation menu/dialog 内且 entity 等于 Reel shortcode 的唯一 Cover 按钮。
- 下载样本只允许 Post、Reel 或带精确 media ID 的 Story，只点击 current/story 单项按钮，禁止用 Grid 或 Download All；保存的单个文件必须与点击后单个 CDN 响应逐字节一致，并核对 MIME 与扩展名。
- 外部环境失败不能放宽可控 E2E 的通过标准。

## 7. 验收标准

- [x] E2E 每次使用当前源码构建。
- [x] 可控环境不依赖真实 Instagram 登录态或项目后端。
- [x] 支持页面、媒体类型、按钮和 Popup 主流程全部有可执行断言。
- [x] 测试点击真实按钮并检查下载文件，不只检查按钮数量。
- [x] 逐项额度、fail-open、部分错误继续和重复点击行为均被固定。
- [x] 可控同 document SPA 切换覆盖 Post → Profile Grid → Story；真实 Instagram 站点的 SPA 切换仍归真实 Canary，当前未执行。
- [x] 等待使用 locator、页面事件或 download promise，不使用固定 sleep。
- [ ] 真实 Instagram Canary 完成布局合同与小文件下载；当前环境缺少显式样本变量，尚未执行。
- [ ] Telegram Popup/sidebar、A/K 扫描和 A/K 单资源真实下载通过。
- [x] X 媒体与下载 service 测试通过。

## 8. 验证命令

```bash
cd extension
pnpm rpc-generate:check

pnpm check
pnpm build
pnpm exec playwright test --project=extension-e2e-instagram-controlled --list
E2E_INCLUDE_INSTAGRAM=1 pnpm exec playwright test --project=extension-e2e-instagram-real --list
pnpm test:e2e:ui
pnpm test:e2e:instagram:controlled
pnpm test:e2e:real
pnpm test:e2e:instagram
```

## 9. 失败与回退

- 可控页面与生产页面差异由真实 Canary 暴露，不削弱可控断言。
- 真实账号或样本失效时记录环境分类并更新样本。
- Telegram 或 X 门禁失败时回到对应共享模块修正，不增加站点旁路。
- 本阶段只修改测试、fixture 和配置；需要回退时不回退已经通过的业务实现。
