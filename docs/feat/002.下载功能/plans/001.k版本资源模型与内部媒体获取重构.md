# 001 · K 版本资源模型与内部媒体获取重构执行计划

## 1. 目标

把 K 版资源获取从“DOM 元素判型”改成“内部 `message.media` 判型”，优先解决四个问题：

- 视频不能因为只有 `.media-photo` 缩略图而下载成图片。
- document / audio / voice / gif / round / image document 能按真实类型进入资源列表。
- popup 到 content 下载链路不再丢 `type/sourceKind/messageFullId/mimeType`。
- grouped media 使用子项自己的 `data-mid/data-peer-id`，不再共用父消息资源。

本轮原则：方案必须简单。阻塞项先删除出本轮，不堆复杂兜底。

## 2. 本轮删除的复杂项

- 不做 K mirror / worker / MessagePort 拦截。
- 不做 K photo 原图内部 location 构造。photo 本轮只在内部确认 `messageMediaPhoto` 后使用 DOM photo URL，并标记 `sourceKind='telegram-k-dom-url'`；这是已知质量缺口，不代表 photo 已拿到最大原图。
- 不做 HLS 分片合并，只在 `alt_documents` 里选择真实 video document。
- 不保留 popup 传完整资源对象或扁平 `{ url, type }` 的旧方案。统一只传 `resourceIds`。
- 不做复杂缓存迁移清理。新代码不再生成 grouped 父消息资源；旧缓存通过刷新页面 / 切聊天清空。

## 3. 资源模型

### 3.1 ResourceType

```ts
type ResourceType =
  | 'photo'
  | 'image'
  | 'video'
  | 'round'
  | 'gif'
  | 'audio'
  | 'voice'
  | 'document'
```

分类顺序固定：

1. `messageMediaPhoto` -> `photo`
2. `messageMediaDocument` + round 标记 -> `round`
3. `messageMediaDocument` + gif / animated 标记 -> `gif`
4. `messageMediaDocument` + voice 标记 -> `voice`
5. `messageMediaDocument` + audio 标记 -> `audio`
6. `messageMediaDocument` + video 标记 -> `video`
7. `messageMediaDocument` + `mime_type` 为 `image/*` -> `image`
8. 其他可下载 document -> `document`

`sticker` 本轮不做独立类型；能按 document 下载就归 `document`，不能下载就跳过。

### 3.2 ResourceSourceKind

```ts
type ResourceSourceKind =
  | 'telegram-k-document'
  | 'telegram-k-dom-url'
  | 'telegram-a-mediahash'
  | 'telegram-a-progressive'
  | 'telegram-a-dom-url'
```

本轮不新增 `telegram-k-photo`，因为 K photo 原图内部链路已删出本轮。

### 3.3 MediaResource

```ts
interface MediaResource {
  id: string
  messageId: string
  messageFullId?: string
  index: number
  url: string
  type: ResourceType
  sourceKind: ResourceSourceKind
  filename?: string
  size?: number
  thumbnail?: string
  mimeType?: string
  documentId?: string
  codec?: string
  width?: number
  height?: number
  duration?: number
  chatId?: string
  metadata: DownloadMetadata
}
```

规则：

- 新构造资源必须填 `sourceKind`。
- 缩略图只能进 `thumbnail`，不能进主 `url`。
- document-backed 资源优先使用 Telegram 的 `mime_type` 和 `file_name`。
- `photo` 本轮只有在 injected 确认是 `messageMediaPhoto` 后，才由 content 使用同一个候选节点的 DOM URL 作为主 URL。

默认 MIME / 扩展名只做最后兜底：

| type | MIME | ext |
| --- | --- | --- |
| photo | image/jpeg | .jpg |
| image | image/jpeg | .jpg |
| video | video/mp4 | .mp4 |
| round | video/mp4 | .mp4 |
| gif | image/gif | .gif |
| audio | audio/mpeg | .mp3 |
| voice | audio/ogg | .ogg |
| document | application/octet-stream | .bin |

## 4. K 主链路

### 4.1 RPC

新增 injected RPC：

```ts
interface InjectedGetKMediaResourcesRequest {
  messageFullIds: string[]
}

interface InjectedGetKMediaResourcesResponse {
  resources: KInternalMediaResource[]
}

interface KInternalMediaResource {
  messageFullId: string
  index: number
  type: ResourceType
  sourceKind: 'telegram-k-document' | 'telegram-k-dom-url'
  url?: string
  filename?: string
  size?: number
  mimeType?: string
  documentId?: string
  codec?: string
  width?: number
  height?: number
  duration?: number
}
```

规则：

- content 传完整 `messageFullIds`，格式 `${peerId}_${mid}`。
- injected 不再调用 `makeFullMid`。
- 每批最多 50 个。
- `METHOD_REQUEST_LIMITS.getKMediaResources = 16384`。
- `METHOD_RESPONSE_LIMITS.getKMediaResources = 262144`。
- 解析不到资源就不返回该资源，不把失败列表传给 UI。
- 日志只记录定位必要字段：`messageFullId`、DOM peerId、内部 `chat.peerId`。
- injected 不读取 DOM，不返回 photo DOM URL。photo 只返回内部判型结果；content 负责把同一候选节点上的 DOM photo URL 合并为最终 `MediaResource`。
- 视频质量选择在 injected 内部完成；只返回选中的 document，不把 `alt_documents` 数组存进 `MediaResource`。

### 4.2 DOM 只负责找候选消息

K scanner 只做两件事：

1. 找媒体候选 DOM。
2. 读取候选节点的 `data-mid/data-peer-id`，组成 `messageFullId`，用 `Set` 去重后再调 RPC。
3. 记录候选节点关联的 DOM 图片 URL，只供 content 合并 `thumbnail`，以及在内部确认 `photo` 后合并 photo 主 `url`。

候选选择器：

- `.media-photo`
- `.media-video`
- `button.video-play`
- `.media-round`
- `.media-gif-wrapper`
- `.document`
- `.document-container`
- `.document-download`
- `audio-element`
- `.audio`
- `[data-doc-id]`
- `.album-item.grouped-item[data-mid][data-peer-id]`
- `.document-container.grouped-item[data-mid][data-peer-id]`

禁止：

- 不能因为 DOM 有 `img.media-photo` 就生成 `photo`。
- 不能把 video/document/audio 的缩略图写入主 `url`。
- grouped 子项不能继承父 bubble 的 `messageId`。

### 4.3 内部解析

新增 `KMediaResourceService`，不引入依赖注入。

职责：

- 用 `messageFullId` 读取 K 内部 message。
- 按 `message.media._` 与 document attributes 判定 `ResourceType`。
- document 类资源构造 `stream/<DownloadOptions>`，`thumb_size` 必须为空。
- photo 只返回“该 `messageFullId` 是 `messageMediaPhoto`”的内部判型；最终 URL 由 content 从同一候选节点补，`sourceKind='telegram-k-dom-url'`。
- 内部对象取不到时跳过，不生成 DOM 可下载资源。
- content 只在 `type === 'photo'` 时把 DOM 图片 URL 合并为主 `url`；其他类型只能把 DOM 图片 URL 写入 `thumbnail`。

document 下载参数：

- `location._ = 'inputDocumentFileLocation'`
- `id/access_hash/file_reference` 来自 document。
- `thumb_size` 不传。
- `mimeType/fileName/size` 来自 document。

### 4.4 视频质量选择

对 `messageMediaDocument.document`：

1. 默认使用主 document。
2. 如果存在 `alt_documents`：
   - 排除 `mime_type === 'application/x-mpegurl'`。
   - 只保留真实 video document。
   - 先选最高 `height`。
   - 同高度优先 `codec !== 'av01'`。
   - 再按 `size` 选更大者。

不保存 m3u8 playlist。

## 5. 下载链路

popup 到 content 统一只传 id：

```ts
interface ContentDownloadBatchRequest {
  requestId: string
  resourceIds: string[]
}
```

content 从 `ResourceBuffer` 查完整 `MediaResource` 后再下载。找不到 resourceId 就让该项失败，不从 popup 旧字段重建。

`resourceId` 契约：

- `resource.id` 是唯一 lookup key。
- K 内部资源 id 固定为 `${messageFullId}_${index}`。
- 没有 `messageFullId` 的 A/sidebar 旧资源继续用已有 id。
- ResourceBuffer 只按 `resource.id` upsert 和 lookup，不再维护第二套 key。

要求：

- `downloadBatch` 请求只接收 `resourceIds`。
- `MessageHandler` 不再把 popup 资源硬编码成 `VIDEO`。
- `IMediaSource` 支持完整 `ResourceType`，并保留 `mimeType/sourceKind/messageFullId/chatId`。
- `IMediaSource` 新增字段：`mimeType?: string`、`sourceKind?: ResourceSourceKind`、`messageFullId?: string`、`chatId?: string`。
- `parseMediaSource` 接受完整 `ResourceType`。
- `BlobDownloader`、`FilenameUtils` 不再默认 mp4。

## 6. ResourceBuffer

只做 sourceRank upsert：

- `resource.id` 是唯一 key；K 内部资源 id 固定为 `${messageFullId}_${index}`。
- 同 key 下，只在新资源 rank 高于或等于旧资源时替换。
- DOM 来源 rank 低，不能覆盖内部/worker 真实链路。

优先级：

1. `telegram-k-document`
2. `telegram-a-mediahash`
3. `telegram-a-progressive`
4. `telegram-k-dom-url`
5. `telegram-a-dom-url`

不做复杂 prune。页面刷新、聊天切换、ResourceBuffer clear 足够清理旧缓存。

## 7. UI / popup

要求：

- 展示 `photo/image/video/round/gif/audio/voice/document`。
- 图标和文案按类型映射。
- 计数不再只有 photo/video。
- 下载时只传 `resourceIds`。

## 8. A 版与 sidebar

本轮只做兼容，不重构 A 主链路：

- A 版已有 worker/mediaHash 资源补 `sourceKind='telegram-a-mediahash'`。
- A progressive 资源补 `sourceKind='telegram-a-progressive'`。
- A DOM 资源补 `sourceKind='telegram-a-dom-url'`。
- A 主消息扫描在 video/img 并存时优先 video。
- 本轮删除 K sidebar DOM 下载能力。K sidebar 不生成可下载 DOM 资源，避免侧链路继续下载缩略图。

A 版 preview-only 且 DOM 只有 img 的视频误判不在本轮解决。

## 10. 阶段

### 阶段 1：类型与 RPC

目标：

- 扩 `ResourceType`、`MIME_TYPE_MAP`。
- 新增 `ResourceSourceKind`。
- 扩 `MediaResource` 字段。
- 新增 `getKMediaResources` RPC。
- `content.downloadBatch` 改为 `resourceIds`。

验收：

- `type/sourceKind/messageFullId/mimeType` 能贯穿资源缓存与下载链路。
- `getStreamUrl(s)` 不再是 K scanner 主链路。
- register 改动已生成 typed client。

验证：

- `cd extension && pnpm rpc-generate`
- `cd extension && pnpm rpc-generate:check`
- `cd extension && pnpm type-check`

### 阶段 2：K 内部 document 主链路

目标：

- K scanner 从 DOM 提取 `messageFullId`。
- injected 读取内部 message 并返回 `KInternalMediaResource[]`。
- document/video/audio/voice/gif/round/image 都走 document 下载参数。
- photo 只在内部确认后使用 DOM URL。

验收：

- 视频缩略图不会进入 `url`。
- document/audio/voice/gif/round/image 有真实 `type/mimeType/filename/sourceKind`。
- grouped 子项使用自己的 `data-mid/data-peer-id`。

验证：

- unit：DOM 只有 `.media-photo` 缩略图，但内部是 video document，返回 `type='video'`、`url=stream/<DownloadOptions>`、`thumbnail=DOM 缩略图`。
- unit：document/audio 候选 DOM 带缩略图时，最终 `url` 来自 injected stream，DOM 图只进 `thumbnail`。
- unit：内部 store 找不到 `messageFullId` 时返回空结果，content 不生成资源。
- unit：mock video/audio/voice/gif/round/image/generic document。
- unit：mock `messageMediaPhoto`，只允许内部确认后生成 `telegram-k-dom-url` photo。
- unit：多个 `.album-item.grouped-item[data-mid]` 返回不同 resource。
- unit：多个 `.document-container.grouped-item[data-mid]` 返回不同 resource。
- unit：同一消息命中多个候选选择器时，`messageFullId` 去重后只请求一次 RPC。
- manual：真实 K 页面确认 DOM `data-peer-id` 与内部 `chat.peerId` 可组成可命中的 `messageFullId`。
- `cd extension && pnpm test:unit:run`

### 阶段 3：视频质量选择

目标：

- 支持 `alt_documents`。
- 排除 m3u8。
- 选择最高且尽量非 AV1 的真实 video document。

验证：

- unit：主 doc + playlist + AV1/H264 alt doc。
- unit：只有 playlist 时不下载 playlist，回到主 document。

### 阶段 4：下载链路与 popup

目标：

- popup 只传 `resourceIds`。
- content 从 ResourceBuffer 回查完整资源。
- `IMediaSource` / `parseMediaSource` 接受完整 `ResourceType`。
- popup 展示新类型。

验证：

- unit：`content.downloadBatch` 只接收 resourceIds。
- unit：找不到 resourceId 时该项失败。
- unit：`MessageHandler` 不再硬编码 VIDEO。
- unit：`IMediaSource` 保留 `mimeType/sourceKind/messageFullId/chatId`。
- unit：每个 ResourceType 的默认 MIME / 扩展名。
- `cd extension && pnpm test:unit:run`
- `cd extension && pnpm test:e2e:ui`

### 阶段 5：A / sidebar 兼容

目标：

- A 现有资源补 `sourceKind`。
- A 主消息 video/img 并存时优先 video。
- K sidebar 不生成可下载 DOM 资源。

验证：

- unit：A main message video > img。
- unit：A mediaHash/progressive/DOM sourceKind。
- unit：K sidebar DOM 缩略图不生成可下载资源。

## 11. 总体验收

- K 视频不会因为 `.media-photo` 缩略图被当 photo 下载。
- K grouped media 每个子项使用自己的 `data-mid/data-peer-id`。
- K document/audio/voice/gif/round/image 能以真实 type 出现在资源列表。
- popup 批量下载只传 resourceIds，content 回查完整资源。
- 下载链路不再默认 mp4 / VIDEO。
- A 版现有 worker/mediaHash 功能不回退。
