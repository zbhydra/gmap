# 019 · X 页面下载进度与可控 E2E

## 1. 目标

让 X/Twitter 页面媒体按钮与 action bar 按钮在本地下载期间禁用并显示可信的当前资源反馈，同时保持共享下载架构简单：同 tweet 互斥、不同 tweet 并发、批量局部失败继续、路由切换不取消下载。

## 2. 非目标

- 不为 Popup 增加百分比。
- 不新增 Scheduler、Queue、DownloadStateManager、取消、暂停、恢复或跨页面任务状态。
- 不新增 RPC method、动态事件、依赖、依赖注入或 Chrome 权限。
- 不用 HLS segment 数、定时器或动画伪造百分比。
- 不使用真实 X 登录态作为自动化门禁。

## 3. 依赖

- 现有 X DOM scanner、network capture、MP4/HLS 下载与页面按钮。
- 共享 `downloadOne` / 顺序 `downloadMany` 和固定 EventRpc。
- Plan 016 的固定不可信 DOM transport 边界。
- 现有 Playwright `extension-e2e-ui` unpacked-extension fixture。

## 4. 已确认决策

- action 批量文案为当前项/总项数 + 当前项进度，例如 `1/2 50%`。
- 媒体按钮固定 36×36；action slot 固定 68px，空闲 36×36 居中，批量忙碌固定 68×36。
- 缺 `Content-Length` 与 HLS 全程显示 `…`；数字百分比向下取整。
- 网络读取最高 99；只有调用 `a.download.click()` 后报告 100。
- 同 tweet 所有页面入口禁用；媒体触发时 action 保留禁用图标，action 触发时当前媒体与 action 同步进度。
- 单项失败立即恢复；批量失败项不阻止后续项，整条 tweet 保持锁定直到全部项处理完。
- 不同 tweet 可同时下载；SPA 路由变化不取消既有下载。

## 5. 改动范围与文件责任

- `core/protocol/injected.ts`：进度 payload 允许 `number | null`。
- `core/downloadProgress.ts`：共享出口接受 `number | null` 并约束数值范围；X 的 floor 留在字节读取与按钮展示层，不改变 Telegram 的小数进度。
- `core/injected/responseBlob.ts`：按可用 `Content-Length` 流式读取，初始 0、floor、99 上限；未知长度或可见非 identity 编码不伪报。
- `sites/x/injected/download.ts`：请求开始发 `null`，保存触发后发 100；HLS 不发 segment 百分比。
- `sites/x/content/index.ts`：只消费当前 session 的资源事件，接受 `null`。
- `sites/x/content/buttons.ts`：每 tweet 简单 session、发起 route key、入口同步和当前项/总项数文案。
- `sites/x/content/styles/buttons.css`：36/68px 稳定尺寸、禁用/忙碌/可访问状态。
- `tests/unit/x-download-service.spec.ts`、`tests/unit/x-media.spec.ts`：进度和 session 边界。
- `tests/helpers/x-controlled.ts`、`tests/e2e/x-download-progress.spec.ts`：受控 X 文档、两块媒体流、真实浏览器下载与局部失败。
- `playwright.config.ts`：把 X controlled spec 纳入 `extension-e2e-ui`。
- 下载域与架构域活跃文档、changelog、`extension/tests/README.md`：同步最终合同和实际验证。

4. 固定 action slot 与忙碌按钮尺寸，检查亮暗背景、禁用态、焦点、窄视口和无布局跳动。

## 9. 风险与回滚

- 页面事件可伪造：影响限制在当前 tweet 按钮文字，不影响额度、RPC、保存或权限。
- 非 identity `Content-Encoding`：能从 fetch 响应头观察到时强制 `null`；不推断页面不可见 header。
- 流式读取会在内存保存 chunk：沿用当前 Blob 下载行为和 HLS 768MiB 上限，不新增磁盘缓存。
- X DOM 变化：受控 E2E 固定内部合同，生产兼容失败允许刷新/重试并从 scanner/anchor 日志定位。
- 回滚时整体移除 X 事件消费和 busy UI；不回退已有 X 扫描、MP4/HLS 下载或 Telegram 进度。
