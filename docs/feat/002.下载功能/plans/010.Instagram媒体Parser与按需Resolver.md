# 010 · Instagram 媒体 Parser 与按需 Resolver

## 1. 目标

建立简单的媒体 parser 和按需 resolver，把 Instagram 页面数据转成当前路由资源 Map 可直接使用的 `MediaResource`。

数据来源按顺序使用：页面 fetch/XHR 的结构化 JSON、document 内 embedded JSON、用户点击时请求同源 permalink。图片从 `image_versions2.candidates` 选择最高有效分辨率，视频从 `video_versions` 选择有效 MP4，Carousel 按 `carousel_media[]` 原顺序返回全部媒体。

DOM 图片、`srcset`、背景图、poster、`blob:` 和 `data:` 只用于定位内容，不能生成下载资源。

## 2. 非目标

- 不硬编码 Meta 私有 GraphQL `doc_id` 或 query hash。
- 不读取、序列化或上传 Cookie。
- 不把页面 JSON、媒体 URL 或解析结果发送到本项目后端。
- 不自动循环请求，不扫描未加载的无限列表。
- 不合并并发点击；每次点击可以独立请求。
- 不增加依赖注入。

## 3. 依赖

- Plan 009：PageContext 与当前路由资源 Map。

## 4. 改动范围

- 新增 `extension/src/sites/instagram/media.ts`，以纯函数解析 Post、Carousel、Reel、Story 和 Highlight 数据。
- 新增 `extension/src/sites/instagram/content/resolver.ts`，按 shortcode 请求同源 `/p/` 或 `/reel/` 页面并解析正文。
- 修改 Instagram network capture，只在 MAIN 保存当前 document 的有限结构化媒体数据；在现有 EventRpc request-response 上增加 `getCapturedMedia`，content 需要 entity 时主动调用，不使用推送事件。
- 资源 ID 使用 Instagram media ID；缺失时使用 `shortcode + ordinal + media kind`，不包含 signed URL。
- Reel 视频进入主资源数组；封面只在页面菜单点击时单独构造，不写入当前路由 Map。
- 每次成功解析直接覆盖 Map 中对应 entity 的整个资源数组；坏项记录日志后跳过，全部失败才返回空结果。
- 解析失败不写 Map，用户再次点击时重新执行 resolver；成功结果在当前页面 key 内直接复用，signed URL 失效时由用户刷新页面重新获取。

## 5. 执行步骤

1. 用固定 JSON fixture 完成图片、视频、Carousel、Reel 和 Story parser。
2. 增加 HTTPS、Meta CDN host、MIME 和媒体类型校验。
3. 接入 embedded JSON，并让 resolver 通过现有 EventRpc request-response 查询有限 network capture。
4. 实现同源 permalink resolver。
5. 把解析结果写入当前路由资源 Map，删除 DOM 到下载资源的旧路径。

## 6. 验收标准

- [x] 图片、视频和 Carousel 解析结果类型、顺序、URL 与文件名正确。
- [x] Reel 主资源始终是视频，封面不能替代视频。
- [x] signed URL 改变时资源 ID 不变，Map 中值被直接更新。
- [x] permalink 解析失败时不下载缩略图，也不调用额度接口。
- [x] 非 HTTPS、非允许 CDN、错误 MIME 和缺失字段被拒绝并打印详细错误。
- [x] 重复点击可以发起独立请求，任何一次失败不锁住后续点击。
- [x] 无后端解析、Cookie 上传、私有 GraphQL 固定参数或依赖注入。

## 8. 失败与回退

- permalink 返回登录墙、限流或不完整数据时，当前点击失败并允许用户再次操作。
- capture 解析错误不能影响页面原 fetch/XHR 结果。
- 本阶段可回退新的 capture 与 resolver 接线，但只能显示无法解析，不能重新启用缩略图下载。
