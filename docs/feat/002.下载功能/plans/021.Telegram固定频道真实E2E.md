# 021 · Telegram 固定频道真实 E2E

## 1. 目标

使用 `https://t.me/hydra_test_channel/13?single` 建立可重复的真实 Telegram 验收，覆盖 A/K 聊天区下载、A 频道资料侧边栏下载，以及下载按钮和相册复选框是否位于正确容器。

## 2. 固定数据

| 项 | 值 |
|---|---|
| 频道用户名 | `hydra_test_channel` |
| A peer | `-1003768618383` |
| K peer | `-3768618383` |
| 相册父消息 | `12` |
| 下载目标子消息 | `13` |
| K 父消息 DOM ID | `4294967308` |
| K 目标子消息 DOM ID | `4294967309` |
| A 页面 | `https://web.telegram.org/a/#-1003768618383` |
| K 页面 | `https://web.telegram.org/k/#@hydra_test_channel` |

消息 13 是相册父消息 12 的第二项。A 使用原始消息 ID；K 的 `data-mid` 使用 `2^32 + messageId`。A 与 K 是独立客户端、各自维护独立 MTProto session，登录态互不共享，仅共用固定绝对 profile `extension/tests/logs/test-user-data-telegram` 目录；setup 用同一个 fresh owner Page 按 A → K 顺序分别确认两版登录。

## 3. 实现方案

1. `tests/helpers.ts` 集中声明固定频道、A/K 版本 DOM 身份和 A 侧边栏身份。
2. 每条 test 开始时先关闭持久化上下文遗留的普通页和 Telegram 页，再创建 fresh page，结束时关闭本 test 页面；遗留页关闭成功是正常清理，只有关闭失败才报错并要求重试。页面内精确等待父消息、两个原生媒体、两个 `data-album-item` 复选框和父消息按钮。
3. `telegram-real-scan.spec.ts` 断言按钮属于消息内容容器、DOM 顺序位于相册之后；复选框属于各自真实相册项，并以边界框验证 24px、右下 8px。
4. `telegram-real-download.spec.ts` 在 A/K 中取消索引 0，只保留消息 13 对应索引 1，监听真实 download 并保存非空视频。
5. `telegram-real-sidebar.spec.ts` 打开 A 频道资料，断言消息 13 按钮 28×28、右下 6px、`DOWNLOAD ALL (3)`，再点击单项按钮保存非空视频。
6. 三条真实下载只 route 固定 `/api/client/quota/check` 为允许，并断言每条用例恰好调用一次；不消耗线上账号每日额度，也不依赖配额异常的 fail-open。
7. `extension-e2e-telegram-real` 单用例总超时为 300 秒；页面等待继续使用 locator/expect 自动等待，不使用 fixed sleep。
8. Playwright 使用 `fullyParallel=false`、`workers=1`，所有 Telegram project 固定
   `retries=0`。

## 4. 非目标

- 不自动登录 Telegram，不读取或提交账号凭证。
- 不 mock Telegram 页面、媒体、Chrome API 或下载链路。
- 不依赖真实后端账号的剩余额度；配额接口是唯一受控边界，其他后端请求不拦截。
- 不新增依赖、依赖注入、测试后门、扩展权限或业务 RPC。
- 不以 Telegram 页面自身 console/pageerror 为失败条件；功能合同和下载副作用才是验收信号。
- 不覆盖用户并行的 Instagram、X、Vimeo 或 Edge 开发脚本改动。

## 5. 验收标准

- [x] A 聊天区精确识别消息 12/13，按钮和两个复选框位置正确。
- [x] K 聊天区精确识别消息 12/13 及偏移 DOM ID，按钮和两个复选框位置正确。
- [x] A 取消子项 12 后只下载子项 13，保存非空视频。
- [x] K 取消子项 12 后只下载子项 13，保存非空视频。
- [x] A 侧边栏消息 13 单项按钮位置、批量数量和真实视频下载通过。
- [x] popup 读取固定频道 K 资源通过。
- [x] `pnpm check`、`pnpm build`、profile 快速校验和完整 real project 通过。

## 6. 验证命令

```bash
cd extension
pnpm check
pnpm build
pnpm test:setup
pnpm exec playwright test --project=extension-e2e-telegram-real --reporter=list
```

## 7. 已确认结果

- A/K 聊天区布局用例分别使用真实页面通过。
- A/K 聊天区下载在同一轮运行中 2/2 通过，均保存真实视频。
- A 侧边栏在等待 hover CSS 过渡后通过 28×28、右下 6px 和真实下载验收。
- A 当前原生媒体 ID 位于插件复选框插入容器内部，测试通过 `data-album-item` 反向定位真实容器，不猜测 Telegram 外层类名。
- 首次完整串行运行是 5/6：前两次下载消耗共享 profile 的线上免费额度，侧边栏点击显示升级弹窗。测试随后只固定单项配额接口为允许，并断言每项恰好一次配额 RPC。
- 修正后 `extension-e2e-real` 完整串行 6/6 通过，耗时 55.4 秒；A/K 聊天和 A 侧边栏各保存一个 1,608,127 字节的真实视频。

## 8. 风险与恢复

- 固定频道被删除或消息 12/13 被修改时，helper 输出分享链接、版本、URL、DOM ID 和选择器；恢复 fixture 后重跑。
- Telegram A/K DOM 更新时，优先更新集中 fixture，不在各 spec 内增加分散 fallback。
- 登录态过期时执行 `pnpm test:setup`；setup 用唯一 fresh owner Page 按 A → K 顺序确认或
  等待登录，两版都 ready 后关闭。
- 外部网络失败允许重跑；不能把真实失败改成 mock 通过。
- 线上额度耗尽不会阻断真实媒体验收；若配额 route 未调用或重复调用，测试按生产 RPC 合同失败。
