# 028. Telegram K WebPage 预览媒体下载

> 状态：待批准。与 027 分别补齐 K 数据分派和 A no-article DOM identity，可独立实施；真实验收必须串行复用唯一 Telegram owner Page。

## 背景

真实页面已确认 A WebPage photo 会生成下载按钮；K 对同类链接没有按钮，无法进入下载验证。当前 `KVersionScanner` 已能从 WebPage 渲染结果收集 DOM 候选和消息身份，但 `KMediaResourceService.getKMediaResource` 只处理 `messageMediaPhoto` / `messageMediaDocument`，`messageMediaWebPage` 返回 null，`buildResources` 因没有内部确认资源而跳过按钮注入。

K 上游数据和 DOM 已提供完整输入：

- `bubbles.ts` 从 `messageMediaWebPage.webpage` 读取 `document` 与 `photo`；有 document 时优先渲染，video/gif/round 走 `wrapVideo`，其它类型走 `wrapDocument`，只有无 document 时才渲染 photo。
- `wrapDocument` 直接读取 `webpage.document`。该对象与主消息 Document 同构，包含 stream URL 所需的 access hash、file reference、DC 和 size。
- photo/video/document 渲染结果均命中现有 `kMediaCandidateSelector`；`KVersionScanner.buildResource` 已支持 PHOTO 使用 DOM URL、Document 使用 injected stream URL。

缺口只在 K 数据入口没有分派 `messageMediaWebPage`。

## 目标

- WebPage 无 document 且有 photo：下载当前 DOM 图片，与 A 的显示尺寸口径一致。
- WebPage 有 document：复用 K 现有 Document 下载合同，下载 video/gif/round/file/audio/voice/image 等原文件。
- document 与 photo 并存时遵循 K 渲染优先级，只产出 document 资源。

## 非目标

- 不改 A 版行为；A 的 no-article Document identity 由 027 处理。
- 不做 mediaViewer 级大图；WebPage photo 仍使用 DOM 已加载图片。
- 不新增重试、fallback、DOM 选择器、RPC 或下载协议。

## 方案

只修改 `extension/src/sites/telegram/injected/services/KMediaResourceService.ts`：

1. 为内部 `TelegramMessageMedia` 补充类型化 `webpage` 字段。
2. 将当前 PHOTO 内部资源映射收敛为 service 内唯一构造入口，供主消息 photo 与 WebPage photo 复用。
3. 将当前“归一化 Document → 构造 stream URL → 返回内部资源”收敛为 service 内唯一构造入口：
   - 主消息 `messageMediaDocument` 仍先执行 `selectBestDocument`，再进入该入口；
   - WebPage document 没有 `alt_documents`，直接进入同一入口。
4. `getKMediaResource` 增加 `messageMediaWebPage` 分派：有 document 时返回通用 Document 资源；否则有 photo 时返回 PHOTO 资源；其余返回 null。

不增加 VIDEO/GIF/ROUND 白名单。Document 类型已由 `TelegramDocumentMetadata` 统一分类，WebPage 再设白名单只会重复并收窄现有合同。

行为矩阵：

| 消息形态 | 当前 | 方案后 |
| --- | --- | --- |
| WebPage photo | 不注入 | 注入按钮，下载 DOM 图片 |
| WebPage video/gif/round document | 不注入 | 注入按钮，stream 下载原文件 |
| WebPage file/audio/voice/image document | 不注入 | 注入按钮，stream 下载原文件 |
| WebPage document + photo | 不注入 | document 优先，stream 下载原文件 |
| 主消息 photo/document | 现有行为 | 复用同一构造入口，行为不变 |
| 无 photo/document 的 WebPage | 不注入 | 不注入 |

## 验收标准

1. 固定频道现有 WebPage photo 消息在 K 版生成按钮，下载得到当前 DOM 图片。
2. 固定消息 26 在 K 版生成按钮并下载原 PDF：900109 字节、SHA-256 `f0ca428c3a03350088ca78aba9b24dee3bcbac23ecbfa07a0eac4260db09f04b`。
3. 主消息 photo/video/document/audio 的现有按钮和下载行为不变。

当前没有真实 WebPage video 样本，不为其制造假设性 E2E；video 与消息 26 走同一个 WebPage Document 构造入口，既有 K 主消息/相册 video E2E 已覆盖同一 stream builder。

## 验证方式

- 在 `telegram-real-download.spec.ts` 增加两条直接验收路径：一个 WebPage photo DOM 下载、一个消息 26 Document stream 下载。不在 `telegram-real-scan.spec.ts` 增加只证明按钮存在的重复用例。
- 每条 Telegram 真实测试开始时先关闭遗留 Telegram 页面，再创建唯一 fresh owner Page，结束时关闭；A/K 用例串行执行，任何时刻不得同时存在两个 Telegram 页面。
- 在 `extension/` 运行 `pnpm test:unit:run`、`pnpm check`、`pnpm build`，实际启动 `pnpm dev`，再运行目标真实 E2E。

## 已知限制

- WebPage photo 是 DOM 当前显示尺寸，不承诺 mediaViewer 原图。
- WebPage Document 的 file reference 过期风险与主消息 Document 相同；当前项失败后由用户重试，不增加恢复机制。
