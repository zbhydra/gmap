# 012 · Instagram 集合页与 Grid 直接下载

## 1. 目标

让 Profile、Profile Reels、Explore、Search 和 Hashtag Grid 的卡片按钮在当前页面直接下载原媒体，不跳转详情页。

卡片只提供 shortcode 和内容类型。点击后先查询当前路由资源 Map；没有非空资源数组时调用 permalink resolver。单图下载原图，Reel 下载 MP4，Carousel 按原顺序逐项下载全部主媒体。

## 2. 非目标

- 不自动加载未滚动到的卡片。
- 不遍历整个账号、搜索结果或话题。
- 不下载卡片缩略图、poster 或背景图。
- 不自动打开详情页。
- 不实现 Popup 或共享下载函数。
- 不增加依赖注入。

## 3. 依赖

- Plan 010：媒体 parser 与按需 resolver。
- Plan 011：按钮扫描与渲染基础。

## 4. 改动范围

- 扩展 `scanner.ts`，识别 `/p/{shortcode}`、`/reel/{shortcode}` 和 `/reels/{shortcode}` 卡片。
- 扩展 `buttons.ts`，在 Grid 卡片上增加一个实体级下载按钮。
- Grid 按钮点击处理直接执行“查 Map -> 必要时调用 resolver -> 逐项下载”，不增加 Grid 专用下载 service。
- 当前集合路由中，已经滚动发现并成功解析的资源保留在同一个 Map；离开该路由后由 Plan 009 清空。
- Grid 按钮只传 shortcode，不保存缩略图 URL。
- resolver 或某个 Carousel 项失败时打印错误；已经解析出的其他项仍可进入后续单项下载流程。

## 5. 执行步骤

1. 增加五类集合页卡片 fixture 和保留路径负向样本。
2. 实现 shortcode 提取与 Grid 按钮挂载。
3. 接入当前路由资源 Map 查询。
4. 接入 permalink resolver，并覆盖单图、Reel、Carousel。
5. 验证虚拟滚动节点移除后 Map 仍保留已发现资源，切换集合路由后清空。
6. 删除旧的 Profile Reel poster 下载断言。

## 6. 验收标准

- [x] Profile、Profile Reels、Explore、Search 和 Hashtag 卡片均可直接触发下载。
- [x] 已有完整数据时不额外请求 permalink。
- [x] 只有 shortcode 时可解析单图、Reel 和完整 Carousel。
- [x] 下载过程中不导航、不打开详情弹窗。
- [x] 卡片 thumbnail、poster、背景图从不进入下载请求。
- [x] 某项解析失败不阻止其他已解析项。
- [x] 离开集合路由后旧资源不再提供给页面或 Popup。

## 7. 验证命令

```bash
cd extension
pnpm test:unit:run -- tests/unit/instagram-surfaces.spec.ts tests/integration/instagram-buttons.spec.ts tests/integration/instagram-permalink-resolver.spec.ts
pnpm check
pnpm build
```

## 8. 失败与回退

- permalink 失败时当前卡片显示失败，用户再次点击即可重新解析。
- 虚拟滚动导致按钮节点消失时只在节点重新出现后重新挂载，不主动滚动页面。
- 本阶段可回退 Grid 按钮接线；不得回退为点击缩略图下载或自动导航详情。

## 9. 实施记录（2026-07-11）

- Grid 页面分派、permalink 解析、原媒体顺序与不导航行为由 surfaces/buttons/resolver 测试覆盖。
- 当前实现没有 DOM thumbnail/poster/background 到 `MediaResource` 的构造路径。
