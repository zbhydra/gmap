# 018 · Instagram 文档与发布收口

## 1. 目标

在功能和测试全部通过后删除旧 Instagram 路径，同步活跃文档，并用最终生产 Manifest 和真实 Canary 完成发布前检查。

最终文档只描述简单结构：`PageContext -> routeMediaStore Map -> parser/resolver -> buttons/Popup -> downloadOne/downloadMany -> fixed EventRpc`。

## 2. 非目标

- 不在收口阶段增加页面、媒体类型或备用下载源。
- 不开启 Threads/Vimeo。
- 不保留新旧两套实现或长期 feature flag。

## 8. 验证命令

```bash
cd extension
pnpm rpc-generate:check
pnpm test:unit:run
pnpm test:coverage
pnpm check
pnpm build
pnpm test:e2e:ui
pnpm test:e2e:instagram:controlled
pnpm test:e2e:real
pnpm test:e2e:instagram
```

仓库根目录执行：

```bash
rg -n "downloadMediaBatch|handleBatchDownload|RPC_HANDSHAKE|HMAC" extension/src extension/tests
rg -n "Threads.*enabled|Vimeo.*enabled|DOM.*主.*MediaResource" docs extension/src
```

所有命中必须逐项核验；旧业务定义、旧能力说明和错误发布状态都会阻止发布。

## 9. 失败与回退

- 删除旧文件后发现漏用例时，修正最终模块，不重新接回旧路径。
- 真实 Instagram 环境失败时记录明确分类；可控 E2E 必须继续通过。
- Telegram 或 X 回归失败时停止发布并修正共享改动，不增加站点特例。
- 发布需要回退时使用上一稳定完整构建；本轮没有数据库或 storage 数据迁移。
