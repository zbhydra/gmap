# 020 · Telegram 真实 E2E 测试 Profile 初始化入口

## 1. 目标

提供一个可重复执行的命令，为所有 Telegram 测试入口初始化固定 Chromium profile：使用唯一 fresh owner Page 按 A → K 顺序确认登录，任一版本未登录时等待人工完成，A/K 都 ready 后正常关闭并保存登录态。

## 2. 非目标

- 不自动输入手机号、验证码、二次验证密码或操作二维码。
- 不同时打开 A/K 两个 Telegram 标签页，不并发验证两版登录态。
- 不把 profile、账号或登录凭证提交到仓库。
- 不新增依赖、Chrome 权限、RPC method、依赖注入或业务测试后门。
- 不在本阶段实现真实 Telegram 下载与按钮位置的新 E2E 用例。

## 3. 已确认决策

- setup、real、ad-assets、manual 与 verify 固定使用同一个绝对 profile：
  `extension/tests/logs/test-user-data-telegram`，不提供 profile 参数或环境变量。
- `pnpm test:setup` 是 Telegram profile 初始化入口。
- 每次执行先 fresh build 当前源码，再加载 unpacked `dist`。
- 启动后尝试关闭恢复出的普通页和 Telegram 页，再创建唯一 fresh owner Page。
- owner Page 先进入 `https://web.telegram.org/a/`；A 在 `.Auth` 不可见且
  `#Main #LeftColumn-main` 可见后等待 5 秒复查。确认或等待 A 登录后，同一 Page 导航 K；
  K 在 `#auth-pages` 不可见、
  `body.has-auth-pages` 已移除且 `#page-chats` 可见，等待 5 秒复查仍成立时才算登录成功。
  验证阶段任一时刻只有一个 Telegram Page。
- A 与 K 是 Telegram Web 的两个独立客户端（分别基于 gramjs 与 TDLib），各自维护独立的
  MTProto session，登录态互不共享，仅共用浏览器 profile 目录；setup 必须按 A → K 顺序
  分别验证两版登录，两版都 ready 后自动关闭并成功退出。
- 日常 Telegram E2E 直接读取固定 profile，不重复运行 setup。

## 4. 改动范围与文件责任

- `extension/scripts/setup-telegram-test-profile.mjs`：构建、启动持久化 Chromium、加载扩展、顺序识别 A/K 登录状态和处理退出。
- `extension/package.json`：提供 `test:setup` / `test:setup:telegram` 命令。
- `extension/tests/fixtures.ts`：让所有 Telegram project 使用固定 profile。
- `extension/tests/README.md`、客户端测试规范和插件 E2E 文档：同步命令、目录与恢复步骤。

## 5. 验收标准

- [x] 空 profile 先打开 Telegram A 登录页并持续等待；A 达到稳定登录终态后同一 Page 导航 K。
- [x] A/K 任一版本未登录时等待人工完成，两版都达到稳定登录终态后自动关闭 Chromium 并保存登录态。
- [x] 再次执行同一命令仍按 A → K 顺序确认两版可用后成功退出。
- [x] setup 验证阶段任一时刻只有一个 owner Page，并在创建前关闭恢复页。
- [x] setup、real、ad-assets、manual 与 verify 使用同一个固定绝对 profile。
- [x] 旧 `test-user-data` 不被删除、移动或覆盖。
- [x] `pnpm check`、`pnpm build` 和脚本启动验证通过。

## 6. 验证命令

```bash
cd extension
node --check scripts/setup-telegram-test-profile.mjs
pnpm check
pnpm build
pnpm test:setup
```

## 7. 风险与恢复

- Telegram 登录 DOM 更新：状态识别依赖 A 的 `.Auth` / `#Main #LeftColumn-main` 与 K 的
  `body.has-auth-pages` / `#auth-pages` / `#page-chats`；失效时重新执行 setup。
- 登录中断：重新执行同一命令继续使用原 profile，不做清理和回滚。
- profile 被 Chromium 占用：关闭使用该目录的浏览器后重试。
- 登录态过期：重新执行 `pnpm test:setup`，在原 profile 中完成登录。

- 2026-07-12（旧行为）setup 只验证 Telegram A；A 出现 `#MiddleColumn` 后关闭 Chromium，
  K 在后续真实 E2E 中复用该 profile 登录态。
- U14 起 setup 改为唯一 fresh owner Page 按 A → K 顺序验证，两版都 ready 后才关闭。
- A 的本地 session 可能先渲染 Main，K 的初始 HTML 也包含隐藏应用壳；setup 因此核对
  登录壳与可见应用节点，命中后等待 5 秒复查一次。真实可用性由紧随其后的 A/K
  smoke 验证，失败时重新执行 setup。
- 所有 Telegram setup、real、ad-assets、manual 与 verify 入口固定使用同一个
  `extension/tests/logs/test-user-data-telegram`。
- 当前脚本已通过 `node --check`、Prettier 与 `git diff --check`；profile 与真实 Telegram
  smoke 在人工登录后执行。
