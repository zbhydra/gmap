## 功能目标

让用户在 website 输入一条媒体链接,系统完成:解析资源 → 授权下载并扣积分 → 在执行节点上把文件交付给用户。三种交付模式统一入口:

- **服务器代理(proxy)**:节点把文件以流的形式返回给前端。
- **客户端直连(direct)**:节点返回平台 CDN 直链,前端自行请求 CDN。
- **客户端合成(client_mux)**:节点返回独立的音视频轨道,前端合成。

下载链路是**通用媒体下载授权控制面**,不是 TG 专用;X、Instagram、Threads、Reddit、Douyin 等平台都走同一条链路。执行节点(角色、调度、健康、管理、发布)由节点系统域提供,见 `@../001.节点系统/feat.md`;扣费规则与积分余额见 `@../003.积分系统/feat.md`。

## 功能范围

### 包含

- 统一 V2 下载流程:解析入口 → 解析执行 → 下载授权 → 下载执行四个阶段。
- 下载授权 token:业务服务器扣额度后签发,执行节点只验签执行。
- 三种下载模式统一入口(proxy / direct / client_mux)。
- 下载 token 的语义、有效期分档、多公钥验签、签名轮换。
- V2 接口规格:解析入口、解析执行、下载授权、下载执行四个接口的请求/响应/错误码。
- 速率治理(下载链路上的速率与并发约束)。
- 后端媒体 Provider 架构:统一 parse/download 契约、每平台一个 Provider、proxy 生命周期释放。
- website 前端 V2 切换:行为、超时、错误处理、灰度。
- 文件过大保护(4GiB 上限)、登录态校验、扣积分去重。
- X/Twitter 页面媒体按钮与推文 action bar 下载按钮的下载中反馈：按钮禁用，显示当前资源进度或不可计算状态。
- 扩展 Popup 当前标签页下载状态：顶部按任务状态显示数量与进度；列表保留失败项并提供人工重试，按任务快照中的取消能力和指标数据展示取消、文件大小与速度。
- Telegram 页面右下角下载管理入口：显示当前页面未完成任务数量，悬浮、聚焦或点击后查看队列、资源文件名、文件大小、下载速度和取消操作。
- Telegram 当前页面内等待任务可移除，下载中任务只在明确支持中止时提供取消；操作只影响指定任务，不清空队列。
- Telegram A/K 大文件保持现有下载入口、进度、队列和取消；浏览器支持站点临时存储时，大文件不在页面内存中聚合完整内容。
- Telegram 资源列表显示文件名、大小、视频或音频时长和当前资源封面；网页预览中的文件与普通消息附件使用各自身份，不互相猜测。
- Telegram 页面打开时读取一份全局 DOM 覆盖；插件包内保留完整默认值，服务端只需填写发生变化的少量项。

### 不包含

- 节点角色模型、按角色组装路由、节点与 session 绑定、健康检查、节点管理 CRUD、节点发布配置 → 见 `@../001.节点系统/feat.md`。
- 积分余额查询、扣费规则、订单/订阅 → 见 `@../003.积分系统/feat.md`。
- 各平台解析差异(TG session、X / Instagram Cookie、Reddit/Douyin 平台识别)→ 各站点下载功能文档。
- 下载 token 一次性消费(有效期内允许重复下载)。
- 下载中单条 TCP 连接中途自动迁移到其他节点。
- 下载字节缓存、转码缓存、对象存储落盘。
- 依赖 Cloudflare Load Balancer(节点列表由业务服务器返回)。
- 未在各站点扩展端技术文档中定义的其它插件本地下载能力；本轮 X 只增加页面瞬时进度与对应读取反馈，不扩展资源发现或媒体类型。
- 跨标签页聚合、页面刷新后的任务恢复、暂停、手动重排和下载历史；活动取消只提供给任务快照明确声明可中止的传输。
- 节点级"支持哪些平台 / 下载模式"的能力配置:所有节点统一暴露接口,缺本地 cookie/session/平台配置或执行依赖时由节点返回不可用,客户端试下一个。
- 下载过程中单次请求的自动迁移:客户端只在节点超时、连不上、DNS/TCP/TLS 失败、网关不可达或返回节点不可用时换下一个。
- Telegram DOM 配置不按插件版本分组，不包含配置历史、回滚、发布状态、定时刷新、页面内轮询或跨页面持久缓存；未来 AI 自动巡检和自动写入另行规划。

## 业务流程

### 主流程(下载)

1. 用户在 website 输入媒体链接,前端调解析入口取得有序解析节点列表(最多 3 个)。解析不强制登录。
2. 前端按顺序请求解析节点执行解析,成功后得到资源信息(平台、下载模式、source_id、文件大小、canonical_link、resource_token),并记住这次解析成功用的是哪个节点。
3. 用户点击下载 → 前端调下载授权入口。下载授权**必须登录**(未登录前端直接打开登录弹窗,不调用)。业务服务器做额度判断与扣积分,签发下载授权 token,返回下载节点列表(最多 3 个)。
4. 前端按顺序请求下载节点执行下载,按下载模式得到文件流 / 直链 / 音视频轨道。

### 节点切换(异常分支)

- 当前节点超时、连不上、DNS/TCP/TLS 失败、网关不可达或返回节点不可用 → 尝试下一个节点。
- 明确业务错误(token 无效/过期、资源不存在、权限不足、文件过大)→ 不换节点,直接失败。

### 扣积分

下载授权时按用户积分口径扣减;同一用户同一资源 6 小时内只扣一次。积分余额与扣费规则见 `@../003.积分系统/feat.md`。

### 文件过大保护(异常分支)

- 业务服务器:已知文件大小超过 4GiB → 直接拒绝签发下载 token。
- 执行节点:执行前重新解析真实大小,超过 4GiB → 拒绝。
- 未知大小:只允许从头流式下载,累计发送字节达到 4GiB 上限立即中断。

### 解析节点亲和(优化分支)

前端把成功解析的节点 id 作为亲和提示传回下载授权;该节点仍在候选池时排第一,否则忽略。这只是排序提示,不是鉴权材料。

### 私有频道(分支)

沿用现有扩展引导边界:节点解析返回"需要客户端"时,前端走扩展引导,不继续试节点。

### Telegram DOM 兼容(分支)

1. 用户打开或刷新 Telegram 页面，插件读取一次服务端 DOM 覆盖，同时完成页面下载能力的初始化准备。
2. 服务端返回空对象或缺少某项时，该项继续使用当前插件包内默认值；返回当前插件不认识的多余项时直接忽略，不影响初始化。
3. 读取失败时整页使用插件包内默认值继续启动，不重试、不阻断下载功能。
4. 管理员更新配置后，已经打开的 Telegram 页面不热更新；用户刷新页面后重新读取。

### Telegram 本地任务管理(分支)

1. 用户可从 Telegram 页面下载管理列表或 Extension Popup 取消指定任务；两处操作同一个当前 document 队列。
2. 真实下载失败保留在任务列表并继续执行后续等待项；用户可从页面列表或 Popup 人工重试，重试项从头开始并排到 FIFO 尾部，且不重复消耗下载额度。
3. Telegram 页面可一次清空全部等待项，或清除等待与失败项并取消当前活动项；当前活动项在本地接受取消后立即从页面与 Popup 消失。
4. 等待中任务尚未进入额度检查，取消后立即从队列移除，不消耗额度，也不影响其它任务顺序。
5. 下载中任务由本地队列接受取消后立即移除、完成本次调用并继续下一项；底层取消和资源清理仅后台尽力执行，其结果不改变本地取消终态。
6. 下载中任务可能已经发出额度检查。取消不承诺撤销已经发出的额度请求；额度检查一旦成功，取消不退款。
7. 取消不是下载失败或额度不足，不显示失败提示；用户可以重新点击原下载入口创建新任务。
8. 不小于 200 MiB 的分块下载在浏览器支持时使用站点临时存储；不支持时沿用内存下载。两种存储方式不改变用户入口、进度、取消或任务顺序。
9. 临时存储下载失败或取消时尝试清理当前文件；清理失败只记录，不恢复任务、不阻塞 FIFO。下载中关闭页面或浏览器后，下一次打开 Telegram 时尝试清理扩展临时内容，不恢复旧任务。
10. Telegram A 附件或网页预览文件首次点击时，若客户端仍在初始化或网络恢复后才取得文件信息，任务保持下载中并在信息到达后继续；用户无需重复点击，可通过取消退出等待。

## 非功能性需求

- 文件大小硬上限 4GiB。
- 下载 token 有效期按文件大小分档(1~6 小时);未知大小用 6 小时。
- 下载 token 支持多公钥验签,便于密钥轮换。
- 下载 token 有效期内允许重复下载(Range 续传、刷新重试、换节点续传复用同一 token)。
- 执行节点不连业务数据库也能完成验签和下载执行(降低部署成本和泄露半径),见 `@../001.节点系统/feat.md`。
- 解析和下载入口都返回最多 3 个健康、启用、权重大于 0 的统一候选节点;没有健康执行节点时可返回健康可用的业务节点兜底,候选池为空时返回节点不可用。
- 下载授权入口用用户短锁防双击并发;扣费去重以 Credits 下载记录的 6 小时窗口为准。
- 扩展同一 content 页面内所有入口共享一个 FIFO 下载列表，业务队列同时只有 1 个活动任务；已取消任务的底层请求可能在后台短暂收尾并与下一项重叠，不再用物理传输并发约束阻塞队列。
- Telegram 同一资源在未完成列表中只保留一个任务；重复提交等待同一任务，取消作用于该共享任务。
- Telegram 页面下载管理列表与 Extension Popup 只展示当前页面的运行时任务（含失败项），共享同一任务顺序和状态；页面刷新或关闭后不恢复。
- X 页面同一条推文只允许一个页面按钮下载会话；X SPA 路由切换不取消已经开始或等待中的下载。
- Telegram DOM 覆盖同时兼容多个已发布插件版本：不上传或判断插件版本，不要求服务端对象字段齐全，也不因多余字段拒绝配置。

## 验收标准

产品视角的关键验收(技术层验收见各 `tech-*.md`):

- 用户在 website 输入链接 → 点下载 → 拿到文件/直链/合成产物,三种模式都从统一执行端点返回。
- 所有 Download 按钮都走统一 V2 流程,不再走旧的解析/下载/intent 接口。
- 下载授权入口收到有效亲和节点 id 且该节点仍在候选池时,优先返回该节点。
- 下载授权必须登录;未登录前端打开登录弹窗,不发起请求。
- 同一用户同一资源 6 小时内重复点击下载只扣一次积分;扣费后响应丢失再刷新重试不重复扣费。
- 已知文件超过 4GiB 拒绝签发;未知大小流式累计达到 4GiB 立即中断。
- 下载 token 有效期内允许重复下载;token 过期后视为新的下载动作,重新走下载授权。
- 节点缺少本地 cookie/session/平台配置或执行依赖时,由节点本地接口返回节点不可用,前端试下一个节点。
- 解析/下载节点失败时前端按顺序试下一个;token 无效/过期时不换节点,引导重新授权。
- 前端不把完整 token 写入日志/埋点/控制台;平台 CDN 请求和 tracks 请求用 no-referrer 策略。
- 扣费后前端用响应返回的最新积分余额更新 UI,不再额外请求余额接口。
- X 页面下载按钮在下载期间不可重复点击；已知总字节数时显示向下取整的真实百分比，未知总字节数与 HLS 下载显示 `…`。
- X action bar 批量入口按“当前项/总项数 + 当前项进度”显示，例如 `1/2 50%`；单项失败不阻止后续项，结束或失败后按钮恢复可点击。
- X 页面只在浏览器保存动作已经触发后才允许显示 `100%`，不能把网络读取完成当作下载完成。
- 扩展同一页面的单项、批量、页面按钮和 Popup 下载按入队顺序执行，任意时刻最多 1 项下载中，其余项显示等待中；当前项失败后保留为失败并继续执行后续项。
- Popup 顶部入口按快照状态显示当前任务数量与进度；进度不可计算时显示 `…`。列表包含下载中、等待中和失败分组；失败项提供 28×28px 重试图标，waiting 始终可本地移除，活动任务只在快照声明可取消时提供取消。
- Telegram 页面下载管理入口的徽章数量与 Popup 未完成任务总数一致；同一任务的文件名、状态、进度、大小和速度在两处一致。
- Telegram Document 优先显示 Telegram 提供并经清理的原始文件名；来源未提供原始名称时显示插件最终用于保存的确定性生成名。
- Telegram 已知总大小时显示已接收字节和总大小，未知大小保持未知；分块下载继续显示实际字节与速度，A mediaHash 按已知大小和 Telegram 进度显示估算值。
- 各平台等待中任务取消后不调用额度检查并立即消失；具备取消能力的下载中任务在本地接受取消后同样立即消失并继续队列。底层取消失败不恢复任务，取消不显示为失败。
- Telegram A 附件或网页预览文件首次点击后，即使网络断开时只取得空文件信息，也不得立即失败；网络恢复并取得目标文件信息后沿原任务继续下载。
- 同一 Telegram 资源重复入队时，页面列表和 Popup 只显示同一个任务，并等待该任务的当前执行结果。
- 浏览器支持站点临时存储时，不小于 200 MiB 的 A progressive、K stream 和 Telegram HTTPS 资源下载期间，页面内存不随已下载字节线性增长；不支持时允许沿用现有内存行为。
- 下载进行时关闭再打开 Popup，仍能读取原 content 页面任务；页面刷新或关闭后不恢复旧任务。
- Telegram DOM 服务端配置为 `{}` 时，当前插件全部使用包内默认值；只覆盖一个已知项时，其余项仍使用包内默认值；包含旧客户端不认识的项时，旧客户端仍可启动并忽略该项。
- Telegram DOM 配置请求失败时，主消息、A 版侧栏和 A Story 仍按包内默认值启动；请求完成或失败前不提前绑定对应扫描与观察器。
- 管理员保存新的 Telegram DOM 覆盖后，刷新 Telegram 页面可读取新值；已打开页面保持本次打开时的配置，不发生中途切换。

## 用户操作逻辑与 UI 元素

> 本功能 UI 位于 website 下载入口、扩展 Popup 和站点页面注入入口。Telegram DOM 覆盖的管理入口位于 `@../008.管理后台/feat.md`；节点管理在 `@../001.节点系统/feat.md`。文案需 i18n。

### website 下载入口

- **链接输入框**:用户粘贴媒体链接。占位文案提示支持的站点。
- **解析按钮**:点击后调解析入口,加载中显示 loading;失败按错误类型展示(输入错误/不支持/需要客户端扩展/解析失败/解析暂不可用)。
- **解析结果区**:展示资源标题、所有者、文件名、大小(已知时)、缩略图;每个可下载资源一个 Download 按钮。
- **Download 按钮**:
  - 未登录点击 → 直接打开登录弹窗,不发起下载授权请求。
  - 已登录点击 → 调下载授权,加载中显示 loading。
  - 授权失败 → 按错误展示(积分不足引导升级/文件过大/下载暂不可用/登录失效重新登录)。
  - 授权成功 → 按 `download_mode` 处理:`proxy` 写入文件流到下载器/浏览器;`direct` 请求平台 CDN;`client_mux` 拉轨道并合成。
  - 授权成功后前端用响应返回的积分余额刷新 UI,不再额外请求余额接口。
- **下载状态/错误提示**:节点临时不可用自动试下一个;所有候选节点临时失败时聚合最后一个失败 code 展示下载失败;token 无效/过期引导重新点击下载。

### Extension Popup 下载状态

- **状态入口**：存在下载中、等待中或失败任务时显示在 Popup 顶部，固定为 72×32px；包含下载图标、当前与失败任务数量和当前项进度。已知进度显示向下取整百分比，未知显示 `…`；全部状态为空后入口隐藏。
- **任务浮层**：点击状态入口，在其下方展开 320px 宽、最高 360px 的浮层；标题显示任务总数，并按“下载中”“等待中”“失败”分组。失败行以错误色文字明确标记并提供 28×28px 蓝色重试图标按钮；waiting 和快照声明可取消的下载中任务提供同尺寸取消图标。文件名尚待队首解析时显示“获取文件名中…”。长文件名单行省略，悬停可查看完整名称。
- **大小与速度**：只在对应快照字段存在时显示。等待中任务只显示已知总大小；活动任务存在任一传输指标时显示已接收/总大小和速度。精确速度正常显示，估算速度增加 `≈`，单项缺失值显示 `--`。
- **取消按钮**：waiting 任务始终可本地移除；下载中任务只有快照声明可取消时才显示。按钮使用 `X` 图标和本地化可访问名称，不使用文字胶囊；点击后任务立即从列表消失。任务已经结束时允许返回未接受并刷新列表，不弹失败提示。
- **关闭交互**：再次点击入口、点击浮层外部或按 `Escape` 关闭；键盘关闭后焦点回到入口，入口具有可见焦点环与完整状态的可访问名称。
- **状态范围**：只展示 Popup 打开时固定目标标签页、当前 content 页面生命周期内的任务。关闭再打开 Popup 可恢复列表；页面刷新或关闭后不恢复失败项和其它任务，不提供下载历史。
- **执行顺序**：页面按钮、Popup 单项与批量入口共用同一 FIFO；失败项不占据活动位置，后续等待项继续。人工重试从头开始、恢复初始展示字段并排到队尾，不自动重试，也不重复消耗额度。

### Extension Popup 资源列表

- **资源行**：使用复选框、64×48px 封面、文件信息、大小和下载动作五列。文件信息第一行显示单行省略的文件名，第二行显示类型和存在时的时长；悬停文件名可查看完整内容。
- **大小与时长**：只显示来源已经提供的值；0 B 是有效大小，未知不显示伪造值。时长小于一小时显示 `m:ss`，一小时及以上显示 `h:mm:ss`。
- **封面**：只显示当前资源自己的可用封面；加载失败或来源未提供时在同一 64×48px 槽位显示类型占位，不改变行高或选择状态。
- **身份**：相册和同消息多资源只有在页面提供精确文件身份时才显示；网页预览同时提供文件和可识别链接时按该链接匹配自身元数据。候选不唯一或链接缺失时不猜测父消息或相邻资源，由用户重新操作其它明确入口。

### X/Twitter 页面下载入口

- **媒体下载按钮**：覆盖在图片或视频媒体面上的 36×36 圆形图标按钮。空闲时可点击；本推文正在下载时全部禁用。当前媒体显示向下取整的百分比，例如 `50%`；进度不可计算时显示 `…`；非当前媒体保留下载图标。
- **action bar 下载按钮**：位于推文原生 action bar 中。空闲时在 68px 宽的稳定槽位内居中显示 36×36 圆形图标；由该入口发起批量下载时变为 68×36 的进度胶囊，显示例如 `1/2 50%` 或 `1/2 …`。由媒体按钮发起单项下载时仅禁用并保留图标。
- **忙碌与恢复**：同一条推文的媒体和 action bar 按钮共同进入禁用、忙碌状态，不能重复点击；不同推文可以独立入队，但实际下载仍由页面 FIFO 单项执行。媒体单项失败立即恢复；action 批量某项失败时保持禁用并继续下一项，全部项处理完后恢复，由用户重试失败项。
- **页面切换**：X 站内路由切换不会取消已经开始的浏览器下载。原路由百分比不带到新路由；如果新路由再次出现同一推文，该推文仍保持禁用图标直到旧下载结束，不显示旧百分比。
- **Popup**：资源列表仍只展示当前 tab 可下载资源；顶部状态入口统一展示页面按钮和 Popup 发起的下载中/等待中任务。

### Telegram 页面下载入口

- **媒体下载按钮**：A/K 主聊天区的每张图片或视频都有 36×36 圆形图标按钮。单媒体位于右下角；相册按钮与该格复选框水平中心线对齐，并在复选框正上方保留 8px 间距。按钮即使越出超小相册格也不能被裁切。
- **显示方式**：桌面端默认隐藏，对应媒体悬停或按钮获得键盘焦点时显示；触屏设备常显。焦点环必须可见，减少动态效果偏好下不播放显隐过渡。
- **下载行为**：点击只下载按钮绑定的当前媒体，不读取或改变相册复选框，也不打开 Telegram 媒体查看器。下载期间按钮禁用并显示整数百分比；进度不可计算时显示 `…`，结束或失败后恢复图标。
- **大文件下载**：A/K 继续显示现有进度并允许取消；临时存储或内存只影响内部写入位置，不改变按钮行为。网页预览文件与普通附件保持独立身份。
- **相册与聊天切换**：每格按钮必须跟随当前活动聊天和媒体身份；A/K DOM 重建、聊天切换及相册格替换后自动恢复，不能把旧聊天中相同消息编号的状态带入新聊天。
- **A Story 下载按钮**：A 版 Story 弹层只显示一个 40×40 圆形图标按钮，绑定当前可见 Story。桌面空间足够时贴在媒体右下侧，空间不足时回退到媒体内部右下角，均与边缘保留间距；按钮常显、有可见键盘焦点环，减少动态效果偏好下不播放颜色过渡。
- **A Story 切换与关闭**：图片保存当前完整画面的原图，视频保存 Telegram 原文件；切换 Story 时同一按钮原位换绑，正在下载的旧 Story 继续留在共享 FIFO，新 Story 可再次入队。关闭弹层后按钮立即移除，重新打开时按当前媒体重建。
- **下载管理入口**：存在下载中、等待中或失败任务时，在主聊天列原生向下浮动控件区显示独立的 48×48px 圆形下载图标；按钮使用 Geist 蓝（亮色 `#006bff`、暗色 `#006efe`）和白色图标，位于原生向下按钮之前或上方，并随同区未读控件纵向排列。右上角显示最小 18×18px 的任务总数徽章，超过 99 个显示 `99+`；全部状态为空时隐藏。
- **页面任务浮层**：入口由鼠标悬浮或点击展开，键盘焦点本身不自动展开；浮层为 332px 宽、最高 360px、最大 8px 圆角。顶部数量右侧提供蓝色清除全部图标按钮，“等待中”标题右侧提供蓝色清空等待图标按钮，失败分组提供蓝色重试图标按钮。清除全部不弹确认框；等待、失败和活动项立即移除，活动项的底层取消与清理在后台尽力执行。宽度不足时限制为 viewport 左右各保留至少 16px，任务行不嵌套卡片。
- **打开与关闭**：鼠标进入入口或浮层时保持展开，离开两者后延迟 150ms 关闭；点击入口可固定或解除固定，触屏只使用点击；`Escape` 关闭并把焦点还给入口。悬浮不是唯一操作方式。
- **任务行**：每行显示资源文件名、状态、进度、大小与速度；waiting 和下载中任务使用 28×28px 取消图标按钮，失败项明确显示失败文字并改用同尺寸重试图标按钮。文件名尚待活动项解析时显示“获取文件名中…”。文件名单行省略，悬浮后通过提示查看全名。
- **主题与动态效果**：入口和浮层跟随 Telegram 当前亮暗主题，正文、次要文字、边框和焦点环满足可读性；显隐只使用 150ms 颜色/透明度过渡，不缩放，不改变布局；`prefers-reduced-motion` 下取消过渡。
- **DOM 配置生效**：页面打开时只读取一次；成功或失败后再启动主消息、A 版侧栏与 A Story 的扫描和监听。管理员更新配置后，用户刷新 Telegram 页面生效。

### admin

系统设置页提供 Telegram DOM 覆盖编辑入口，默认内容为空对象，仅保存管理员实际填写的覆盖项，不展示插件包内默认值，也不提供“恢复默认”。完整 UI 与操作边界见 `@../008.管理后台/feat.md`。节点列表/启停/健康检查/session 管理/X / Instagram Cookie 管理在 `@../001.节点系统/feat.md`。
