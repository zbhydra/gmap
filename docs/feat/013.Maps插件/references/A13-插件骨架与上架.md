# A13 · 插件骨架与上架(竞品事实 + 我方决策)

## 功能定义

插件工程底座:manifest 权限、上下文架构、SW 生命周期策略、远程配置通道、发布渠道。

## 竞品事实(引以为戒多于照搬)

- manifest v3,permissions 仅 `storage/identity/activeTab`,host 到 `*.google.com` 与自己后端;jQuery 3.2.1 + webpack 4 + Vue 2 render,obfuscator.io 混淆。
- 三上下文:injected(主世界 hook XHR)↔ contentScript(隔离世界,解析+UI+滚动)↔ SW(后端代理+调度),`chrome.runtime.sendMessage` 封装 60+ 事件常量。
- 致命伤(实测):SW 内存态批量队列随 30 秒生命周期蒸发;DOM 选择器失效静默失败;强制登录墙挡住全部未登录用户。

## 我方落地要点(全部已拍板)

| 决策点 | 结论 |
| --- | --- |
| 工程骨架 | 复用本仓库 `extension/`(MV3 + Vue3 + Pinia + 自研 RPC + Playwright e2e),新仓库或 monorepo 新子项目立项时定 |
| SW 生命周期 | 状态落盘步进状态机,SW 轻量化为无状态代理(A6) |
| DOM/schema 漂移 | 远程配置通道:包内默认 + 远端稀疏覆盖 + 1 小时缓存,三组 dom/parseSchema/scrape(A1/A9) |
| 失败处理 | 选择器/解析/schema 缺失一律可见报错,禁止静默 |
| 登录墙 | 不强制登录(A11) |
| 上架渠道 | **不上 Chrome Web Store**(审核风险);目标 Edge Add-ons + Firefox AMO;Firefox MV3 是事件页,SW 生命周期问题天然不存在,调度代码做平台分支;隐私政策页必需 |
| 采集验证 | hook XHR 对新 Maps 已无效(前端闭包缓存原生引用,实测),协议验证一律 CDP 层;黄金样本归档于 scratch `golden-samples/` |
