# A6 · 批量任务面板(竞品调研)

> Roadmap:A6 · 调研:🔍 完成 · 深读:scratch 逆向 01(dashboard)/02 §7/09;我方架构决策:scratch 11 号 #5

## 功能定义

独立扩展页(dashboard),创建和管理批量任务:关键词队列任务(逐关键词自动搜索采集)与评论 URL 队列任务(逐链接自动抓评论),带进度监控与自动导出。

## 用户操作(竞品)

1. 打开 dashboard 页,新建任务:粘贴关键词列表(≤500 个/任务)或评论 URL 列表(≤500 个),可设置每店评论上限(默认 300)。
2. 启动任务 → 自动逐个开 Maps 搜索页/评论页 → 自动 Start → 完成自动下载 → 切下一项。
3. 面板实时显示每个任务的 try/stuck/complete/skip 计数;单关键词 90 秒无进展判卡死自动跳过。
4. 任务保存上限 150 个(IndexedDB)。

## 竞品实现逻辑

- 队列存 dashboard 的 IndexedDB(任务对象含 kw、try、stuck、complete、skip、reviews_max_export 等)。
- 调度:background 开标签 → 消息通知 contentScript 自动 start(auto_download 强制开)→ 完成/卡死消息回 background → 切下一关键词;全程 service worker 保活靠 KEEP_LIVE 心跳 + 每 15 秒轮换提取 tab 激活。
- **竞品致命缺陷(实测确认)**:任务状态放 SW 内存,MV3 SW 空闲 30 秒被杀——用户关掉所有 Maps 页 → 心跳停 → 队列蒸发,无恢复。

## 我方落地要点(已拍板,scratch 11 号 #5)

- **状态落盘的步进状态机,不对抗平台模型**:采集主循环留 contentScript(页面进程天然长命);批量队列持久化(storage.session / IndexedDB);调度步进化(每步写状态,SW 任意唤醒读状态推进一步);chrome.alarms 兜底扫描未完成任务。SW 本体轻量化为无状态 tab/window 代理。
- 不采用:心跳续命、offscreen 常驻 worker(审核风险)。
- 15 秒 tab 轮换保留与否由实测决定(它服务防后台 tab 节流,与 SW 保活无关)。
