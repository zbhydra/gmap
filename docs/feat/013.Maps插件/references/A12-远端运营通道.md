# A12 · 远端运营通道(竞品调研)

> Roadmap:A12 · 调研:🔍 完成(实测证实)· 深读:scratch 逆向 06/11 #6

## 功能定义

不改插件发版即可触达用户的三类运营能力:面板公告、新版本提示、行为埋点。

## 用户操作(竞品)

用户无感知:每次打开 Maps 页(boot)时插件向服务端拉取套餐/公告/版本号,公告 HTML 直接注入面板;GA4 埋点随用户行为(搜索、导出、同步、按钮点击)上报。

## 竞品实现逻辑

- **公告**:云函数 license/isPro 响应携带 `extension.content.html` 服务端 HTML 片段,直接 innerHTML 注入面板——作者免发版改公告/广告(实测:license 校验与公告下发是同一云函数,假 key 也返回公告 HTML)。
- **版本提示**:响应携带远端版本号,与本地版本字符串比较决定是否附加升级提示。
- **埋点**:GA4 Measurement Protocol 直发(安装事件、search/export/sync 等业务事件经 SW 汇总);另有后端事件云函数(如 chrome_install、关键词上报)。
- 三者每次 boot 现拉、只进内存不落盘——本质是运营性远程配置,与用户功能配置(全本地)分离(见 A9)。

## 我方落地要点

- 公告/版本提示合并进我方统一远程配置通道(013 域已拍板的 dom/parseSchema/scrape 之外加运营组),或走 backend 现有远端配置机制(001/012 遗产的统一远端配置方案),tech 文档定归属。
- 埋点复用本仓库 GA4 + SLS 双写基建(009 域/website-shared 经验),不新造轮子。
- 隐私红线:竞品上报用户搜索关键词属中等强度遥测,我方上报字段需按 009 域脱敏口径(mark-sanitizer 模式)审查。
