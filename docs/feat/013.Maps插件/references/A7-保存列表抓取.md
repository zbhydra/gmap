# A7 · 保存列表抓取(竞品调研 + 当前 Maps 实测)

> Roadmap:A7 · 调研:✅ 完成(源码级 + 2026-08-30 当前 Maps 登录态实测)· 深读:scratch 逆向 02(place list 模式)、readable `modules/contentScript-main.js` 935/1030/730/1379 行;域内 `竞品逆向/` 同主题文档

## 功能定义

抓取 Google Maps 列表形态页面中的地点(用户保存列表 Saved lists、搜索侧栏本地结果列表),逐项打开详情采集,无需逐个搜索。竞品官网以 "can extract saved place lists" 作为插件差异点宣传。

## 用户操作(竞品)

1. 打开列表形态页面(保存列表 / 搜索侧栏本地结果列表)。
2. 插件给列表中每一项插入 "Extract" 按钮(300ms 轮询等渲染,`done` 类防重)。
3. 点击某项:进入通用采集状态(复用 A1 start():配额检查 → 字段生成 → status=1),并自动点击该项打开详情。
4. 逐项采集,列表自动滚动加载;到底自动完成,按 A8 导出。

## 竞品实现逻辑(源码级)

- **触发**:URL 含子串 `data=!4m2!10m1!1e1` 即激活,onUrlChange 与 300ms 轮询双保险;不区分列表来源。
- **UI 注入**:`div[role=main]` 最后一个子 div 下的列表项(非首非尾)逐个插按钮。
- **数据通道**:无新协议——点击列表项打开详情后仍走 A1 的 `/search?tbm=` 拦截。
- **列表滚动**(`scrollPlaceListToNext`):滚动容器 = `div[role=main]` 倒数第二个子 div;每轮 +500px、动画随机 2–4s;勾 Email +2s / Social +3s(等服务端补全);末项无子内容 → complete。

## 当前 Maps 实测(2026-08-30,登录态,webbridge + CDP)

| 项 | 竞品时代 | 当前 Maps 实测 | 结论 |
| --- | --- | --- | --- |
| 列表聚合页 URL | 含 `data=!4m2!10m1!1e1` | **精确含**( `/maps/@…,13z/data=!4m2!10m1!1e1?hl=en` ) | 触发条件仍命中 |
| 深层列表页 URL(点进某保存列表) | — | `data=!4m6!1m2!10m1!1e1!11m2!2s{listToken}!3e1` | **竞品精确子串失效**(`4m2` 段变为 `4m6!1m2`),仅 `10m1!1e1` 尾段保留 |
| 列表容器 DOM | `role=main` 末子 div,项 = 子 div 过滤首尾 | 聚合页同构;**深层列表容器结构漂移**(role=main 下子项数量/形态不同) | 照抄竞品容器定位不可靠 |
| 保存列表数据 | 账号保存列表可见(Favorites · 1 place 实证) | 需 Google 登录态 | 与「不强制登录」不冲突:未登录用户无保存列表,入口自然不存在 |

**实测方法备查**:合成 click 与 CDP trusted click 均无法触发 Maps 左栏 Saved 导航(内部事件委托),最终用 webbridge 语义 `click`(@e ref,自处理滚动与事件)进入;列表层级间导航用 CDP trusted 点击列表项。

## 我方落地要点

- **触发条件必须用宽松匹配**:URL 含尾段 `10m1!1e1`(覆盖 `4m2`/`4m6!1m2` 两种前缀),写入 parseSchema/dom 远程配置组的触发正则;照抄竞品精确子串会漏掉全部深层保存列表页。
- **实现定位**:A1 的「列表模式」分支(同一采集引擎,换 UI 注入与滚动容器);容器选择器(列表容器、列表项、详情按钮)全部走远程配置,聚合页与深层列表页各配一组。
- 深层列表页的容器选择器需在实现时按实测 DOM 再校准一轮(本次已确认结构漂移存在,具体稳定选择器留给实现期,以远程配置下发)。
- 登录态边界:未登录用户无保存列表,与「不强制登录」决策不冲突。
