# A7 · 保存列表抓取(竞品调研)

> Roadmap:A7 · 调研:🔍 完成(源码级;剩余一个实现期验证点)· 深读:scratch 逆向 02(place list 模式)、readable `modules/contentScript-main.js` 935/1030/730/1379 行

## 功能定义

抓取 Google Maps 列表形态页面中的地点(含用户保存列表 Saved lists、Google 搜索侧栏本地结果列表),逐项打开详情采集,无需逐个搜索。竞品官网以 "can extract saved place lists" 作为插件差异点宣传。

## 用户操作(竞品)

1. 在 Google Maps 打开任意列表形态页面(典型:左侧栏为地点列表、右侧为地图,URL 含 `data=!4m2!10m1!1e1`;用户的 Saved list 打开后即为此形态)。
2. 插件给列表中每一项上方插入 "Extract" 按钮(300ms 轮询等列表渲染,`done` 类防重复注入)。
3. 点击某项的 Extract:插件进入通用采集状态(复用 A1 的 start():配额检查 → 字段生成 → status=1),并自动点击该项打开详情。
4. 用户逐项点击(或滚动触发加载更多),插件自动滚动列表容器加载下一批;采集数据走 A1 的 XHR 拦截通道。
5. 列表到底自动完成,按 A8 导出。

## 竞品实现逻辑(源码级)

- **触发**:URL 含 `data=!4m2!10m1!1e1` 即激活,onUrlChange 与轮询双保险;**不区分列表来源**(搜索结果列表与用户保存列表同构处理)。
- **UI 注入**:`div[role=main]` 最后一个子 div 下的列表项(非首非尾),每项前插按钮,sticky 定位随滚动可见。
- **点击处理**:`is_place_extract = true` → 调通用 `start()`(注意:列表模式下也会重放当前搜索)→ 以 jQuery 点击列表项详情按钮打开详情,让 Maps 发出详情 RPC 被拦截。
- **列表滚动**(`scrollPlaceListToNext`):滚动容器 = `div[role=main]` 倒数第二个子 div;每轮 scrollTop +500px、动画随机 2–4s;**勾选 Email 额外 +2s、Social +3s**(给服务端 findV3 补全留时间);列表末项无子内容 → complete;否则随机 interval 后递归。
- **数据通道**:无新协议——详情打开后仍是 A1 的 `/search?tbm=` 拦截;即本功能 = A1 通道 + 列表页 UI/滚动变体。

## 我方落地要点

- **实现定位**:作为 A1 的「列表模式」分支(同一采集引擎,不同的 UI 注入与滚动容器),不是独立功能模块。
- 选择器(列表容器、列表项、详情按钮)全部走远程配置 dom 组——竞品的 jQuery 结构选择器在当前 Maps 大概率已漂移,与 A1 同理不照抄。
- **实现期验证点(唯一)**:用登录 profile 打开一个真实 Saved list,确认当前 URL 是否仍携带 `data=!4m2!10m1!1e1`、列表 DOM 形态;方法照 scratch 10 号(CDP 抓取,`--disable-quic`)。不阻塞立项与开发,实现该分支时顺手验证。
- 登录态边界:Saved lists 需用户登录 Google 才有内容;我方「不强制登录」决策不受影响——未登录用户只是没有可抓的保存列表,功能入口自然不出现。
