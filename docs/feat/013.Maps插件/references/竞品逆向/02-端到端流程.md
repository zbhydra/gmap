# 02 · 端到端流程

从用户打开 Google Maps 到拿到 CSV 的完整时序。证据:contentScript-main.js(mod_396)、injected-hook.js(mod_394)、background-msg-handlers.js(mod_384)。

## 阶段 0 · 安装与初始化(一次性)

1. SW 安装:`chrome.runtime.onInstalled` → cloudRun("event", {event:"chrome_install"}) 上报安装;首次初始化 storage:`{request_interval: 2, auto_download: false, fields: 全部36字段, stuck_max_retry: 1}`。
2. 用户登录(必须在 dashboard/popup 完成,未登录 UI 面板不出现):
   - `LOGIN` → `chrome.identity.getUserInfo()`(Google OAuth,scope 仅 userinfo.email)
   - 拿到 `{email, id}` → `Parse.User.logIn(username=email, password=id)`;账号不存在则自动 `signUp`(同参数)
   - 即:**Google 账号即 Parse 账号,密码就是 Google 用户 id**
3. `GET_IS_PRO` → `Parse.Cloud.run("isPro", {uid})` → 返回 `{pro, plan, extension:{content,version}, quota…}`,contentScript 缓存到内存。

## 阶段 1 · 注入与待命(Maps 页面)

1. 页面加载完(contentScript `document_end`):
   - `setTimeout(100ms)` 后创建 `<script src="chrome-extension://…/src/injected.js">` 插入 head → **进入页面主世界**(隔离世界无法 hook 页面 XHR,这是必须注入的原因);onload 后立即 remove 节点。
2. injected.js hook `XMLHttpRequest.prototype.open / setRequestHeader / send`。
3. contentScript `boot()`:
   - 读 storage(request_interval、auto_download、license、Drive/HubSpot 开关)
   - 有 license.key 则 `GET_LICENSE_STATUS`(cloudRun "license")验证;否则走 `GET_IS_PRO`
   - `photosScraper.init(isPro, user, opts)` + `boot()`
   - `MutationObserver` 监听 document,URL 变化时触发 `onUrlChange()`
   - `onDragMode()`:MutationObserver 持续观察 `[aria-checked]` 复选框——Maps 搜索结果页的"结果随地图移动"开关。开着 = drag 模式(滚动逻辑不同)。
4. `initUI()`:轮询等待 `[role=main]` 出现,然后 jQuery 把 `#map_scraper` 面板 append 到 body(左侧 fixed,或 place 页右侧 20px)。

## 阶段 2 · 点击 Start Extracting(`start()`)

1. 检查用量:`usage_percent >= 100` → 弹订阅页,终止。
2. `initStuckMonitor()`:isBulkAuto 时每 25s 检查一次,超过 90s 无进展 → `KEYWORD_AUTO_STUCK` 让 background 换下一个关键词。
3. `observeCheckbox()`:若 drag 模式开着,bulk 自动模式会强制点击关掉它。
4. `generateFields()`:storage.fields ∩ CSV_EXPORT_FIELDS;非 Pro 再剔除 PRO_FIELDS。
5. `status = 1`;`pins = []`;**触发搜索**:`$("div[role=search]").find("form").first().parent().find("button").first().trigger("click")`(重放当前搜索,让 Maps 重新发请求)。
6. 取关键词:`#searchboxinput` 的值;取不到则从 URL 正则 `/\/maps\/search\/(.+?)\/@/` 解码。
7. GA 埋点:`ga_event{evt:"search"}` + `log_search{kw, status}`(kw 上报后端)。

## 阶段 3 · 拦截与解析循环(核心)

```
用户(或自动)在 Maps 上搜索
        │ Maps 自身发 XHR: /search?tbm=map&…(内部 RPC)
        ▼
injected.js: send() 里挂 progress 监听
  - URL 含 /search?tbm= 且 responseText 以 /*""*/ 结尾(响应完整标志)
  - dispatchEvent("load_api_complete", {str, url, fullurl, postData, headers})
        │ (progress 阶段即可读 responseText,不必等 load,提速)
        ▼
contentScript receive(str):
  1. status 必须= 1(采集中),否则丢弃
  2. parser.toJson(str) → pin 数组(解析协议见 03/04 文档)
  3. 免费版:超过 10 条截断 slice(0,10)
  4. 去重:pins 里已存在相同 Cid+Name 的丢弃
  5. 若勾选 Email / Social Medias → sendMsg FIND_LEADS(见下)
     否则只 sendMsg COUNT_ONLY(仅计数,后端 findNoop.increment)
  6. 若勾选 Plus Code → sendMsg GET_PLUS_CODE(background 对每条调
     cloudRun→maps.plusCode(lat,long)? 实为后端接口,返回 global_code)
  7. pins += 新数据
  8. 终止判定:
     - pins.length < 2 → 直接 complete(结果太少)
     - 非免费且 pins.length >= 10 → complete 并截断 10 条
  9. updateUI() 更新面板计数
  10. await wait(interval 秒)   ← 默认 8s,可在 options 调 5~10s
  11. scrollToNext() + scrollPlaceListToNext()
```

**滚动驱动加载**(`scrollToNext()`):
- 找 `div[role=main]` 下的 `div[role=feed]`(结果列表容器)
- jQuery animate 把 scrollTop 滚到 scrollHeight(随机时长 1.5~3.5s,拟人)
- feed 最后一个子 div 有文字(如"You've reached the end of the list")→ `complete()`
- 否则随机 `interval*1000 ± 随机` 毫秒后递归滚动 → Maps 每次滚到底就发起新的 `/search?tbm=` XHR → 回到注入环节,形成闭环

**place 列表模式**(URL 含 `data=!4m2!10m1!1e1`,即 Google 搜索侧栏的本地结果列表):
- `updatePlaceListUI()` 给列表每一项前插入 "Extract" 按钮(`div[role=main] > div:last-child` 内遍历)
- 点击按钮 → 逐项点击打开详情 → `scrollPlaceListToNext()` 滚动列表容器(`div[role=main]` 倒数第二个子 div),Email 模式 +2s、Social 模式 +3s 等待

**drag 模式下**(结果随地图移动):不自动滚动,只被动收集地图移动产生的响应。

## 阶段 4 · Email / 社交媒体挖掘(FIND_LEADS,后台)

contentScript `findLeads(pins, exportEmail, exportMedias)` → background:

1. `cloudRun("getFindParams")` → 服务端下发 `{version, size, lookup}`
2. `lookup === "v3"`(现行):逐条 `cloudRun("findV3", {domain, profiles: Name+" "+Fulladdress, kgmid, website, app, key, version, kw})`
   - 服务端用 domain/名称搜索并返回 `{emails:[…], medias:{instagram:url, facebook:url, …}}`
   - 写回 `pin.Email = emails.join(",")`,`pin["Social Medias"] = "instagram: …\nfacebook: …"`
3. 旧版回退:逐条 `cloudRun("fetchEmail", {domain})` 只抓 Email
4. **注意:无 license 时 key 为空,服务端按免费配额计费/限流;这步全部在后端完成,插件本地不做任何邮件抓取**

## 阶段 5 · 完成(complete)

1. `status = 2`,UI 切换为 "Export Detailed List - N (.CSV)"
2. `auto_download` 开启 → 直接 `download()`;bulk 模式发 `KEYWORD_AUTO_COMPLETE`(background 关 tab、切下一关键词)
3. `auto_save_to_google_drive` → 先导出再 `saveToDrive`(见 07)
4. `auto_save_to_hubspot` → `syncToHubspot()`
5. `refreshMonthUsage()` 刷新用量百分比,>=100% 显示 "You have used all of your lead requests…"

## 阶段 6 · 评论与照片(独立子流程,在 place 详情页)

用户在某个 place 详情页时(`onUrlChange` 检测 `/place/`),面板多出 "Reviews & Photos" 标签页:

**评论**:点 "Start Extracting Reviews"
1. contentScript `mod_318.getReviewsURL()`:
   - 从 URL 提取 hex ID:正则 `/(0x[a-zA-Z0-9]+)/gm`,过滤长度≤20,最后两个 join(":") 为 fid,最后一个为 lrd
   - `cid = BigInt(lrd).toString(10)`
   - `FIND_PLACE_ID{fid}` → background(cloudRun)拿 placeId
2. 打开新 tab:`https://search.google.com/local/reviews?placeid={placeId}&_rs_=1`
3. rsScript 在该页 `boot()`:URL 有 `#&lrd=…`(页面自己带的)→ `_start()` → `fetchReviews(null)`
4. `fetchReviews`:主动 `fetch` 评论 RPC(协议见 03 文档 3.2 节)→ `txtToJson()` 解析 → 追加 → `next_page` token 存在则 wait(2s) 递归翻页
5. 终止:达到套餐上限(free 20 / pro 250 / business 2500)或不足 10 条或无 token → `complete()` → bulk 自动下载
6. 手动点按钮导出,字段:Author/Review Text/Review Rating/Date/Photos/Likes/Owner Answer/Owner Answer Date/Author Profile/Author Image/Review URL

**照片**:点 "Start Extracting Photos"
1. `getPhotosURL()`:`https://www.google.com/maps/uv?pb=!1s{hex1}:{hex2}&_ps_=1` 打开照片画廊页
2. 页面 boot(`lkt=LocalPoiPhotos`):从页面 `<script>` 的 `window.WIZ_global_data` 抠 `SNlM0e`(XSRF AT token)
3. `fetchPhotos()`:POST `wizrpcui/_/WizRpcUi/data/batchexecute?rpcids=wTe8We`(协议见 03 文档 3.3 节)→ 解析 imgs(过滤 streetview)+ next + end
4. 翻页递归直到 end 或达上限(free 10 / pro 100 / business 1000)

## 阶段 7 · 批量任务(dashboard)

dashboard.html(Vue + IndexedDB)创建任务:
- 关键词任务(≤500 个/任务):逐个 `OPEN_BULK_KEYWORD_TAB` 打开 Maps 搜索页 → `KEYWORD_AUTO_START` 通知 contentScript → 自动 `start()`(auto_download=true)→ 完成 `KEYWORD_AUTO_COMPLETE` → 下一关键词;90s 无进展 `KEYWORD_AUTO_STUCK` 跳过
- 评论 URL 任务(≤500 个):同构,由 rsScript 侧处理
- 全程 SW 保活:`KEEP_LIVE` 心跳

## 状态机小结

`status: 0 待命(startUI) → 1 采集中(extractUI, Pause) → 2 完成(completeUI, Export/Reset);3 = 暂停(Resume)`
