# 03 · 数据采集协议(三条通道)

回答"怎么采集 gmap 的"。三条通道全部围绕 Google Maps 的**内部 RPC**,没有一条走公开 API。

## 3.1 通道一:主搜索响应拦截(商家列表,核心)

### 拦截(injected.js,页面主世界)

```js
// hook XMLHttpRequest.prototype.open/setRequestHeader/send
xhr.send = function(body) {
  this.addEventListener("progress", () => {
    if (this._url.includes("/search?tbm=") && this.responseText.endsWith("/*\"\"*/")) {
      window.dispatchEvent(new CustomEvent("load_api_complete", {
        detail: { str: this.responseText, url, fullurl, postData, headers }
      }));
    }
  });
  // …
}
```

要点:
- URL 特征:路径含 `/search?tbm=`——这是 Maps 前端搜索/滚动加载时发出的内部 RPC(`https://www.google.com/search?tbm=map&…`),POST protobuf-ish 文本
- **在 progress 事件就截获**(不必等 load),以 `/*""*/` 结尾作为响应完整性哨兵;每个 xhr 只发一次(`_sent` 防重)
- detail 里顺带带上了 postData(解码后)和请求头——插件当前版本没用它们解析,但为调试保留了

### 响应格式(还原后的 toJson 逻辑,contentScript-main.js)

响应文本是 Google 内部 RPC 的序列化格式,形如:

```
)]}'          ← 防 XSSI 前缀(4 字符)
12345         ← 长度行
[["…"], …]    ← 多行,每行是一个 JSON 片段
/*""*/        ← 哨兵
```

`toJson` 的剥壳步骤(代码顺序):
1. `str.slice(0, -6)`:去掉末尾 6 字符(`\n/*""*/`)
2. `JSON.parse(...).d`:取出 `d` 字段字符串
3. `.substr(4)`:去掉 `)]}'` 前缀
4. `JSON.parse` → 大数组 `data`
5. `data[data.length - 8]`:**商家列表在倒数第 8 个元素**(Google 版本兼容点)
6. `this.filename = getValues(data[0][0])`:文件名 = 搜索关键词

列表有两种形态:
- **V1**(旧):`data[0][1]` 是行数组,每行 16 元素,**第 15 个(下标 14)才是商家详情数组**
- **V2**(新):`data[len-8]` 是对象/Map,遍历 values(`item[1]`)得到详情数组

### 详情数组下标(contentScript-main.js `parseDetails`)

`getValues(obj, i, j, k…)` 是逐层取值的容错函数(任何一层空即返回 undefined),`a` 表示详情数组:

| 字段(内部名) | 下标路径 | 说明 |
| --- | --- | --- |
| url / domain | `a[7][0]` / `a[7][1]` | 官网;不含 http(s) 则清空 |

- `Google Maps URL = https://www.google.com/maps?cid={cid}`

## 3.2 通道二:评论 RPC(主动构造请求)

### 第一步:拿到入口(rsScript/mod_318 `getReviewsURL`)

- place 详情页 URL 里含两个十六进制 ID(正则 `/(0x[a-zA-Z0-9]+)/gm`,长度≤20)
- 最后两个 → `fid = "0x…:0x…"`;最后一个 → `lrd`
- `cid = BigInt(lrd).toString(10)`
- `FIND_PLACE_ID{fid}` → background → cloudRun → 返回 placeId
- 打开 `https://search.google.com/local/reviews?placeid={placeId}&_rs_=1`(该页面是 Google 官方评论列表页,rsScript 注入其中)

### 第二步:抓取(rsScript `_start` → `fetchReviews`)

**主动 fetch**,不靠拦截:

```
GET https://search.google.com/httpservice/web/PrivateLocalSearchUiDataService/GetLocalBoqProxy
    ?hl={页面hl}&gl={页面gl}
    &reqpld=[null,[null,null,null,null,null,null,null,null,null,
        [null,1,null,null,null,null,null,null,null,10,null,["{lrd}"],null,null,null,null,
         [1,1,null,[[3],[4],[5],[6],[7]]],null,null,{next_token 或 null}]]]
    &msc=gwsrpc&opi=89978449
```

- `reqpld` 里的 `"${lrd}"` 定位商家;`10` 是每页条数;`[[3],[4],[5],[6],[7]]` 类似字段掩码
- `next_token` 为 `"${token}"`(翻页)或 `null`(首页)
- `opi=89978449`:内部服务版本号(写死)

### 响应解析(两种解析器并存)

`txtToJson`(当前主用):文本 `split("\n")`,**第 3 行** `JSON.parse` → 数组 `d`:
- 列表:`d[1][10][2]`,翻页 token:`d[1][10][6]`
- 每条评论 `r`:
  - id=`r[5]`,rate=`r[1]`,date=`r[2][0]`,timestamp=`new Date(Number(r[2][2]))`
  - name=`r[3][0]`,avatar=`r[3][1]`,author_url=`r[3][2]`
  - like=`r[11]`,comment=`r[27]`,photos=`r[14][*][0]` join "\n"
  - reply=`r[4][2]`,reply_date=`r[4][1]`,review_url=`r[12]`

`_txtToJson`(回退,HTML 解析):从响应抠 `<div>…</div>`,jQuery 找 `.gws-localreviews__google-review`,逐项 DOM 取值(名字/评分 `span[role=img][aria-label]`/`.review-full-text`/`g-scrolling-carousel` 照片数/`[data-orc="lororc"]` 商家回复/`data-next-page-token` 翻页)。**这是整个插件里唯一一次用 DOM 选择器解析 Google 数据。**

`toJSON`(另一种响应形态,`split("\n")` 第 4 行,`d[0][2]` 再 parse):照片 URL 规则 `split("=")[0]+"=w1000"`。

### 翻页与终止

- 翻页:有 `next_page` → `wait(2000ms)` → 递归 fetchReviews(token)
- 终止:达套餐上限(free 20 / pro 250 / business 2500;bulk 任务可自定义 reviews_max_export,默认 300)或 `reviews.length < 10`(不足一页)或无 token
- 页面兜底:检测 `no_reviews` 图片(0 评论)、`af-error-container`(错误页)、标题含 "500" → 直接完成并通知 bulk 调度器

## 3.3 通道三:照片 RPC(主动构造请求)

### 入口(getPhotosURL)

- 从 place URL 提取两个 hex ID → `https://www.google.com/maps/uv?pb=!1s{hex1}:{hex2}&_ps_=1`
- 该页是 Maps 官方照片画廊(`lkt=LocalPoiPhotos` 时 photos scraper 的 boot 激活)

### AT token(photos/mod_317 `parseScriptToData`)

遍历页面 `<script>`,找含 `window.WIZ_global_data` 的块,截取到 `window.IJ_values` 之间,`JSON.parse(...).SNlM0e` —— 即 Google 页面级 XSRF token(页面 HTML 里明文存在)。

### 请求

```
POST https://www.google.com/wizrpcui/_/WizRpcUi/data/batchexecute
     ?rpcids=wTe8We&source-path=%2Fsearch&hl=en&_reqid={page}72138&rt=c
Content-Type: application/x-www-form-urlencoded;charset=UTF-8

f.req=[[["wTe8We",
  "[\"{lrd}\",null,{next 或 null},\"CgIgAQ==\",null,null,null,null,null,null,\"LU_PHOTO_GALLERY\",null,null,0]",
  null,"generic"]]]
&at={SNlM0e}&
```

- `_reqid` = 页码 + "72138" 拼接(模仿前端 reqid 规则)
- `CgIgAQ==`、`LU_PHOTO_GALLERY` 是请求 payload 里的固定常量(图库类型标记)

### 响应解析

`toJson`(mod_317):剥壳方式同 3.1(slice 尾部 → `d` 字段 → substr(4) → parse),取每个结果块:
- `photoUrl`/`videoUrl` 字段;**过滤 URL 含 `streetview` 的项**(removeStreeViweImg)
- `next` = 结果里的翻页 token;`end` = 布尔(第 10 位)

另有备用通道 `fetchPhotos_v1`:`https://www.google.com/maps/rpc/photo/listentityphotos?authuser=0&hl=en&pb=!1e2!3m1!1s{encodeURIComponent(lrd)}!5m36!2m2!1i406!2i200!3m3!2i20!3s{next}!5b1!7m26!…!4e1`,响应 `split("'")[1]` 取 JSON(当前主流程未走此路径,属保留的旧实现)。

### 翻页与终止

wait(interval) → 递归,`data.page++`;终止:达上限(free 10 / pro 100 / business 1000)或 `end` 或 `imgs.length < 10`。

## 3.4 通道四(辅助):后端代抓(Email / 社交 / Plus Code)

主列表数据全在客户端拿,但 **Email、Social Medias、Plus Code 三列走作者后端**:

- `findV3` / `fetchEmail`:Parse Cloud Function 在服务端搜索商家官网域名并抓邮箱/社交链接,返回给插件
- `getFindParams`:服务端下发挖掘算法版本/批量大小/lookup 分流
- Plus Code:服务端按经纬度换算 global_code(虽然主响应里也有下标 183 可取,双保险)

好处(对作者):核心增值能力服务端化、可计量计费、防客户端逆向(本调研已还原调用协议,但服务端实现不可见)。

## 3.5 频控与拟人化

- 滚动间隔可调 5/6/8/9/10 秒,默认 8 秒
- 滚动动画时长随机 1.5~3.5 秒;递归滚动延迟 = `random() * interval*1000 + 2000`ms
- place 列表模式:Email +2s、Social +3s 额外等待
- 评论翻页固定 2 秒;照片翻页 interval 秒
