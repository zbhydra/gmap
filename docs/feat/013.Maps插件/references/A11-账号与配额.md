# A11 · 账号与配额(竞品调研)

> Roadmap:A11 · 调研:🔍 完成(含实测)· 深读:scratch 逆向 06;我方决策:scratch 11 号 #2

## 功能定义

插件侧的账号登录、套餐/配额查询与展示、付费状态判定(免费/Pro/Business)。

## 用户操作(竞品)

1. 未登录时插件面板**完全不出现**(硬登录墙:免费也必须登)。
2. dashboard/popup 点登录 → Google OAuth(仅 userinfo.email scope)→ 静默建号(账号 = 邮箱,密码 = Google id)。
3. 面板/设置显示当前套餐、月用量百分比(usage/quota),≥100% 禁止开始采集并弹订阅页(跳官网 Stripe/Paddle 中转,携带其后端 uid)。
4. 备选:dashboard 直接输入 license key 激活(不走账号)。

## 竞品实现逻辑

- 身份:Google 身份映射为自建 Parse Server 账号(username=email、password=google id,无独立注册);登录态是功能可用的前置。
- 套餐真源在服务端:云函数返回 `{pro, plan, quota, 公告 HTML, 远端版本号}`,每次 boot 现拉、只进内存;配额由服务端计量(见 A4 计数点)。
- 双轨付费判定:账号制 isPro(主)+ license key 校验(辅,code===0 即 Pro;实测假 key 返回明确错误码)。
- 实测:假 uid 返回 "Object not found"——uid 必须是真实账号 objectId。

## 我方落地要点(已拍板,scratch 11 号 #2)

- **不强制登录才能用**:登录态与功能可用性解耦;需要计费/配额时用轻量凭证(license key 或自有账号体系)。
- 插件登录流程走本仓库现有 website & extension 用户模型(007 域),不参考对方 OAuth-即账号的设计(一体否决)。
- 配额体系复用 003 积分 / 005 计数器;免费月度额度与分档(1,000/100k/500k)是竞品定价参照,我方档位在 C2 决策。
- 竞品 license 云函数「捎带远程公告」的机制归入 A12 通道。
