## 5 · 隐私政策

- **扩展内页面**:`privacy.html`(产物根,扩展页);入口在设置页页脚链接,测试地址 `chrome-extension://<id>/privacy.html`。内容覆盖:数据类型(公开商家数据/用户设置/技术交互数据)、存储位置(浏览器本地 storage + IndexedDB)、网络行为(自有后端 API、所浏览 Google 页面、可选 Drive/HubSpot 用户授权)、无广告/无第三方追踪。
- **商店隐私政策 URL(占位,待 hydra)**:`https://www.example.com/privacy`——两商店均要求可公开访问的 URL;发布前把 `public/privacy.html` 原样发布到官网该路径(静态文件,无需改写)。官网域名落定后同步更新 vite.config.ts 的 `EXTENSION_WEBSITE_BASE_URL` 生产默认值(manifest `homepage_url` 当前同为占位 `https://www.example.com`)。
- 联系邮箱占位 `support@example.com`(与 popup 页脚一致),上架前待 hydra 确认真实邮箱。

## 6 · Firefox manifest 与 Chromium 差异(逐项)

`EXTENSION_BUILD_TARGET=firefox` 时的全部差异(manifest 工厂内注释为代码级真相):

| 键 | Chromium(chrome/edge) | Firefox | 依据 |
| --- | --- | --- | --- |
| `background` | `{ service_worker }` | `{ scripts }`(事件页) | Firefox MV3 不支持 SW;A13/11 号 #5 |
| `browser_specific_settings.gecko` | 无 | `id`(占位 TODO)+ `strict_min_version: "140.0"` + `data_collection_permissions` | AMO 2025-11-03 起新扩展强制数据采集声明;内置授权体验要求 140+ |
| `oauth2` | 有(Drive getAuthToken 用) | 无(getAuthToken 为 Chromium 专属 API) | MDN identity 兼容性 |
| `homepage_url` | 有(官网占位) | 无(Firefox 忽略该键) | MDN |
| `externally_connectable` | 无(登录 v3 已删除该键,不登记扩展 ID) | 无(Firefox 不支持该键) | 007 plans/006(2026-09-01) |

其余键(permissions、host_permissions、content_scripts、web_accessible_resources、action、options_ui、icons、_locales)三渠道一致。

**调度代码零改动**:11 号 #5 拍板的「状态落盘步进状态机 + alarms 兜底」在 Firefox 事件页语义下天然成立——background 无必须存活的内存态,消息/alarm 唤醒后从 IndexedDB 读状态推进一步。唯一行为差异:Firefox 将 `periodInMinutes: 0.5` 钳到 1 分钟(controller.ts 注释已有记载),卡死判定从最快 30s 放宽到最快 60s,可接受。

**Firefox 功能差异(审核说明与已知限制)**:
- Drive 直传(U9)依赖 `chrome.identity.getAuthToken`,Firefox 无此 API → **Firefox 上 Drive 自动保存不可用**;HubSpot 走 `launchWebAuthFlow` + backend 代理,理论可用,但 redirect URL 在 Firefox 下形态不同(AMO 签名后为 `https://<id>.extensions.allizom.org/`),backend 侧 redirect 白名单待 real smoke 验证。
- `host_permissions` 在 Firefox 127+ 随安装提示授予,用户可随时在扩展面板收回;插件对权限缺失的表现是可见报错(失败不静默),无需额外处理。

## 7 · Firefox AMO 提交要点

1. **data_collection_permissions 口径**(已写入 manifest):
   - `required: ["websiteContent"]`——采集引擎必然处理用户浏览的 Maps 页面内容,这是核心功能,不可选;
   - `optional: ["technicalAndInteraction"]`——SLS 行为打点;Mozilla 规定该项不可 required,由 Firefox 内置授权开关控制。
   - 隐私政策 URL(§5)在 AMO 后台单独填写。
2. **审核备注(review notes)建议要点**:扩展只读取 Google Maps 公开页面内容;不收集个人身份信息;数据默认只存本地;远程配置仅含页面选择器/解析 schema,不含用户数据;打点为匿名设备 ID + 事件计数。附 privacy.html 内容。
3. **源码审查预期**:采集类扩展可能触发人工审核,准备回复「数据流向图」(Maps 页面 → 本地导出 / 用户显式授权的 Drive/HubSpot / 补全请求发自有后端)。
4. **gecko.id 占位** `mapsgrab@example.com`(vite.config.ts TODO):AMO 签名与更新的永久身份,提交前必须由 hydra 定稿替换(定稿后不可再改)。
5. web-ext / addons-linter 不在本仓库工具链(不新增依赖);提交前用 `npx web-ext lint --source-dir dist-firefox`(手动,联网环境)做一次官方 lint。

## 8 · Edge Add-ons 提交要点

1. 上传 `dist-edge.zip`(与 Chromium manifest 一致,无需声明 Firefox 差异)。
2. Partner Center 表单:「Does your extension collect personal data?」→ 选是并勾选:Website content(公开商家数据)、Technical information(匿名打点);隐私政策 URL 填 §5 占位。
3. 单一用途说明(Single purpose):「Extract publicly visible business data from Google Maps pages for export」。
4. 权限理由(必填逐条):`storage`(本地保存设置与任务)、`alarms`(批量任务恢复扫描)、`identity`(可选 Drive/HubSpot 用户授权)、`host_permissions: googleapis.com`(Drive 直传)、content script matches(仅 Google Maps/搜索/评论页)。
