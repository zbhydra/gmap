## 0 · e2e 基建设计(U2 交付,全域复用)

目标:**默认 e2e 完全自动化,零人工干预,可重复**。

- **project**:`extension-mv3`(Playwright,`--load-extension=<dist>` + `--disable-extensions-except`,fresh-built;沿用 extension/ 现有 playwright 底座与浏览器身份机制)。
- **fixture 路由模式**:双 pattern 拦截——`page.route('https://www.google.com/maps/**')` 以本地 fixture fulfill(按 013 实测 DOM 形态构造的列表/详情页 HTML,交互链路);`page.route('https://www.google.com/search*')` 以黄金样本 fulfill(解析链路,Maps 内部 RPC 走 `/search?tbm=map`,不匹配 `/maps/**`)。**XHR 回放机制**:fixture 页内嵌回放脚本向 `/search?tbm=` 发起 XHR,injected hook 捕获真实形态流量,采集计数/导出断言成立。插件 content script 在真实 Maps URL 上激活。
- **SW 侧零外网策略**:Playwright 的 route 拦截不到 MV3 service worker 发起的请求(上游已知限制),因此 e2e 使用独立构建变体 `build:e2e`:构建期注入 `__API_BASE_URL__=http://127.0.0.1:<port>` 指向本地 mock 服务(globalSetup 拉起,提供配置下发与打点接收端点),background 的配置拉取与埋点全部落在本地 mock——零外网、零真实遥测。
- **断言面**:面板三态出现与切换、采集计数增长、导出下载事件(download API)、批量任务落盘与恢复。
- **单测**:黄金样本 → 解析器逐字段断言(格式 A/B 双形态);远程配置覆盖/回退;状态机步进。
- **real smoke**(可选,不进默认集):真实 Maps 采集 1–2 条,单独 project 显式指定才跑——防风控,不满足「无人工干预」约束的部分不入默认。

## 2 · 依赖与并行

- 串行链:U1 → U2 → {U3, U4, U5, U9, U10} → U11。
- U6 依赖 U1;backend 队列 U1 → U7 → U8 三个单元互相串行,可与插件侧单元并行(U7 的面板门控部分另依赖 U2)。
- 并行规则:同一 worker 不并发两个单元。
- **契约文件互斥**:core/types.ts 与远程配置 schema 文件是全计划共享契约——同一时间只允许一个单元修改它们;并行单元各自的功能文件独立并行,需要扩展契约时向架构师申请,由架构师调度顺序(该单元的契约扩展在单元内完成后放锁)。汇合后整体 reviewer 只审跨单元契约与组合行为。
