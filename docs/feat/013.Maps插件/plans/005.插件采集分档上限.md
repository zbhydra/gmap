# 插件采集分档上限实施与验收

本单元补齐 [采集业务流程](../feat.md#业务流程) 的有效订阅单次上限，并将本次实际采集限制在可用月余额内。

## 实施清单

- [x] `backend/src/app/api/client/maps_client.py` 的 `MAPS_RUN_LIMITS` 持有 Google 插件单次权益；通过既有有效订阅解析器取得稳定商品 ID，匿名、无订阅和过期订阅沿用本产品 Free 权益。
- [x] `GET /api/client/maps/usage` 与 `POST /api/client/maps/usage/report` 同形返回 `run_limits`，其 `search`、`reviews`、`photos` 均为正整数。上报响应继续包含 `deducted`，共享月度用量模型保持原合同。
- [x] `extension/src/sites/maps/usage/usageApi.ts` 在 HTTP 边界验证权益，查询与完成上报都向缓存提供完整快照；上报请求使用后端定义的 `request_id`。
- [x] 查询与上报复用现有 token 拦截器：有登录 token 时携带，未登录时继续按设备使用匿名路径。
- [x] `usageClient.ts` 的 `getRunLimit` 集中选取本次目标与可用月余额的较小值；用量不可得时复用远程配置的离线默认上限。
- [x] Search 与保存列表共用同一开始入口；评论、照片工作页首次开始及 Reset 都现拉用量，再把本次上限传入采集器。余额为零时显示已有额度用尽提示，不发采集请求。
- [x] 批量评论的显式每店目标保持独立，只受月余额限制；关键词批量预检继续使用既有默认搜索估算，不把付费最大单次权益当作每个关键词的预估结果数。
- [x] 采集器内部只使用开始入口传入的上限；移除评论构造覆盖和引擎自行决定免费上限的旧路径。
- [x] 工作页面板按解析失败、额度用尽两种语义选择友好提示，内部诊断保留在采集器日志；Reset 同步进入等待状态，异步检查期间阻止重复触发并保留旧结果。
- [x] 登录态真实 E2E 断言改为实际采集超过 Free 上限、完成上报业务成功且用量按实际行数增加、导出行数一致。

## 集成验收与限制

- [ ] 当前源码完成插件 `pnpm check`、`pnpm build`、`pnpm build:real`，再加载新产物运行真实 MV3 登录态采集；本单元复用集成执行者的构建与启动证据，不并行生成产物。
- [ ] 真实 Pro 开始查询与完成上报均携带登录身份，采集超过 Free 上限，业务成功且用量按实际条数增加；零余额工作页显示额度用尽并停止采集。
- [ ] 稳定需求与技术合同由集成执行者同步，移除已实现缺口的旧现状描述。

月余额在开始时读取，完成后按实际记录数计量。多标签页仍可能同时读取同一余额；网络或用量服务不可用时保持既有采集放行语义。本单元未验证真实 Google 的 Business 最大条数长程采集。
